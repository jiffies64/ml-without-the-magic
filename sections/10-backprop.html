Backpropagation by Hand

Backprop is the chain rule with careful bookkeeping. We compute every gradient in a real network by hand, with real numbers, and show every step.

56 min read
You'll learn

  • the chain rule flowing backward
  • a full worked numerical example
  • the local-gradient rule

A neural network learns by changing its weights in the direction that lowers the loss. To change a weight the right way, we need one number for it: the gradient. It says how much the loss would change if we changed that weight by a tiny amount. A real network has millions of weights, so we need millions of these numbers, and we need them again at every training step. Backpropagation (“backprop”) is the algorithm that computes all of them in one sweep backward through the network. Every later lesson in this book uses it.

◆ The one idea to hold onto

Backprop is the chain rule from Section 2 applied to a graph. The intermediate results are stored and reused instead of computed again. That reuse is the whole trick. It turns “millions of expensive experiments” into “one backward pass that costs about as much as two forward passes.” Everything below is careful bookkeeping of this idea.

1The goal, and why the obvious method fails

Intuition first

Suppose you want to know how each weight affects the loss. The obvious idea is to try it. Take one weight and add a tiny amount to it. Run the whole network again and see how much the loss changed. Divide the change in loss by the change in the weight. That ratio is (approximately) the gradient for that one weight. Then put the weight back and do the next one. This works, and it needs no calculus. The problem is speed.

☂ Everyday parallel

Imagine a mixing desk with a million volume sliders that all feed one loudspeaker. You want to know how much each slider affects the final loudness. The slow way: move slider one a little, play the whole song, measure the loudness, and reset. Then do the same for slider two, and play the entire song again. That is a million playbacks for one reading of the desk. Backprop gets every slider's effect from one playback plus one pass back from the speaker to each slider.

Now the math

Write the loss as $L$ (one number that says how wrong the network is) and a weight as $w$. The brute-force (“finite difference”) estimate of the gradient is:

$$ \frac{\partial L}{\partial w} \;\approx\; \frac{L(w+\varepsilon) - L(w)}{\varepsilon} $$

In words: $\partial L/\partial w$ means “how fast the loss $L$ changes when we change the weight $w$.” We estimate it by adding a tiny amount $\varepsilon$ (epsilon, a small number like $10^{-5}$) to the weight. We see how much $L$ changes, and divide by $\varepsilon$. The problem: computing $L(w+\varepsilon)$ means running the entire forward pass of the network.

Now count the cost. Say the network has $P$ weights, and one forward pass costs $C$ units of work. Then estimating every gradient this way costs about:

$$ P \times C \quad\text{units of work.} $$

In words: one full forward pass per weight. A small model with a million weights ($P = 10^{6}$) needs a million forward passes for one learning step. Modern models have billions of weights and take hundreds of thousands of steps. At that size, the brute-force method would take far too long to be useful.

◆ What backprop gives you

Backprop computes all $P$ gradients with one backward pass. The backward pass costs a small constant times the forward pass, usually about 2×, no matter how many weights there are. It reuses partial results: the gradient at an earlier layer is built from work already done for the later layers. Nothing is computed twice. This is an example of dynamic programming (solving a big problem by storing and reusing the answers to smaller, overlapping parts).

Check yourself A network has 5 million weights and one forward pass takes 2 ms. Roughly how long does one gradient step take with brute force, and with backprop? Reveal

Brute force: one forward pass per weight, so $5{,}000{,}000 \times 2\text{ ms} = 10{,}000{,}000$ ms. That is about 2.8 hours for one learning step, and you need thousands of steps. Backprop: one forward pass (2 ms) plus one backward pass (about 2× the forward pass, so about 4 ms). That is about 6 ms in total. The gradients are the same. The cost differs by a factor of more than a million, because backprop reuses intermediate results.

2The computation graph

Intuition first

To organize the bookkeeping, we draw the network as a computation graph. It is a diagram of small boxes called nodes, one for each simple operation: multiply, add, apply the sigmoid, and so on. Arrows called edges carry numbers from one box to the next. We put the input in and let the numbers flow from left to right. This is the forward pass, and it produces the prediction and the loss. Then we go from right to left. This return trip is the backward pass, and it produces the gradients.

☂ Everyday parallel

Think of a supply chain: farmer → mill → bakery → shop. In the forward direction, goods move toward the shop, and the shop's profit is the final number. In the backward direction, information moves toward the farmer: “one more unit from you changes my profit by this much.” That number can be positive or negative. (If the shop already has too much bread, one more unit lowers its profit.) Each link receives this message, converts it with its own local rate, and passes it upstream. The next section makes this exact.

Now the math

Here is the graph we will compute with. One input $x$ flows through two layers. Each layer does a linear step (multiply by a weight, add a bias) and then a nonlinear step (the sigmoid, written $\sigma$). The final node compares the output with the target $y$ and produces the loss $L$:

$$ \begin{aligned} &x \;\to\; \underbrace{z_1 = w_1 x + b_1}_{\text{linear}} \;\to\; \underbrace{a_1 = \sigma(z_1)}_{\text{nonlinear}} \\[2pt] &\;\to\; \underbrace{z_2 = w_2 a_1 + b_2}_{\text{linear}} \;\to\; \underbrace{a_2 = \sigma(z_2)}_{\text{nonlinear}} \;\to\; \underbrace{L = \tfrac12 (a_2 - y)^2}_{\text{loss}} \end{aligned} $$

In words: $x$ is the input number. $w_1$ and $b_1$ are the first layer's weight and bias. $z_1$ is the layer's raw output (the pre-activation). $a_1$ is $z_1$ squashed by the sigmoid into the range $(0,1)$ (the activation). The symbols $w_2$, $b_2$, $z_2$, $a_2$ mean the same for the second layer, and $a_2$ is the network's prediction. $y$ is the target value for $a_2$. $L$ is the squared-error loss: half the squared gap. The $\tfrac12$ is there for convenience; it cancels when we differentiate.

Definition

The forward pass runs the graph from left to right. It computes and stores every intermediate value ($z_1, a_1, z_2, a_2, L$). The backward pass runs from right to left. It computes the gradient of $L$ with respect to every stored value and every parameter. The forward pass must come first, because the backward pass reuses the stored values. That reuse is where the speed comes from.

Check yourself Why must we keep the forward-pass values in memory instead of discarding them once we have the loss? Reveal

Because the backward pass needs them. As we will see, the gradient for $w_2$ is $\delta_2 \cdot a_1$: it multiplies by the stored activation $a_1$. If we threw $a_1$ away, we would have to compute it again, which defeats the purpose. This is why training needs much more memory than running a model for predictions (inference). Training must keep the whole forward pass in memory for the return trip.

3The core rule at every node

Intuition first

Every node in the graph follows the same small rule. Once you see it, you have seen all of backprop. A node receives a number from the node after it. The number says “this is how much the final loss changes per unit change of my output.” The node also knows one local fact: “how much does my output change when my input changes?” Multiply the two. The result is “how much the final loss changes per unit change of my input.” That is the message the node passes one step further back.

☂ Everyday parallel

Back to the supply chain. The shop tells the bakery: “each extra loaf you send raises my profit by 2 dollars” (the gradient coming in). The bakery knows a local fact: “each extra kilogram of flour lets me bake 3 loaves” (the local gradient). So the bakery tells the mill: “each extra kilogram of flour is worth $2 \times 3 = 6$ dollars of final profit.” If the shop had said “−2 dollars,” the message would be −6: less flour is better. Nobody needs to see the whole chain. Each link multiplies the message from downstream by its own local rate and passes it on.

Now the math

This is the chain rule, written as a rule you can apply mechanically. Take any node that computes an output $u$ from an input $t$. Let the loss be $L$. Then:

$$ \underbrace{\frac{\partial L}{\partial t}}_{\text{gradient sent to input}} \;=\; \underbrace{\frac{\partial L}{\partial u}}_{\text{gradient from above}} \;\times\; \underbrace{\frac{\partial u}{\partial t}}_{\text{local gradient}} $$

In words: (gradient of the loss for my output) × (how my output responds to my input) = (gradient of the loss for my input). The last factor, $\partial u/\partial t$, is the local gradient. It depends only on what this node does. You can compute it without knowing anything about the rest of the network. This locality makes backprop modular: each operation only needs to know its own derivative.

◆ The local-gradient rule

gradient in (from above) × local gradient = gradient out (to inputs)

Every node applies this rule. Backprop starts at the loss, whose gradient with respect to itself is $1$. Then it applies the rule node by node, back to the weights. If a value feeds several nodes, its gradient is the sum of the messages from all of them. (This is the multivariable chain rule: each path through which the value affects $L$ adds its own contribution.)

We need the local gradients of the three operations in our graph. The first two follow directly from the derivative rules:

$$ \begin{aligned} \text{multiply } u = wt &: \quad \frac{\partial u}{\partial t} = w, \qquad \frac{\partial u}{\partial w} = t \\[4pt] \text{add } u = t + b &: \quad \frac{\partial u}{\partial t} = 1, \qquad \frac{\partial u}{\partial b} = 1 \end{aligned} $$

In words: a multiply node passes the gradient back scaled by the other input. So $z_2 = w_2 a_1$ sends gradient to $a_1$ scaled by $w_2$, and to $w_2$ scaled by $a_1$. An add node passes the gradient back unchanged (local gradient $1$).

The third is the sigmoid. Section 6 derived its derivative; here is the short version. Write $\sigma(z) = (1+e^{-z})^{-1}$ and use the chain rule:

$$ \begin{aligned} \frac{d\sigma}{dz} &= \frac{e^{-z}}{(1+e^{-z})^{2}} = \frac{1}{1+e^{-z}}\cdot\frac{e^{-z}}{1+e^{-z}} \\[4pt] &= \sigma(z)\,\bigl(1-\sigma(z)\bigr) = a(1-a) \end{aligned} $$

In words: the second fraction equals $1 - \sigma(z)$, because $\frac{e^{-z}}{1+e^{-z}} = 1 - \frac{1}{1+e^{-z}}$. So the sigmoid's local gradient is $a(1-a)$. We can compute it from the activation $a$ that we stored in the forward pass. There is no need to compute an exponential again on the way back.

Check yourself At a node $u = w t$, the gradient from above is $\partial L/\partial u = -3$, and the stored inputs are $w = 2$, $t = 5$. What gradients does the node send to $t$ and to $w$? Reveal

Apply the rule twice. To the input $t$: the local gradient is $w = 2$, so $\partial L/\partial t = -3 \times 2 = \mathbf{-6}$. To the weight $w$: the local gradient is $t = 5$, so $\partial L/\partial w = -3 \times 5 = \mathbf{-15}$. The multiply node “swaps” its inputs on the way back: each branch is scaled by the other value. Every linear layer is built from multiply nodes, so you will use this swap all the time.

4The main example: a full network, by hand

Intuition first

Now we do the real thing. We take the two-layer graph from Section 2 and put in concrete numbers. We compute every value forward and every gradient backward. We skip nothing, so you can reproduce each number with a calculator. Figure 10.2 shows all the numbers at once; the steps below compute them one by one. These are the fixed ingredients:

SymbolMeaningValue
$x$the single input$1.0$
$w_1,\; b_1$layer-1 weight and bias$0.5,\; 0.5$
$w_2,\; b_2$layer-2 weight and bias$1.5,\; -1.0$
$y$the target value for $a_2$$1.0$

We round every result to four decimal places. The sigmoid is $\sigma(z) = 1/(1+e^{-z})$.

Now the math

Forward pass: compute and store every value

Node 1: first linear step. Multiply the input by $w_1$ and add $b_1$:

$$ z_1 = w_1 x + b_1 = (0.5)(1.0) + 0.5 = \mathbf{1.0000} $$

Node 2: first sigmoid. Squash $z_1$ into $(0,1)$:

$$ a_1 = \sigma(1.0) = \frac{1}{1 + e^{-1.0}} = \frac{1}{1 + 0.3679} = \mathbf{0.7311} $$

Node 3: second linear step. Multiply the activation by $w_2$ and add $b_2$:

$$ z_2 = w_2 a_1 + b_2 = (1.5)(0.7311) + (-1.0) = 1.0966 - 1.0 = \mathbf{0.0966} $$

Node 4: second sigmoid. This is the network's prediction:

$$ a_2 = \sigma(0.0966) = \frac{1}{1 + e^{-0.0966}} = \frac{1}{1 + 0.9079} = \mathbf{0.5241} $$

Node 5: the loss. Compare the prediction $a_2$ with the target $y = 1.0$:

$$ \begin{aligned} L &= \tfrac12 (a_2 - y)^2 = \tfrac12 (0.5241 - 1.0)^2 \\ &= \tfrac12 (-0.4759)^2 = \tfrac12(0.2265) = \mathbf{0.1132} \end{aligned} $$

In words: the network predicts $0.5241$, but we want $1.0$. It is off by $0.4759$, and the loss is $0.1132$. All five numbers are now stored. The backward pass will reuse them.

Backward pass: send the gradient back, node by node

We start at the loss and apply the local-gradient rule again and again. It helps to name the gradient at each pre-activation. The standard name is $\delta$ (delta): $\delta_2 = \partial L / \partial z_2$ and $\delta_1 = \partial L / \partial z_1$. Notice how each step reuses a stored forward value.

Step A: through the loss node. Differentiate $L = \tfrac12(a_2 - y)^2$ with respect to $a_2$. The $\tfrac12$ cancels the $2$ from the power:

$$ \frac{\partial L}{\partial a_2} = (a_2 - y) = 0.5241 - 1.0 = \mathbf{-0.4759} $$

In words: the gradient is negative. Gradient descent moves against the gradient, so it will increase $a_2$. That makes sense, because $0.5241$ is below the target $1.0$.

Step B: through the second sigmoid. The local gradient is $a_2(1-a_2)$, computed from the stored $a_2$. Multiply it by the gradient from above to get $\delta_2$:

$$ \begin{aligned} \frac{\partial a_2}{\partial z_2} &= a_2(1-a_2) = (0.5241)(0.4759) = 0.2494 \\[4pt] \delta_2 = \frac{\partial L}{\partial z_2} &= \frac{\partial L}{\partial a_2}\cdot\frac{\partial a_2}{\partial z_2} = (-0.4759)(0.2494) = \mathbf{-0.1187} \end{aligned} $$

In words: we took the message $-0.4759$ and scaled it by the sigmoid's local gradient $0.2494$. That $0.2494$ came directly from the stored $a_2$, with no new exponentials. $\delta_2$ is the gradient of the loss with respect to the layer-2 pre-activation.

Step C: the layer-2 weight and bias. Recall $z_2 = w_2 a_1 + b_2$. The multiply node sends gradient to $w_2$ scaled by the other input, the stored $a_1$. The add node sends gradient to $b_2$ unchanged:

$$ \begin{aligned} \frac{\partial L}{\partial w_2} &= \delta_2 \cdot \frac{\partial z_2}{\partial w_2} = \delta_2 \cdot a_1 = (-0.1187)(0.7311) = \mathbf{-0.0868} \\[4pt] \frac{\partial L}{\partial b_2} &= \delta_2 \cdot \frac{\partial z_2}{\partial b_2} = \delta_2 \cdot 1 = \mathbf{-0.1187} \end{aligned} $$

In words: two of our four parameter gradients are done. The weight gradient reused the stored activation $a_1 = 0.7311$. The bias gradient is $\delta_2$ itself, because adding a bias passes the gradient through unchanged.

Step D: back into layer 1. The multiply node also sends gradient to its other input $a_1$, scaled by $w_2$:

$$ \frac{\partial L}{\partial a_1} = \delta_2 \cdot \frac{\partial z_2}{\partial a_1} = \delta_2 \cdot w_2 = (-0.1187)(1.5) = \mathbf{-0.1780} $$

In words: we have crossed from layer 2 into layer 1. The gradient has reached $a_1$, the first layer's activation. Now we pass it through the first sigmoid, in the same way as the second.

Step E: through the first sigmoid. Same rule as Step B, now with the stored $a_1$:

$$ \begin{aligned} \frac{\partial a_1}{\partial z_1} &= a_1(1-a_1) = (0.7311)(0.2689) = 0.1966 \\[4pt] \delta_1 = \frac{\partial L}{\partial z_1} &= \frac{\partial L}{\partial a_1}\cdot\frac{\partial a_1}{\partial z_1} = (-0.1780)(0.1966) = \mathbf{-0.0350} \end{aligned} $$

In words: $\delta_1$ is the gradient of the loss with respect to the layer-1 pre-activation. It is much smaller than $\delta_2$. The signal shrank as it passed back through the sigmoid, whose local gradient is at most $0.25$. Stack many sigmoid layers and the signal keeps shrinking. This is the vanishing gradient problem (Section 12).

Step F: the layer-1 weight and bias. Recall $z_1 = w_1 x + b_1$. This is the same pattern as Step C, now with the stored input $x$:

$$ \begin{aligned} \frac{\partial L}{\partial w_1} &= \delta_1 \cdot \frac{\partial z_1}{\partial w_1} = \delta_1 \cdot x = (-0.0350)(1.0) = \mathbf{-0.0350} \\[4pt] \frac{\partial L}{\partial b_1} &= \delta_1 \cdot \frac{\partial z_1}{\partial b_1} = \delta_1 \cdot 1 = \mathbf{-0.0350} \end{aligned} $$

In words: all four parameter gradients are done. We went from the loss back to the first weight. At each node we did only one thing: “gradient from above × local gradient,” using stored values. That whole sweep is one backward pass.

◆ All four gradients, in one place

These are the numbers we came for: the slope of the loss along each parameter.

$\dfrac{\partial L}{\partial w_1}$$\dfrac{\partial L}{\partial b_1}$$\dfrac{\partial L}{\partial w_2}$$\dfrac{\partial L}{\partial b_2}$
$-0.0350$$-0.0350$$-0.0868$$-0.1187$

All four are negative. This means that increasing any of these parameters would lower the loss. So the update will increase all of them.

One gradient-descent step: does the loss drop?

Gradient descent moves each parameter a small step against its gradient (downhill on the loss). The step size is the learning rate $\alpha$ (alpha). Take $\alpha = 1.0$. The update rule for any parameter is $w \leftarrow w - \alpha\,\partial L/\partial w$:

$$ \begin{aligned} w_1 &\leftarrow 0.5 - (1.0)(-0.0350) = \mathbf{0.5350} \\ b_1 &\leftarrow 0.5 - (1.0)(-0.0350) = \mathbf{0.5350} \\ w_2 &\leftarrow 1.5 - (1.0)(-0.0868) = \mathbf{1.5868} \\ b_2 &\leftarrow -1.0 - (1.0)(-0.1187) = \mathbf{-0.8813} \end{aligned} $$

In words: subtracting a negative gradient means adding. Every parameter grew a little, as the signs predicted. Now the real test: does the loss fall? Run the forward pass again with the new parameters.

New forward pass:

$$ \begin{aligned} z_1 &= (0.5350)(1.0) + 0.5350 = 1.0700 \\ a_1 &= \sigma(1.0700) = 0.7446 \\ z_2 &= (1.5868)(0.7446) + (-0.8813) = 0.3002 \\ a_2 &= \sigma(0.3002) = 0.5745 \\ L_{\text{new}} &= \tfrac12(0.5745 - 1.0)^2 = \tfrac12(0.1811) = \mathbf{0.0905} \end{aligned} $$

In words: the loss fell from $0.1132$ to $\mathbf{0.0905}$. The prediction moved toward the target, from $0.5241$ to $0.5745$. One backward pass and one step made the network measurably less wrong. Repeat this loop thousands of times and you have training.

☂ Everyday parallel

You walk down a hill in thick fog. You cannot see the valley; you can only feel the slope under your feet. The gradient is that slope, and the learning rate is the length of your step. You take one step downhill, feel the slope again, and take another step. Backprop tells you the slope; gradient descent takes the step.

The same thing in PyTorch

manual backprop, no autograd: reproduces every number above

import torch

def sigmoid(z):
    return 1.0 / (1.0 + torch.exp(-z))

# fixed ingredients
x  = torch.tensor(1.0)
w1, b1 = torch.tensor(0.5), torch.tensor(0.5)
w2, b2 = torch.tensor(1.5), torch.tensor(-1.0)
y  = torch.tensor(1.0)

# ---- forward pass: compute and keep every value ----
z1 = w1 * x + b1        # 1.0000
a1 = sigmoid(z1)        # 0.7311
z2 = w2 * a1 + b2       # 0.0966
a2 = sigmoid(z2)        # 0.5241
L  = 0.5 * (a2 - y)**2  # 0.1132

# ---- backward pass: gradient in x local gradient, node by node ----
dL_da2 = (a2 - y)               # -0.4759
d2     = dL_da2 * a2 * (1 - a2) # delta2 = -0.1187
dL_dw2 = d2 * a1                # -0.0868
dL_db2 = d2                     # -0.1187
dL_da1 = d2 * w2                # -0.1780
d1     = dL_da1 * a1 * (1 - a1) # delta1 = -0.0350
dL_dw1 = d1 * x                 # -0.0350
dL_db1 = d1                     # -0.0350

print(dL_dw1, dL_db1, dL_dw2, dL_db2)
# tensor(-0.0350) tensor(-0.0350) tensor(-0.0868) tensor(-0.1187)

# ---- one gradient-descent step (learning rate 1.0) ----
alpha = 1.0
w1, b1 = w1 - alpha*dL_dw1, b1 - alpha*dL_db1
w2, b2 = w2 - alpha*dL_dw2, b2 - alpha*dL_db2

a2_new = sigmoid(w2 * sigmoid(w1*x + b1) + b2)
print(0.5 * (a2_new - y)**2)    # tensor(0.0905)  -> the loss dropped
Check yourself Why is $\partial L/\partial b_1$ equal to $\partial L/\partial w_1$ here (both −0.0350)? Would they still be equal if the input were $x = 2.0$? Reveal

Both are $\delta_1$ times a local gradient. For the bias the local gradient is $1$, so $\partial L/\partial b_1 = \delta_1$. For the weight the local gradient is the input $x$, so $\partial L/\partial w_1 = \delta_1 \cdot x$. They are equal here only because $x = 1.0$. With $x = 2.0$ they would differ. (Careful: $\delta_1$ itself would also change, because the forward values change. But the weight gradient would be $2\delta_1$ and the bias gradient $\delta_1$.) A weight's gradient always scales with the input that feeds it; a bias's gradient does not.

5The same rules for a whole layer at once

Intuition first

Real layers have many neurons. The weights form a matrix $\mathbf{W}$, and the activations form vectors. The rules do not change. “A multiply node swaps its inputs” becomes “multiply by the transpose of the matrix.” The number $\delta$ becomes a vector $\boldsymbol{\delta}$, with one entry per neuron. Everything you did by hand now runs on a whole layer in one matrix operation. GPUs are built to do such operations fast.

☂ Everyday parallel

Think of computing the payroll for a whole company at once instead of one employee at a time. The rule for each person (hours × rate) does not change. You put everyone in one table and do the arithmetic in one sweep. Vectorizing backprop is the same move: the same rule, applied to the whole layer with one matrix multiply.

Now the math

Take a layer $\mathbf{z} = \mathbf{W}\mathbf{x} + \mathbf{b}$. $\mathbf{W}$ has shape (out, in), as in Section 9. Let $\boldsymbol{\delta} = \partial L / \partial \mathbf{z}$ be the gradient that arrives at the layer's pre-activations. We derive the gradients one entry at a time, then collect them into matrices. Entry $i$ of $\mathbf{z}$ is:

$$ z_i = \sum_{j} W_{ij}\, x_j + b_i $$

In words: neuron $i$ multiplies input $j$ by the weight $W_{ij}$, sums over all inputs $j$, and adds its bias $b_i$. The weight $W_{ij}$ appears in only one output, $z_i$. But each input $x_j$ appears in every output $z_1, z_2, \dots$

Now apply the local-gradient rule to each kind of parameter:

$$ \begin{aligned} \frac{\partial L}{\partial W_{ij}} &= \frac{\partial L}{\partial z_i}\,\frac{\partial z_i}{\partial W_{ij}} = \delta_i\, x_j \\[4pt] \frac{\partial L}{\partial b_i} &= \frac{\partial L}{\partial z_i}\,\frac{\partial z_i}{\partial b_i} = \delta_i \\[4pt] \frac{\partial L}{\partial x_j} &= \sum_i \frac{\partial L}{\partial z_i}\,\frac{\partial z_i}{\partial x_j} = \sum_i \delta_i\, W_{ij} \end{aligned} $$

In words: the first two lines are Step C again, for each neuron: “$\delta$ times the other input” for a weight, and “$\delta$ itself” for a bias. The third line has a sum, because $x_j$ feeds every neuron. By the sum rule from Section 3, its gradient adds up the messages from all of them. That is Step D, summed over neurons.

Now collect the entries into matrices. The grid of numbers $\delta_i x_j$ is the outer product $\boldsymbol{\delta}\,\mathbf{x}^{\top}$ (a column times a row). The sum $\sum_i \delta_i W_{ij}$ is entry $j$ of $\mathbf{W}^{\top}\boldsymbol{\delta}$ (the little $\top$ means transpose: rows become columns). So:

$$ \begin{aligned} \frac{\partial L}{\partial \mathbf{W}} &= \boldsymbol{\delta}\,\mathbf{x}^{\top} &&\text{(for the weight matrix)} \\[4pt] \frac{\partial L}{\partial \mathbf{b}} &= \boldsymbol{\delta} &&\text{(for the bias vector)} \\[4pt] \frac{\partial L}{\partial \mathbf{x}} &= \mathbf{W}^{\top}\boldsymbol{\delta} &&\text{(sent to the previous layer)} \end{aligned} $$

To continue one more layer back, remember where $\mathbf{x}$ came from. The input of this layer is the output of the previous one: $\mathbf{x} = \phi(\mathbf{z}_{\text{prev}})$, where $\phi$ is the previous layer's activation function. So pass $\partial L/\partial\mathbf{x}$ through $\phi$, as in Step E. Multiply by the local gradient $\phi'$, entry by entry:

$$ \boldsymbol{\delta}_{\text{prev}} = \bigl(\mathbf{W}^{\top}\boldsymbol{\delta}\bigr) \odot \phi'(\mathbf{z}_{\text{prev}}) $$

In words: $\odot$ means “multiply matching entries” (the element-wise product). Each neuron's incoming gradient is scaled by its own local slope $\phi'$. This line, repeated from layer to layer, is the backward pass for a deep network. It is the same “gradient in × local gradient = gradient out” that you did by hand, now vectorized.

The same thing in PyTorch

the three layer gradients, checked against autograd

import torch
torch.manual_seed(0)

# a layer: W is (out=3, in=4), one input vector x of length 4
W = torch.randn(3, 4)
x = torch.randn(4)
delta = torch.randn(3)        # gradient arriving at this layer's z

dL_dW = torch.outer(delta, x) # delta x^T  -> shape (3, 4), same as W
dL_db = delta                 # -> shape (3,)
dL_dx = W.T @ delta           # -> shape (4,), sent to the previous layer
print(dL_dW.shape, dL_db.shape, dL_dx.shape)
# torch.Size([3, 4]) torch.Size([3]) torch.Size([4])

# check with autograd: a loss whose gradient at z is exactly delta
W.requires_grad_(); x.requires_grad_()
L = (delta * (W @ x)).sum()
L.backward()
print(torch.allclose(W.grad, dL_dW), torch.allclose(x.grad, dL_dx))   # True True
▲ Watch out

The transposes are necessary: they make the shapes fit. $\partial L/\partial \mathbf{W}$ must have the same shape as $\mathbf{W}$, because you subtract it from $\mathbf{W}$ in the update. And $\partial L/\partial \mathbf{x}$ must have the same shape as $\mathbf{x}$. If a backward pass gives a shape error, check the transposes first. When you are stuck, print the shape on every line, as in Section 1.

Check yourself A layer has $\boldsymbol{\delta} = [1, 0, -2]$ and input $\mathbf{x} = [1, 2, 0, 1]$. Predict row 3 of $\partial L/\partial \mathbf{W}$. Which whole row and which whole column are zero, and why? Reveal

Row 3 is $\delta_3\,\mathbf{x}^\top = -2 \times [1, 2, 0, 1] = [-2, -4, 0, -2]$. Row 2 is all zeros, because $\delta_2 = 0$: neuron 2's output does not affect the loss here, so its weights get no update. Column 3 is all zeros, because $x_3 = 0$: a weight that multiplies a zero input had no effect on the output, so it gets no blame.

6Trust, but verify: gradient checking

Intuition first

It is easy to make a small mistake in hand-derived gradients: a missing transpose, or a wrong sign. There is a simple way to catch such mistakes. Compare your backprop gradient with the brute-force estimate from the start of this lesson. If they agree to many decimal places, your backprop is almost certainly correct. This is the numerical gradient check. It is one of the most useful tools for debugging a network written from scratch.

☂ Everyday parallel

You compute 47 × 23 in your head with a clever shortcut. To check it, you add 47 twenty-three times on paper. The slow method is too slow for everyday use, but it is hard to get wrong. So it is a good way to test the fast method once. Backprop is the fast shortcut; the numerical gradient is the slow, reliable check.

Now the math

Use the centered difference: change the weight both up and down by $\varepsilon$. It is much more accurate than the one-sided version from Section 1:

$$ \frac{\partial L}{\partial w} \;\approx\; \frac{L(w+\varepsilon) - L(w-\varepsilon)}{2\varepsilon} $$

In words: move the weight up, move it down, and take the slope between the two points. The error of this estimate shrinks like $\varepsilon^2$, while the one-sided error shrinks only like $\varepsilon$. It is far too slow to train with (one forward pass per weight, the problem that backprop solves). But it is a good one-time check that backprop is correct.

▲ Watch out

Do gradient checks in float64. A float32 number keeps only about 7 significant digits. The difference $L(w+\varepsilon) - L(w-\varepsilon)$ is tiny, so most of those digits are lost in the subtraction. In float32, the code below prints about $-0.0339$ instead of $-0.0350$.

The same thing in PyTorch

numerical check of our hand-computed gradient for w1, in float64

import torch

def loss(w1, b1, w2, b2, x=1.0, y=1.0):
    a1 = 1/(1 + torch.exp(-(w1*x + b1)))
    a2 = 1/(1 + torch.exp(-(w2*a1 + b2)))
    return 0.5 * (a2 - y)**2

w1, b1, w2, b2 = (torch.tensor(v, dtype=torch.float64) for v in (0.5, 0.5, 1.5, -1.0))
eps = 1e-5
num_grad_w1 = (loss(w1+eps, b1, w2, b2) - loss(w1-eps, b1, w2, b2)) / (2*eps)

print(num_grad_w1.item())   # -0.03500407346271328   (backprop: -0.03500407346316374)

In words: the numerical estimate is $-0.0350$ when rounded, the same value we computed by hand in Step F. In float64 it agrees with the exact backprop value to about 11 decimal places. That agreement shows our backward pass is correct. Section 15 turns this into a regular debugging habit.

◆ You will rarely write this by hand again

Deriving gradients by hand is how you understand backprop. In practice, a library does it for you. Autograd (Section 13) records the computation graph while your forward code runs. Then it applies the local-gradient rule you just used at every node, automatically. In Section 11 we write a full multi-layer network's backward pass from scratch in NumPy. You will see there is nothing hidden: only the bookkeeping you now understand.

Check yourself Your backprop gradient for a weight is 0.4000, but the centered numerical check gives −0.4000. What kind of bug does this mismatch point to? Reveal

A sign error in the backward pass. When the sizes match but the signs are opposite, you have almost certainly flipped a subtraction somewhere. A typical example is $y - a$ written where $a - y$ belongs. This is a common backprop bug, and a gradient check finds it at once. (The check compares gradients only, so it cannot find a sign error in the update step itself.) If instead the sizes were very different, look for a missing local-gradient factor (for example a forgotten $a(1-a)$) or a wrong transpose.

7What to carry forward

  • Training needs $\partial L/\partial w$ for every parameter. Brute force costs one forward pass per parameter, which is far too slow. Backprop gets them all with one backward pass (about 2× the cost of a forward pass) by reusing stored forward values. This is dynamic programming.
  • The computation graph is the network drawn as nodes (operations) and edges (values). The forward pass computes and stores values; the backward pass computes gradients.
  • The local-gradient rule at every node: gradient in (from above) × local gradient = gradient out (to inputs). If a value feeds several nodes, add up the gradients that come back.
  • Useful local gradients: multiply swaps its inputs; add passes the gradient through unchanged; the sigmoid's is $a(1-a)$, computed from the stored activation.
  • We computed a whole two-layer network by hand: forward to $L = 0.1132$, backward to four gradients, one step, and the loss fell to $0.0905$. The code confirms every number.
  • For a whole layer, $\partial L/\partial W_{ij} = \delta_i x_j$, which gives $\partial L/\partial\mathbf{W} = \boldsymbol{\delta}\,\mathbf{x}^{\top}$, $\partial L/\partial\mathbf{b} = \boldsymbol{\delta}$ and $\partial L/\partial\mathbf{x} = \mathbf{W}^{\top}\boldsymbol{\delta}$.
  • Gradient checking in float64 compares backprop with the centered difference. A sign error or a missing factor shows up at once.
