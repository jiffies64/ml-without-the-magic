Training Dynamics & Optimizers

The same network can learn well or fail completely, depending on how you start it and how you step. Here is why.

32 min read
You'll learn

  • learning rates
  • SGD, momentum, Adam
  • LR schedules

You have a network. You have a loss (a single number that says how wrong the network is). You have backpropagation to tell you which way each weight should move. So training is done, right? Not quite. Two choices decide whether the loop converges in a minute or never converges. They are the numbers you start the weights at, and the size of the steps you take. This section is about those two knobs. They turn a working design into a working model.

◆ The one idea to hold onto

Backprop tells you the direction to move each weight. It says nothing about where to begin or how far to step. Those two decisions (initialization and the optimizer) are what “training dynamics” means. If you get them wrong, a network that is otherwise correct will not learn.

1Initialization: where the weights start

Intuition first

Before the first step of training, every weight needs a starting value. It feels like this should not matter much, because training will fix the weights anyway. But the starting point controls two things. First, it decides whether the neurons can ever become different from each other. Second, it decides whether the signal can travel through a deep stack of layers without dying out or blowing up. If either goes wrong, the network learns slowly, badly, or not at all.

☂ Everyday parallel

Imagine a choir where every singer gets the same sheet music and the same instructions from the conductor. However long they rehearse, they all sing the same note. A choir of 40 then sounds like one loud singer. To get harmony, the singers must start on different parts. A layer of neurons is the same: the neurons must start different to end up doing different jobs.

Why not all zeros: the symmetry problem

Now the math

The tempting “safe” choice is to set every weight to zero. Let us prove why this breaks the network. Take one layer. Each neuron $j$ computes a weighted sum of the same inputs $\mathbf{x}$. Then it passes the sum through an activation function $\phi$ (a simple nonlinear function such as ReLU or tanh):

$$ a_j = \phi\!\left(\sum_i w_{ji}\, x_i + b_j\right) $$

In words: to get neuron $j$'s output, multiply each input $x_i$ by its weight $w_{ji}$, add them up, add the bias $b_j$, then apply $\phi$. The weight $w_{ji}$ connects input $i$ to neuron $j$.

Now give every neuron in the layer the same weights and bias (for example, all zero). Then the sum inside is the same number for every neuron $j$. So every neuron produces the same output:

$$ w_{ji} = c \text{ for all } j, i \;\;\Rightarrow\;\; a_1 = a_2 = \dots = a_n $$

That is already bad. The real problem is what backprop does next. From Section 10, the gradient for a weight is the error signal at the neuron times the input:

$$ \frac{\partial L}{\partial w_{ji}} = \delta_j\, x_i, \qquad \delta_j = \phi'(z_j) \sum_k w^{\text{next}}_{kj}\, \delta^{\text{next}}_k $$

In words: $\delta_j$ is the gradient of the loss with respect to neuron $j$'s pre-activation $z_j$ (the sum before $\phi$). It collects the error signals $\delta_k^{\text{next}}$ from the next layer, weighted by the outgoing weights $w^{\text{next}}_{kj}$.

If the outgoing weights are also identical for every $j$, then every neuron gets the same $z_j$ and the same sum. So every $\delta_j$ is equal, and every weight gets the same gradient:

$$ \frac{\partial L}{\partial w_{1i}} = \frac{\partial L}{\partial w_{2i}} = \dots = \frac{\partial L}{\partial w_{ni}} $$

In words: $\partial L/\partial w_{ji}$ means “how much the loss $L$ changes if we nudge weight $w_{ji}$.” When every neuron is a copy, these numbers are all equal. So the optimizer moves every copy by the same amount.

Follow the consequence. The weights start equal and always move by the same amount, so they stay equal forever. A layer of 100 neurons behaves like a layer of one. This is the symmetry problem: nothing in the update rule can break the tie.

All zeros is even worse than “all equal.” The outgoing weights are zero, so every $\delta_j$ in the hidden layers is zero. The inputs to the last layer are $\phi(0)$, which is 0 for ReLU. So in an all-zero ReLU network every weight gradient is exactly 0. Only the biases can move, and the network cannot start learning.

◆ The fix

Break the symmetry by starting the weights at small random numbers. Now each neuron sees a different weighted sum and receives a different gradient. So each neuron is free to specialize. Random initialization is not optional. It is what lets a wide layer be more useful than a single neuron. (Biases can start at zero; the random weights already break the tie.)

Check yourself You set every weight in a tanh layer to 0.5 (not zero). Is the symmetry problem solved? Reveal

No. The problem is not the value zero, it is that all the values are equal. With every weight 0.5, every neuron computes the same sum, gets the same $\delta_j$, and receives the same update. The neurons stay copies. Only random (different) starting values break the tie.

Why not too large, and not too small

Intuition first

So the weights must be random. But how big? This is the second job of initialization. A deep network passes the signal through many layers in a row. If each layer magnifies the signal a little, the effect compounds and the numbers explode. If each layer shrinks it a little, the signal fades to nothing before it reaches the end. Either way, learning stalls.

☂ Everyday parallel

Think of 50 audio amplifiers connected in a row, each feeding the next. If each one has a gain of 1.1, the sound at the end is $1.1^{50} \approx 117$ times louder. If each has a gain of 0.9, only $0.9^{50} \approx 0.5\%$ of the sound is left. Only a gain very close to 1 keeps the sound at a normal level. Initialization sets that gain for each layer of the network.

This is the eigenvalue story from Section 1. Passing a signal through a stack of layers is repeated multiplication by weight matrices. Repeated multiplication grows or decays depending on whether each matrix stretches by more or less than 1. We want each layer to stretch by about 1, so the signal survives all the way through. Figure 12.1 shows what happens in a real 20-layer ReLU network.

Deriving the right scale: variance preservation

Now the math

Let us turn “stretch by about 1” into a formula. Consider one neuron's pre-activation $z$ (the weighted sum before the activation function):

$$ z = \sum_{i=1}^{n_\text{in}} w_i\, x_i $$

In words: $z$ is the sum over all $n_\text{in}$ incoming connections of weight times input. $n_\text{in}$ (the fan-in) is the number of inputs that feed this neuron.

We want $z$ to have about the same spread as the inputs. We measure spread with the variance (the average squared distance of the values from their mean). Assume the weights and the inputs are independent and have mean zero. Then the variance of one term is:

$$ \mathrm{Var}(w x) = \mathbb{E}[w^2 x^2] - (\mathbb{E}[w x])^2 = \mathbb{E}[w^2]\,\mathbb{E}[x^2] - 0 = \mathrm{Var}(w)\,\mathrm{Var}(x) $$

The variances of independent terms add, and there are $n_\text{in}$ terms:

$$ \mathrm{Var}(z) = \sum_{i=1}^{n_\text{in}} \mathrm{Var}(w_i\, x_i) = n_\text{in}\,\mathrm{Var}(w)\,\mathrm{Var}(x) $$

In words: each of the $n_\text{in}$ terms adds $\mathrm{Var}(w)\,\mathrm{Var}(x)$. So one layer multiplies the input variance by the factor $n_\text{in}\mathrm{Var}(w)$.

For the output spread to equal the input spread, that factor must be 1:

$$ n_\text{in}\,\mathrm{Var}(w) = 1 \;\;\Longrightarrow\;\; \boxed{\;\mathrm{Var}(w) = \frac{1}{n_\text{in}}\;} $$

In words: draw each weight from a distribution whose variance is 1 divided by the number of inputs. A neuron with more inputs must start with smaller weights, because it adds up more terms. Every modern init scheme starts from this line.

Xavier (Glorot) initialization notes that the signal flows two ways: forward (the activations) and backward (the gradients). The same argument on the backward pass sums over the $n_\text{out}$ neurons that this one feeds (the fan-out). So the forward pass wants $\mathrm{Var}(w)=1/n_\text{in}$ and the backward pass wants $\mathrm{Var}(w)=1/n_\text{out}$. Glorot's compromise uses the average of the two fan numbers:

$$ \mathrm{Var}(w) = \frac{1}{\tfrac{1}{2}(n_\text{in} + n_\text{out})} = \frac{2}{n_\text{in} + n_\text{out}} $$

In words: replace $n_\text{in}$ by the average of the fan-in and the fan-out. When the layer has as many outputs as inputs, this is the same as $1/n_\text{in}$. Xavier assumes an activation that is symmetric around zero and close to the identity near zero, such as tanh.

He (Kaiming) initialization adapts this for ReLU. ReLU ($\max(0,z)$) sets every negative input to zero. That changes the step above, because the inputs to the next layer are no longer zero-mean. Let $x = \mathrm{ReLU}(z)$, with $z$ symmetric around zero. Half of the values of $z$ are negative and become 0. So the second moment (the mean of the squares) is halved:

$$ \mathbb{E}[x^2] = \tfrac{1}{2}\,\mathbb{E}[z^2] = \tfrac{1}{2}\,\mathrm{Var}(z) $$

The next layer's weights still have mean zero, so for its pre-activation $z' = \sum_i w_i x_i$ we get $\mathrm{Var}(w_i x_i) = \mathbb{E}[w_i^2]\,\mathbb{E}[x_i^2]$, and:

$$ \mathrm{Var}(z') = n_\text{in}\,\mathrm{Var}(w)\,\mathbb{E}[x^2] = \tfrac{1}{2}\, n_\text{in}\,\mathrm{Var}(w)\,\mathrm{Var}(z) $$

Setting the factor $\tfrac{1}{2} n_\text{in}\mathrm{Var}(w)$ to 1 gives:

$$ \mathrm{Var}(w) = \frac{2}{n_\text{in}} $$

In words: ReLU halves the mean of the squares at each layer. The factor of 2 in the weight variance cancels that halving, so the spread stays the same from layer to layer. This is why the numerator is 2, not 1.

Definition

Use He (Kaiming) initialization with ReLU and its relatives. Use Xavier (Glorot) with tanh. Sigmoid is not centered at zero. Xavier is still the usual choice for it, but there the derivation holds only roughly. Both schemes come in two versions. The “normal” version draws from a bell curve with the target variance. The “uniform” version draws from a flat range with the same variance. The difference rarely matters.

The same thing in PyTorch

He init for a ReLU layer, compared with the PyTorch default

import torch
import torch.nn as nn

torch.manual_seed(0)
layer = nn.Linear(256, 128)   # fan_in = 256, fan_out = 128
print(layer.weight.var().item())   # 0.001297...  default: 1/(3*256) = 0.0013

# He / Kaiming init, the right choice when a ReLU follows this layer
nn.init.kaiming_normal_(layer.weight, nonlinearity='relu')
nn.init.zeros_(layer.bias)     # biases can start at zero
print(layer.weight.var().item())   # 0.007741...  target: 2/256 = 0.0078

# For a tanh layer you would use Xavier instead:
# nn.init.xavier_normal_(layer.weight)

Note the default. nn.Linear draws its weights uniformly from $[-1/\sqrt{n_\text{in}},\, 1/\sqrt{n_\text{in}}]$. That gives $\mathrm{Var}(w) = 1/(3 n_\text{in})$, about 6× smaller than He. The default works well for shallow networks and for networks with normalization layers. In a deep plain ReLU stack, the signal shrinks layer by layer. Then you call kaiming_normal_ by hand. You also use these functions when you build a custom layer.

▲ Watch out

Two silent failures. All-zero weights: the symmetry trap above; the network never becomes better than one neuron per layer. The wrong scale for a deep network: if the weights are too big, the activations overflow and the loss becomes NaN within a few steps. If they are too small, the activations and gradients fade and the loss barely moves. If your loss goes to NaN at once, check the initialization and the learning rate (next) first.

Check yourself You build a 50-layer ReLU network with 256 inputs per layer, but you draw every weight from a standard normal (variance 1). Predict what happens in the forward pass. Reveal

The activations explode. Each layer multiplies the mean square of the signal by $\tfrac{1}{2} n_\text{in}\mathrm{Var}(w) = 128$. After 50 layers that is about $128^{50} \approx 10^{105}$, far above the float32 maximum (about $3 \times 10^{38}$). The values overflow to inf, and the output becomes NaN on the first forward pass. (We ran this with torch.manual_seed(0): the output is nan.) He init sets the factor to 1, and the signal survives all 50 layers.

2The learning rate: how far to step

Intuition first

Gradient descent moves each weight a little in the downhill direction that backprop found. The learning rate $\alpha$ (also called the step size) is the number that says how big “a little” is. It is usually the first hyperparameter to tune. If it is too big, the steps overshoot and the loss diverges. If it is too small, training crawls.

☂ Everyday parallel

You walk downhill in thick fog to reach the bottom of a valley. You can only feel the slope under your feet. With giant strides you jump over the valley floor and land higher up the far slope. You bounce back and forth and never settle. With tiny steps you get there, but very slowly. The learning rate is the length of your stride.

Now the math

The update rule for the whole parameter vector $\theta$ is:

$$ \theta \leftarrow \theta - \alpha\, \nabla_\theta L $$

In words: the arrow means “replace the left side with the right side.” Take the current parameters $\theta$ and subtract the gradient $\nabla_\theta L$ (the uphill direction) times the learning rate $\alpha$. Subtracting the uphill direction means stepping downhill. $\alpha$ sets the length of the step.

Why does a too-large $\alpha$ diverge? Take the simplest bowl, $L(\theta) = \tfrac{1}{2}k\theta^2$, where $k$ is the curvature. Its gradient is $k\theta$, so one step gives:

$$ \theta \leftarrow \theta - \alpha k \theta = (1 - \alpha k)\,\theta $$

In words: each step multiplies the distance to the minimum by $(1-\alpha k)$. If $\alpha < 2/k$, the size of that factor is below 1 and $\theta$ shrinks toward 0. If $\alpha > 2/k$, the factor is below −1: each step jumps to the other side of the bowl and lands farther away. Then the loss grows every step.

▲ Watch out

Learn the classic signs. Loss going to NaN, or rising: the learning rate is too high; divide it by 10. Loss falling very slowly, almost a flat line: it is too low; raise it. A good first guess for Adam is 1e-3; for plain SGD, 1e-1 to 1e-2. Tune the learning rate before you change anything else.

Check yourself On the bowl $L = \tfrac{1}{2}k\theta^2$ with $k = 10$, what happens with $\alpha = 0.15$? With $\alpha = 0.25$? Reveal

The factor is $1 - \alpha k$. With $\alpha = 0.15$ it is $-0.5$: $\theta$ changes sign every step (a zig-zag) but halves in size, so it still converges. With $\alpha = 0.25$ it is $-1.5$: each step jumps to the other side and 1.5× farther away, so the loss grows. The limit is $\alpha = 2/k = 0.2$. A loss that zig-zags and trends upward means the learning rate is too high.

3Optimizers: better ways to step

Plain gradient descent takes the raw gradient and steps. An optimizer is a rule that reshapes that step to make training faster and more stable. We will build up the three you meet most often (SGD, momentum and Adam). Each one fixes a weakness of the one before.

SGD and why we use minibatches

Intuition first

The “true” gradient is the average gradient over the entire training set. With millions of examples, computing it for every step is very expensive. Stochastic gradient descent (SGD) takes a shortcut. (“Stochastic” means “random.”) It estimates the gradient from a small random group of examples, called a minibatch, and steps on that estimate. The estimate is noisy, but it is cheap. You can take hundreds of steps in the time that one full-dataset step would take.

☂ Everyday parallel

To learn how a national election is leaning, you do not phone all 50 million voters. You poll a random 1,000. The poll is a little off from the true number (that is the noise). But it asks 50,000 times fewer people, so you can repeat it every day. A minibatch is that poll: a small random sample that shows well enough which way to step.

Now the math

SGD is the update from the last section, computed on a minibatch $\mathcal{B}$ instead of the whole set:

$$ \theta \leftarrow \theta - \alpha\, \nabla_\theta L_{\mathcal{B}}(\theta) $$

In words: the same downhill step as before, but the gradient $\nabla_\theta L_{\mathcal{B}}$ is measured on the current minibatch $\mathcal{B}$ only. It is a noisy but unbiased estimate of the true gradient. “Unbiased” means that its average over many batches is the true gradient.

The noise is not only a cost. Its small random kicks can push the optimizer out of shallow bad spots (poor local dips in the loss). A perfectly smooth gradient would stay there.

Momentum: remember where you were going

Intuition first

Pure SGD knows only the slope right now. In a long narrow valley, it bounces from wall to wall instead of rolling along the floor. On flat patches it slows to a crawl. Momentum keeps a running memory of the recent gradients and steps in that accumulated direction. Directions that stay the same build up speed. Side-to-side wobbles cancel out.

☂ Everyday parallel

Roll a heavy bowling ball down a bumpy hill. A small dip or pebble does not stop it; its built-up speed carries it over. Random small bumps to the left and right mostly cancel, so it holds a steady line toward the bottom. That built-up “keep going this way” is what momentum adds to the raw gradient.

Now the math

First, a tool we will use three times. An exponential moving average (EMA) of a sequence of values $g_1, g_2, \dots$ is a running average. It gives recent values more weight and lets old ones fade:

$$ \bar{g} \leftarrow \beta\, \bar{g} + (1-\beta)\, g $$

In words: keep a fraction $\beta$ of the old average and mix in a fraction $1-\beta$ of the new value $g$. With $\beta = 0.9$, a value's weight shrinks by 10% per step, so the average “remembers” roughly the last $1/(1-\beta) = 10$ values.

Momentum keeps a velocity vector $\mathbf{u}$. PyTorch's version is:

$$ \begin{aligned} \mathbf{u} &\leftarrow \beta\, \mathbf{u} + \nabla_\theta L \\ \theta &\leftarrow \theta - \alpha\, \mathbf{u} \end{aligned} $$

In words: first line: the new velocity is $\beta$ (typically 0.9) times the old velocity, plus the fresh gradient. Second line: step along the velocity, not the raw gradient. A steady downhill direction adds up step after step. Noisy sideways parts average toward zero.

This rule has no $(1-\beta)$, so is it an EMA? Yes, up to a constant factor. Define $\bar{g} = (1-\beta)\,\mathbf{u}$ and multiply the first line by $(1-\beta)$:

$$ (1-\beta)\,\mathbf{u} \leftarrow \beta\,(1-\beta)\,\mathbf{u} + (1-\beta)\,\nabla_\theta L \quad\Longleftrightarrow\quad \bar{g} \leftarrow \beta\,\bar{g} + (1-\beta)\,\nabla_\theta L $$

In words: the velocity $\mathbf{u}$ is the EMA of the gradients times $1/(1-\beta)$. With $\beta = 0.9$ that factor is 10. So momentum steps along the average recent gradient. On a steady slope, its step is up to 10× larger than plain SGD with the same $\alpha$.

Check yourself With momentum $\beta = 0.9$, the gradient is the same vector $g$ at every step. What does the velocity $\mathbf{u}$ approach? Reveal

At the steady state, $\mathbf{u} = 0.9\,\mathbf{u} + g$, so $\mathbf{u} = g / 0.1 = 10g$. The step becomes $10\alpha g$. On a steady slope, momentum moves 10× faster than SGD with the same learning rate. When the gradient flips sign from step to step, the terms cancel and the velocity stays small.

Adam: momentum plus a step size for every weight

Intuition first

Momentum fixed the direction. A second problem remains: different weights need different step sizes. Some weights have large gradients and some have tiny ones. With one global learning rate, the first group jumps too far or the second group barely moves. Adam (“adaptive moment estimation”) solves both problems. It uses momentum for the direction, and it gives every parameter its own step size, tuned automatically. It is the default optimizer in much of deep learning.

☂ Everyday parallel

A hiker walks down a mountain. She remembers the general downhill direction she has been walking, so she keeps her momentum. She also measures the ground under each step. Where the ground rises and falls sharply, she shortens her stride. Where it is gentle, she lengthens it. So her stride is about the same length everywhere, whatever the terrain. Adam does this for every weight.

Now the math

Adam keeps two EMAs of the gradient $g = \nabla_\theta L$. Let $t$ be the step count, starting at 1. The first moment $m$ is an EMA of the gradient itself. It tracks which way to go:

$$ m \leftarrow \beta_1\, m + (1-\beta_1)\, g $$

In words: mix the running direction $m$ with the fresh gradient. $\beta_1$ is usually 0.9. This is the momentum half: the smoothed direction.

The second moment $v$ is an EMA of the gradient squared (each component squared, elementwise). It tracks how large each parameter's gradients have been:

$$ v \leftarrow \beta_2\, v + (1-\beta_2)\, g^2 $$

In words: mix the running squared gradient $v$ with the fresh squared gradient. $\beta_2$ is usually 0.999 (a very long memory). A parameter with large gradients builds a large $v$; a parameter with small gradients has a small $v$.

There is a cold-start problem. Both $m$ and $v$ start at zero. So in early steps they are biased toward zero (too small). The bias correction scales them back up:

$$ \hat{m} = \frac{m}{1 - \beta_1^{\,t}}, \qquad \hat{v} = \frac{v}{1 - \beta_2^{\,t}} $$

In words: divide by $1 - \beta^t$. At step $t = 1$ the divisor is small ($0.1$ for $\beta_1$, $0.001$ for $\beta_2$). So it scales the small early estimates back up. As $t$ grows, $\beta^t$ goes to 0 and the divisor goes to 1. For $m$ this takes a few dozen steps ($1-0.9^{12} \approx 0.72$). For $v$ it takes thousands ($1-0.999^{12} \approx 0.012$, $1-0.999^{1000} \approx 0.63$).

Finally, the update: the direction $\hat{m}$, divided by the per-parameter scale $\sqrt{\hat{v}}$:

$$ \theta \leftarrow \theta - \alpha\,\frac{\hat{m}}{\sqrt{\hat{v}} + \epsilon} $$

In words: step in the smoothed direction $\hat{m}$, but divide each parameter's step by the square root of its own $\hat{v}$. $\epsilon$ (about $10^{-8}$) is a tiny number that prevents division by zero. If a gradient is steady at some value $g$, then $\hat{m} \approx g$ and $\sqrt{\hat{v}} \approx |g|$. So the step is about $\alpha$, whatever the size of $g$. Adam removes the gradient's scale and keeps its direction.

◆ Adam in one breath

$m$ is a smoothed direction (momentum). $\sqrt{v}$ is a per-parameter scale that Adam divides out, so every step is roughly $\alpha$ long. Bias correction fixes the too-small early estimates. Together they give an optimizer that usually works at learning rate 1e-3 without tuning each layer. That is why it is a common default.

Figure 12.2 shows the three optimizers on a narrow valley. The loss is $L = \tfrac{1}{2}(x^2 + 25y^2)$: steep across ($y$), gentle along ($x$).

The same thing in PyTorch

the three optimizers share one interface

import torch

model = torch.nn.Linear(64, 10)

# plain SGD
opt = torch.optim.SGD(model.parameters(), lr=1e-2)

# SGD with momentum (beta = 0.9)
opt = torch.optim.SGD(model.parameters(), lr=1e-2, momentum=0.9)

# Adam: betas = (beta1, beta2), eps as above
opt = torch.optim.Adam(model.parameters(), lr=1e-3,
                       betas=(0.9, 0.999), eps=1e-8)

# AdamW: Adam with decoupled weight decay (see below)
opt = torch.optim.AdamW(model.parameters(), lr=1e-3, weight_decay=0.01)

# the training step is the same whichever you chose:
loss = model(torch.randn(32, 64)).sum()   # stand-in for a real loss
opt.zero_grad()    # clear last step's gradients (they accumulate otherwise)
loss.backward()    # backprop fills every .grad
opt.step()         # the optimizer applies its update rule

The loop uses the same three calls for every optimizer: zero_grad, backward, step. The optimizer object hides the momentum and scaling math inside step().

AdamW. Weight decay (L2 regularization, from Section 7) pulls each weight toward zero with strength $\lambda$. Plain Adam adds $\lambda\theta$ to the gradient, so the decay is also divided by $\sqrt{\hat v}$. Weights with large gradients then get almost no decay. AdamW decouples the two: it does the Adam step, then subtracts $\alpha\lambda\theta$ directly. This is the version most large models use.

▲ Watch out

Do not forget opt.zero_grad(). PyTorch adds new gradients into .grad by design. If you skip the reset, this step's gradient is added to the old one. The updates are then wrong, and the model may not converge. Clear the gradients every step.

Check yourself Two weights have steady gradients: 100 for one, 0.01 for the other. With learning rate $\alpha$, how far does SGD move each weight per step? How far does Adam move each (after the first few steps)? Reveal

SGD moves them by $100\alpha$ and $0.01\alpha$: a factor of 10,000 apart. Adam moves both by about $\alpha$. With a steady gradient, $\hat{m} \approx g$ and $\sqrt{\hat{v}} \approx |g|$, so the ratio is about 1. So for the large-gradient weight Adam takes a much smaller step than SGD, and for the small-gradient weight a much larger one. (In PyTorch, 5 Adam steps with lr=1e-3 move both weights by -0.0050.)

4Learning-rate schedules: change the step over time

Intuition first

Even the best fixed learning rate is a compromise. Early in training you want big steps to cover ground fast. Near the bottom, you want small steps, so the weights settle into the minimum instead of bouncing around it. A learning-rate schedule changes $\alpha$ during training, usually from high to low.

☂ Everyday parallel

Parking a car. You drive toward the parking space at normal speed (big steps). Then you slow down for the last few centimeters, so you do not hit the curb (small steps). A schedule does the same: move fast first, then finish slowly and carefully.

Now the math

Here are three common schedules. Let $t$ count training steps (or epochs; an epoch is one full pass over the training data). Step decay multiplies the learning rate by a factor $\gamma$ (for example 0.1 or 0.5) every $s$ steps:

$$ \alpha_t = \alpha_0 \cdot \gamma^{\lfloor t / s \rfloor} $$

In words: start at $\alpha_0$. Every $s$ steps, multiply the rate by $\gamma$. The floor $\lfloor t/s \rfloor$ counts how many drops have happened so far. The result is a staircase.

Cosine decay lowers the rate smoothly along a cosine curve, from $\alpha_0$ to zero over the total training length $T_{\text{total}}$:

$$ \alpha_t = \tfrac{1}{2}\,\alpha_0\left(1 + \cos\frac{\pi t}{T_{\text{total}}}\right) $$

In words: at the start ($t=0$) the cosine is 1, so $\alpha_t = \alpha_0$. At the end ($t=T_{\text{total}}$) the cosine is −1, so $\alpha_t = 0$. In between, the rate follows a smooth S-shaped curve with no sudden drops. It is a very popular choice today.

Warmup is used only at the start. Begin with a tiny learning rate and raise it over the first few hundred or thousand steps. Then a decay schedule takes over. Why? Early on, the weights are random and the gradients are large and change fast. A big step at once can push the model into a bad region. Warmup also gives Adam's $v$ time to collect many gradients before the steps get large.

◆ Why transformers warm up

Large transformer models are sensitive in their first few hundred steps. Without warmup, the loss often diverges early. So a standard recipe is linear warmup, then cosine (or inverse-square-root) decay: raise the learning rate gently, then lower it slowly. When you read a training setup for a transformer, you will usually find these two numbers: the warmup steps and the decay schedule.

The same thing in PyTorch

Adam with linear warmup then cosine decay, stepped every minibatch

import math
import torch
import torch.nn as nn

torch.manual_seed(0)
X, Y = torch.randn(512, 64), torch.randint(0, 10, (512,))   # toy data
train_loader = torch.utils.data.DataLoader(
    torch.utils.data.TensorDataset(X, Y), batch_size=32, shuffle=True)
model = nn.Linear(64, 10)
loss_fn = nn.CrossEntropyLoss()
opt = torch.optim.Adam(model.parameters(), lr=1e-3)

epochs = 20
total = epochs * len(train_loader)   # 20 epochs x 16 batches = 320 steps
warmup = 32

def lr_factor(step):                 # multiplies the base lr of 1e-3
    if step < warmup:
        return (step + 1) / warmup   # linear warmup
    progress = (step - warmup) / (total - warmup)
    return 0.5 * (1 + math.cos(math.pi * progress))   # cosine decay

scheduler = torch.optim.lr_scheduler.LambdaLR(opt, lr_factor)

for epoch in range(epochs):
    for x, y in train_loader:
        opt.zero_grad()
        loss = loss_fn(model(x), y)
        loss.backward()
        opt.step()          # update the weights
        scheduler.step()    # then move the lr one step along the schedule
    if epoch % 5 == 0:
        print(epoch, f"{scheduler.get_last_lr()[0]:.2e}")

Call opt.step() every minibatch. Then call scheduler.step() at the rate the schedule is written for. Here the schedule counts minibatch steps, so we call it every minibatch; warmup needs this. Some schedules (like a step decay every 30 epochs) are written in epochs; then you call scheduler.step() once per epoch. The scheduler changes the lr that the optimizer reads on its next step.

Check yourself In the snippet above, you move scheduler.step() out of the inner loop, so it runs once per epoch. What does the learning rate do over the 20 epochs? Reveal

The schedule counts in steps and expects 320 of them, but now it gets only 20. So the learning rate stays in the warmup phase the whole time. It climbs from $1/32 \cdot 10^{-3}$ to only about $20/32 \cdot 10^{-3} \approx 6 \times 10^{-4}$, and it never decays. The step counter and the schedule must use the same unit.

Check yourself Your model trains well with a fixed learning rate, but in the last third of training the loss stops improving and jitters. What single change is most likely to help, and why? Reveal

Add a decay schedule (step or cosine), so the learning rate shrinks late in training. The jitter means the steps are too large to settle into the minimum: each step overshoots a little. A smaller $\alpha$ lets the weights move closer to the bottom. Cosine decay to near zero is a common choice, and it often gives a small gain in final accuracy.

5What to carry forward

  • Never initialize all weights to the same value (such as zero). Identical neurons get identical gradients and stay copies forever: the symmetry problem. Use small random weights.
  • Scale that randomness to preserve variance across layers: $\mathrm{Var}(w)\approx 1/n_\text{in}$. Use He ($2/n_\text{in}$) with ReLU, because ReLU halves the mean square. Use Xavier ($2/(n_\text{in}+n_\text{out})$) with tanh.
  • The learning rate is the first knob to tune: too high diverges, too low crawls. A good default for Adam is 1e-3.
  • Optimizers build on each other. SGD steps on a cheap, noisy minibatch gradient. Momentum steps along a running average of past gradients. Adam also divides by a per-parameter scale ($\sqrt{\hat v}$) and uses bias correction. AdamW applies weight decay separately.
  • Schedules change the learning rate over time: step or cosine decay to settle, with warmup at the start for sensitive models like transformers.
