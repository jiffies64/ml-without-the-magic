Tensors & Autograd

In Section 10 you built the graph, applied the chain rule and ran the backward pass by hand. Now PyTorch does all of it for you. You will work through a small graph by hand, then watch autograd produce the same gradients.

A tensor is PyTorch's main data structure. Every input, weight and output you work with is a tensor. The idea itself is plain: a grid of numbers with a shape. What makes it useful is that PyTorch can record every operation you do on a tensor. On request, it gives you back the exact gradient: the thing you computed by hand in Section 10.

◆ The one idea to hold onto

A tensor is an n-dimensional array. Autograd is the part of PyTorch that builds a computation graph while you do arithmetic on tensors. It is the same kind of graph you drew by hand in Section 10. Then it runs the same backward pass to fill in every gradient, automatically.

1Tensors: arrays that can grow another dimension

Intuition first

A tensor is a number, a list of numbers, a grid of numbers, or a stack of grids. It is one idea that can keep adding dimensions. A single number is a scalar (rank 0; the rank is the number of dimensions). A list is a vector (rank 1; see Section 1). A grid is a matrix (rank 2). A stack of matrices is a rank-3 tensor, and so on. PyTorch allows any rank.

☂ Everyday parallel

Think of a spreadsheet. One cell is a scalar. One row is a vector. The whole sheet is a matrix. Now think of a workbook: several sheets of the same shape, one behind the other. That stack is a rank-3 tensor. Nothing new happened; you stacked the same kind of thing one level deeper.

Every tensor carries three pieces of information. Check them whenever something breaks:

  • shape: how many entries along each dimension. For example, (64, 3, 28, 28) for 64 color images of 28×28 pixels.
  • dtype: what kind of number is stored (float32, int64, …). Mixing dtypes in one operation is a common source of errors.
  • device: where the numbers are stored, in the CPU's memory or in a GPU's memory. Section 14 shows how to move tensors and models between devices.

The same thing in PyTorch

making tensors and reading their shape

import torch

scalar = torch.tensor(3.0)                     # rank 0
vector = torch.tensor([1.0, 2.0, 3.0])          # rank 1, shape (3,)
matrix = torch.tensor([[1.0, 2.0],
                       [3.0, 4.0]])             # rank 2, shape (2, 2)
cube   = torch.zeros(2, 3, 4)                   # rank 3, shape (2, 3, 4)

print(vector.shape, vector.dtype, vector.device)
# torch.Size([3]) torch.float32 cpu
Check yourself A batch of 32 grayscale images, each 28×28 pixels. What rank is the tensor, and what is a reasonable shape? What changes for color images? Reveal

Rank 3, shape (32, 28, 28): one dimension for “which image in the batch” (32), and two for the pixel grid (28, 28). Color images need a channel dimension for red, green and blue. That gives rank 4: (32, 3, 28, 28).

2Broadcasting: stretching a small tensor to fit a big one

Intuition first

Broadcasting is the rule that lets you combine tensors of different shapes without writing a loop. Suppose one tensor has size 1 along some dimension. Then PyTorch treats it as if it were repeated along that dimension until the shapes match. No memory is copied; the tensor only behaves as if it were.

☂ Everyday parallel

A spreadsheet has one row per shop and one column per product type. Each product type has its own tax rate: 10% on electronics, 5% on clothes, 0% on food. You do not type the rates into every row. You write one row of three rates, and the spreadsheet applies it to every shop. Broadcasting does the same: one small row is applied to every row of a bigger table.

Now the math

PyTorch compares two shapes from the right-hand side, one dimension at a time:

  1. If one shape is shorter, add dimensions of size 1 on its left until both have the same length. So (3,) is read as (1, 3).
  2. Two dimensions are compatible if they are equal, or if one of them is 1. A size-1 dimension is stretched to match the other.
  3. If every pair is compatible, the result takes the larger size in each position. Otherwise PyTorch raises an error.
$$ \text{(4, 3) and (3,)} \;\to\; \text{(4, 3) and (1, 3)} \;\to\; \text{(4, 3)} $$

In words: a 4×3 matrix combined with a vector of length 3 works. The vector gets a missing leading dimension of size 1, so it acts like one row. That row is then stretched to all 4 rows.

The same thing in PyTorch

one row of tax rates applied to every row

import torch

sales = torch.tensor([[100.0, 200.0, 300.0],   # 4 shops (rows),
                      [ 50.0,  75.0,  10.0],   # 3 product types (columns)
                      [400.0, 100.0,  20.0],
                      [ 10.0,  10.0,  10.0]])  # shape (4, 3)

tax_rate = torch.tensor([0.10, 0.05, 0.00])    # one rate per column, shape (3,)

print(sales * tax_rate)   # shape (4, 3): each column gets its own rate, no loop
# tensor([[10.0000, 10.0000,  0.0000],
#         [ 5.0000,  3.7500,  0.0000],
#         [40.0000,  5.0000,  0.0000],
#         [ 1.0000,  0.5000,  0.0000]])
▲ Watch out

The first broadcasting error you will see: sales + torch.ones(4) gives RuntimeError: The size of tensor a (3) must match the size of tensor b (4) at non-singleton dimension 1. Broadcasting stretches only dimensions of size 1. It never guesses how to match a 3 against a 4. Print both .shapes and find the dimension that does not line up. (Here, torch.ones(4, 1) would work: it is one column, stretched across the 3 columns.)

Check yourself x has shape (64, 10) (a batch of 64 rows of 10 scores) and b has shape (10,) (a bias per column). Does x + b broadcast, and to what shape? Reveal

Yes. b is read as (1, 10). From the right: 10 and 10 match; 1 and 64 are compatible. The result has shape (64, 10): the same bias vector added to each of the 64 rows. This is how a linear layer's bias $\mathbf{b}$ in $\mathbf{XW}^\top + \mathbf{b}$ is applied to a whole batch at once.

Check yourself Predictions pred have shape (64, 1) and targets y have shape (64,). What is the shape of pred - y? Why is this dangerous? Reveal

y is read as (1, 64). Then (64, 1) and (1, 64) both stretch, and the result is (64, 64): every prediction minus every target. There is no error. A loss like ((pred - y)**2).mean() still returns one number, but it is the wrong number. Fix it with pred.squeeze(1) or y.unsqueeze(1), so both shapes match.

3Autograd: Section 10, automated

Intuition first

In Section 10 you built a computation graph by hand. It had a node for each operation and arrows for how values flow forward. Then you walked the arrows backward and applied the chain rule to get every gradient. Autograd does the same bookkeeping for you. When you do arithmetic on a tensor with requires_grad=True, PyTorch records the operation as a node in a graph. When you call .backward(), it walks that graph backward and fills in .grad on every leaf.

☂ Everyday parallel

When you do your taxes by hand once, you learn how each deduction changes the final number. Tax software then does the same arithmetic for you every year after: same rules, same order. Section 10 was doing your taxes by hand. Autograd is the software. It is not a different, more clever method. It is the same method, run for you.

Definition

A tensor with requires_grad=True tells PyTorch: “record every operation done with me, because I will want a gradient for this value later.” Calling .backward() on a final scalar output starts the backward pass. The gradient for each tracked tensor is stored in its .grad attribute.

The same thing in PyTorch

the smallest working example

import torch

x = torch.tensor(3.0, requires_grad=True)
y = x ** 2 + 2 * x            # y = x^2 + 2x

y.backward()                  # walk the graph backward from y
print(x.grad)                 # tensor(8.)  because dy/dx = 2x + 2 = 2(3)+2 = 8

A small graph, by hand and by autograd

Take a small expression: multiply two values, add a third, then multiply the result by a fourth. (This example and its numbers come from Andrej Karpathy's micrograd, a tiny autograd engine that is worth reading.)

$$ e = a \cdot b, \qquad d = e + c, \qquad L = d \cdot f $$

In words: three operations in a chain, ending in one number $L$. It has the same building blocks as a neuron: a multiply (like a weight times an input) and an add (like a bias). It has no nonlinearity, so it is not a neural network. But autograd treats every operation the same way, so the method carries over.

With $a = 2$, $b = -3$, $c = 10$, $f = -2$, the forward pass gives $e = -6$, $d = 4$ and $L = -8$. Now apply the chain rule backward from $L$, as in Section 10:

$$ \begin{aligned} \frac{\partial L}{\partial d} &= f = -2, \qquad \frac{\partial L}{\partial f} = d = 4 \\[4pt] \frac{\partial L}{\partial e} &= \frac{\partial L}{\partial d}\cdot\frac{\partial d}{\partial e} = -2 \cdot 1 = -2 \\[4pt] \frac{\partial L}{\partial c} &= \frac{\partial L}{\partial d}\cdot\frac{\partial d}{\partial c} = -2 \cdot 1 = -2 \\[4pt] \frac{\partial L}{\partial a} &= \frac{\partial L}{\partial e}\cdot\frac{\partial e}{\partial a} = -2 \cdot b = 6 \\[4pt] \frac{\partial L}{\partial b} &= \frac{\partial L}{\partial e}\cdot\frac{\partial e}{\partial b} = -2 \cdot a = -4 \end{aligned} $$

In words: start at the output and multiply local derivatives backward along the graph. Each gradient says how much the final number moves per unit change in that variable. For example, $\partial L/\partial a = 6$ means: if you raise $a$ by a tiny amount, $L$ rises by about 6 times that amount.

Now build the same graph in PyTorch and let autograd do the same walk:

autograd reproduces the hand derivation

import torch

a = torch.tensor(2.0,  requires_grad=True)
b = torch.tensor(-3.0, requires_grad=True)
c = torch.tensor(10.0, requires_grad=True)
f = torch.tensor(-2.0, requires_grad=True)

e = a * b
d = e + c
L = d * f

L.backward()

print(a.grad, b.grad, c.grad, f.grad)
# tensor(6.) tensor(-4.) tensor(-2.) tensor(4.)  <-- same as the hand derivation

The numbers are the same. Autograd is not a different or approximate technique. It is the chain-rule walk from Section 10, done by a machine that never forgets a term.

Check yourself Change the last line to L = d * f + a, so $a$ is used twice. Predict a.grad before you run it. Reveal

tensor(7.). $a$ now reaches $L$ along two paths. Through $e$ it gets 6, as before. Through the new “$+\,a$” it gets 1, because addition passes the upstream gradient (here 1) unchanged. When a value is used in several places, the chain rule adds the gradients from all paths, and autograd does the same: $6 + 1 = 7$.

4Graph mechanics: leaves, detaching, and not tracking at all

Intuition first

A few practical rules keep autograd from doing more (or less) work than you want. If you know them, you avoid code that trains on wrong gradients or stops with a confusing error.

Definition

A leaf tensor is one you created directly (like a and b above). It is not the result of an operation on other tracked tensors (like e or d). By default, only leaf tensors keep a .grad. The model's parameters (weights and biases) are always leaves. That is what you want, because those are the numbers you update.

There are two ways to stop autograd from tracking, for different reasons:

  • .detach() returns a new tensor with the same numbers, but not connected to the graph. Use it when you want a value (for example, to log or plot) without its history.
  • torch.no_grad() is a context manager that turns off graph building for everything inside it. Use it for inference (making predictions, not training). No backward pass follows, so a graph would only waste memory and time.

The same thing in PyTorch

three ways a result can be tracked or not

import torch

w = torch.tensor(1.5, requires_grad=True)
x = torch.tensor(2.0)

y = w * x
print(y.requires_grad)        # True  -- built from a tracked tensor

with torch.no_grad():
    y_infer = w * x           # no graph built at all -- for prediction, not training
    print(y_infer.requires_grad)  # False

y_detached = y.detach()       # same value as y, graph history dropped
print(y_detached.requires_grad)   # False
▲ Watch out

Gradients accumulate. Calling .backward() does not overwrite .grad; it adds to what is already there. If you run the backward pass twice without a reset, the two gradients are added together. The model still trains, but on the wrong numbers. This is why every training loop calls optimizer.zero_grad() before each backward pass. We build a full loop in Section 14.

gradients add up until you reset them

import torch

x = torch.tensor(2.0, requires_grad=True)

y = x ** 2
y.backward()
print(x.grad)     # tensor(4.)   dy/dx = 2x = 4

y = x ** 2
y.backward()
print(x.grad)     # tensor(8.)   NOT 4 again -- it accumulated: 4 + 4

x.grad.zero_()    # reset before the next backward pass
y = x ** 2
y.backward()
print(x.grad)     # tensor(4.)  correct, now that we cleared it first
Check yourself Continue the last snippet (so x.grad is 4) with (3 * x).backward() and no reset. What is x.grad now? Then you call x.grad.zero_() and (x ** 3).backward(). What is it then? Reveal

First tensor(7.): the new gradient 3 is added to the old 4. After the reset, tensor(12.): the derivative of $x^3$ is $3x^2 = 3 \cdot 4 = 12$. If a training loss behaves strangely, a missing zero_grad() is one of the first things to check.

5What to carry forward

  • A tensor is an n-dimensional array with a shape, a dtype and a device. Scalar, vector, matrix and higher ranks are all the same idea.
  • Broadcasting lines shapes up on the right, counts missing leading dimensions as 1, and stretches size-1 dimensions. Watch for (N, 1) against (N,).
  • Autograd builds the same computation graph you built by hand in Section 10. .backward() runs the same chain-rule walk, and it matched the hand-computed gradients above.
  • Only leaf tensors (like model parameters) keep .grad. Use .detach() to drop history and torch.no_grad() for inference.
  • Gradients accumulate across calls to .backward(). Zero them before the next backward pass.
