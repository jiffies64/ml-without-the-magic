Sequence Models: RNNs & LSTMs

A recurrent network reads one step at a time and carries a memory forward. The same design that makes this possible also makes it hard to train over long sequences.

32 min read
You'll learn
  • RNNs & hidden state
  • unrolling
  • vanishing/exploding gradients
  • LSTMs
  • why we moved on

The convolutional networks in Section 16 work on a grid, where nearby pixels matter but no direction comes “first”. Text, audio and time series are different. They are sequences, and their order carries meaning. “Dog bites man” and “man bites dog” use the same words in a different order, and they say very different things. Recurrent networks were the first architecture built to respect that order.

◆ The one idea to hold onto

A recurrent network reads a sequence one element at a time. It keeps a running hidden state, a summary of everything seen so far, and updates it at every step. One update rule, used again and again, is the source of its power. As you will see, it is also the source of its biggest weakness.

1RNNs: a hidden state that carries memory forward

Intuition first

A recurrent neural network (RNN) processes a sequence step by step: one word, one audio sample, or one time tick at a time. At each step it looks at two things: the current input, and a running summary of everything before it (the hidden state). From these it makes an updated summary and carries it to the next step.

☂ Everyday parallel

Think of reading a sentence aloud, word by word, to someone who cannot see the page. When you reach “bank” in “I walked along the river bank”, you already have a sense of the sentence from the earlier words. That sense tells you “bank” means the side of a river, not a place for money. You do not re-read the sentence from the start at every word. You carry a summary forward and update it. That summary is the hidden state.

Now the math

At each time step $t$, the network takes the current input $\mathbf{x}_t$ and the previous hidden state $\mathbf{h}_{t-1}$. It produces the new hidden state $\mathbf{h}_t$:

$$ \mathbf{h}_t = \tanh\!\left( \mathbf{W} \mathbf{x}_t + \mathbf{U} \mathbf{h}_{t-1} + \mathbf{b} \right) $$

In words: $\mathbf{W}$ is a matrix that transforms the current input (the same $\mathbf{W}\mathbf{x}$ as in Section 1). $\mathbf{U}$ is a matrix that transforms the previous hidden state, which brings in what the network remembers. $\mathbf{b}$ is a bias vector. The $\tanh$ squashes each entry into the range −1 to 1, so the hidden state cannot grow without limit. The key point: the same $\mathbf{W}$, $\mathbf{U}$ and $\mathbf{b}$ are used at every time step. One small set of weights handles a sequence of any length. This is like one convolution kernel being used at every position in Section 16.

Unrolling and backpropagation through time

To picture the RNN, and to train it, we draw it “unrolled”. We make one copy of the update rule per time step and lay the copies out left to right. Each copy passes its hidden state to the next one, and each copy also receives its own input:

$$ \begin{array}{ccccccc} & & \mathbf{x}_1 & & & & \mathbf{x}_T \\ & & \downarrow & & & & \downarrow \\ \mathbf{h}_0 & \to & \mathbf{h}_1 & \to & \cdots & \to & \mathbf{h}_T \end{array} $$

In words: $\mathbf{h}_0$ is the starting state (usually all zeros), and $T$ is the sequence length. The unrolled picture looks like a very deep feedforward network, except that every copy shares the same weights $\mathbf{W}$ and $\mathbf{U}$. We train it with ordinary backpropagation (Section 10) on this unrolled picture. This is called backpropagation through time (BPTT). The error at the last step must flow backward through every earlier step, through the same matrix $\mathbf{U}$ each time, to reach the start of the sequence.

The same thing in PyTorch

an RNN over a batch of sequences

import torch
import torch.nn as nn

torch.manual_seed(0)
rnn = nn.RNN(input_size=8, hidden_size=16, batch_first=True)

x = torch.randn(4, 10, 8)          # (batch=4, sequence length=10, features=8)
h0 = torch.zeros(1, 4, 16)         # (layers=1, batch=4, hidden=16), all zeros

outputs, h_last = rnn(x, h0)
print(outputs.shape)   # torch.Size([4, 10, 16]) -> hidden state at each of the 10 steps
print(h_last.shape)    # torch.Size([1, 4, 16])  -> only the final hidden state
print(torch.allclose(outputs[:, -1], h_last[0]))  # True: the last output IS h_T

In words: batch_first=True changes the layout of x and outputs only. The hidden state h0 keeps the shape (layers, batch, hidden) either way. The first axis counts stacked RNN layers; here there is one.

Check yourself Predict the parameter count of nn.RNN(input_size=8, hidden_size=16). Does it change if you feed it a sequence of length 500 instead of 10? Reveal

$\mathbf{W}$ is 16×8 = 128 numbers and $\mathbf{U}$ is 16×16 = 256. PyTorch keeps two bias vectors of 16 each (one for the input part, one for the hidden part). So the total is 128 + 256 + 32 = 416. The count does not change with the sequence length. The weights describe one update step, not the whole sequence. A 500-step sequence runs the same update 500 times instead of 10.

2The failure mode: vanishing and exploding gradients

Intuition first

Here is the problem with using the same weight matrix at every step. Backpropagation through time multiplies by that same matrix once per time step, all the way back to the start. Repeated multiplication does not stay neutral. It compounds, like repeated stretching or repeated shrinking.

☂ Everyday parallel

A message passes down a long line of people. Each person repeats it at 90% of the volume they heard. After 10 people it is at 35% of the first volume. After 50 people it is at 0.5%, and you can no longer hear it. If each person instead repeats it 10% louder, after 50 people it is over 100 times louder. A small change per step, repeated along a long chain, makes the signal fade away or blow up.

Now the math

Let's find how the last hidden state depends on an early one. Write $\mathbf{a}_t = \mathbf{W}\mathbf{x}_t + \mathbf{U}\mathbf{h}_{t-1} + \mathbf{b}$, so $\mathbf{h}_t = \tanh(\mathbf{a}_t)$. One step back, the chain rule gives a Jacobian (the matrix of all partial derivatives):

$$ \frac{\partial \mathbf{h}_t}{\partial \mathbf{h}_{t-1}} = \operatorname{diag}\!\big(1 - \mathbf{h}_t^2\big)\,\mathbf{U} $$

In words: the derivative of $\tanh$ is $1 - \tanh^2$. So the Jacobian is $\mathbf{U}$, with each row scaled by the tanh slope of that unit. $\operatorname{diag}(\cdot)$ puts a vector on the diagonal of a matrix. Each slope is between 0 and 1.

Going back $T$ steps multiplies $T$ of these Jacobians:

$$ \frac{\partial \mathbf{h}_T}{\partial \mathbf{h}_0} = \prod_{t=T}^{1} \operatorname{diag}\!\big(1 - \mathbf{h}_t^2\big)\,\mathbf{U} $$

In words: the gradient that connects the last hidden state to the first passes through $T$ copies of $\mathbf{U}$, each scaled by slopes of at most 1. Recall from Section 1 that a matrix's eigenvalues are its stretch factors, and that repeated multiplication raises them to a power. If the largest eigenvalue of $\mathbf{U}$ (in absolute value) is below 1, the product shrinks toward zero as $T$ grows. The tanh slopes can only shrink it more. This is the vanishing gradient problem. It is the same effect as the eigenvalue example in Section 1 and the depth problem in Section 12. If the largest eigenvalue is above 1, the product can blow up: the exploding gradient problem. It does not always blow up, because the tanh slopes can pull it back down. So an eigenvalue above 1 is needed for explosion, but it is not enough on its own (Pascanu et al., 2013).

▲ Watch out

This is why plain RNNs do badly on long-range tasks. An example: “does the verb at the end of a long paragraph agree with the subject at the start?” The gradient must pass back through dozens of update steps to link the two. By then, it has often faded to nearly nothing. At prediction time the same happens to the hidden state: information about the early subject gets overwritten step by step.

Check yourself Suppose each backward step scales the gradient by about 0.9. How much weaker is the signal from 50 steps back than from 1 step back? What does that mean for learning? Reveal

$0.9^{50} \approx 0.005$, so about half a percent of the signal survives. Compared with one step back ($0.9$), the signal is roughly 170 times weaker. The weight update is a sum over all steps, so the short-range terms fill it almost completely. The network learns short-range patterns well and long-range ones barely at all. This is why plain RNNs have a “short memory” in practice, even though the hidden state could in principle carry information from every step.

3LSTMs: gates that choose what to remember

Intuition first

The LSTM (Long Short-Term Memory) is an RNN variant designed against the vanishing gradient. A plain RNN pushes everything through one $\tanh$ update every step. An LSTM instead keeps a separate memory cell. It uses three learned gates to decide, at every step, what to forget, what to add, and what to read out.

☂ Everyday parallel

Imagine you keep a notebook while you read a long report. On each page you make three decisions. Which old notes do you cross out because they no longer matter? (The forget gate.) Which new fact do you write down? (The input gate.) How much of the notebook do you read back to use right now? (The output gate.) The notebook itself, the memory cell, stays the same from page to page except where you edit it. You do not rewrite it from scratch on every page.

Definition

A gate in an LSTM is a small learned layer followed by the sigmoid function $\sigma(\cdot)$, so each output is between 0 and 1. It works like a volume knob for each element. Near 0 it blocks information; near 1 it lets information through unchanged. The forget, input and output gates are three separate knobs, each learned for its own job.

Now the math

At step $t$, the LSTM reads $\mathbf{x}_t$ and the previous hidden state $\mathbf{h}_{t-1}$. It computes three gates and one candidate memory. Each has its own weights, and each has the same form as the RNN update:

$$ \begin{aligned} \mathbf{f}_t &= \sigma\big(\mathbf{W}_f \mathbf{x}_t + \mathbf{U}_f \mathbf{h}_{t-1} + \mathbf{b}_f\big) \\ \mathbf{i}_t &= \sigma\big(\mathbf{W}_i \mathbf{x}_t + \mathbf{U}_i \mathbf{h}_{t-1} + \mathbf{b}_i\big) \\ \mathbf{o}_t &= \sigma\big(\mathbf{W}_o \mathbf{x}_t + \mathbf{U}_o \mathbf{h}_{t-1} + \mathbf{b}_o\big) \\ \tilde{\mathbf{c}}_t &= \tanh\big(\mathbf{W}_c \mathbf{x}_t + \mathbf{U}_c \mathbf{h}_{t-1} + \mathbf{b}_c\big) \end{aligned} $$

In words: $\mathbf{f}_t$ is the forget gate, $\mathbf{i}_t$ the input gate, $\mathbf{o}_t$ the output gate, and $\tilde{\mathbf{c}}_t$ the candidate memory. All four read the same inputs. The three gates use a sigmoid, so they are knobs between 0 and 1. The candidate $\tilde{\mathbf{c}}_t$ uses tanh, so it is new content between −1 and 1.

Then the cell and the hidden state are updated:

$$ \begin{aligned} \mathbf{c}_t &= \mathbf{f}_t \odot \mathbf{c}_{t-1} + \mathbf{i}_t \odot \tilde{\mathbf{c}}_t \\ \mathbf{h}_t &= \mathbf{o}_t \odot \tanh(\mathbf{c}_t) \end{aligned} $$

In words: $\odot$ means element-by-element multiplication. The new memory is the old memory, scaled by the forget gate, plus new content, scaled by the input gate. The hidden state is a gated readout of the memory.

Now see why this helps the gradient. Follow only the memory path and treat the gates as given. Then one step back is:

$$ \begin{aligned} \frac{\partial \mathbf{c}_t}{\partial \mathbf{c}_{t-1}} &= \operatorname{diag}(\mathbf{f}_t) \\[4pt] \frac{\partial \mathbf{c}_T}{\partial \mathbf{c}_0} &= \operatorname{diag}\big(\mathbf{f}_T \odot \cdots \odot \mathbf{f}_1\big) \end{aligned} $$

In words: on the memory path, each backward step multiplies the gradient by the forget gate. No $\mathbf{U}$, no tanh slope. If the network learns to keep a fact ($\mathbf{f}_t$ near 1 for that unit), the gradient for that unit passes back almost unchanged. Compare the RNN's product of $\operatorname{diag}(1-\mathbf{h}_t^2)\,\mathbf{U}$ terms. (The gates also depend on $\mathbf{h}_{t-1}$, which adds more paths. We ignore those here; the memory path is the one that carries long-range gradients.)

This additive update is similar to the $\mathbf{x} + F(\mathbf{x})$ skip connection of Section 16. Both give the gradient a path with no repeated matrix multiplication. The LSTM eases the vanishing gradient, but it does not remove it. The forget gates must learn values near 1, and a product of many values like 0.95 still shrinks. The code below shows how much the forget gate matters.

The same thing in PyTorch

an LSTM, and the forget gate controlling the gradient path

import torch
import torch.nn as nn

torch.manual_seed(0)
lstm = nn.LSTM(input_size=8, hidden_size=16, batch_first=True)
x = torch.randn(4, 10, 8)            # (batch=4, sequence length=10, features=8)
h0 = torch.zeros(1, 4, 16)           # (layers, batch, hidden): batch_first does not apply here
c0 = torch.zeros(1, 4, 16)           # LSTMs carry a memory cell next to the hidden state

outputs, (h_last, c_last) = lstm(x, (h0, c0))
print(outputs.shape)  # torch.Size([4, 10, 16])
print(c_last.shape)   # torch.Size([1, 4, 16])  -> the memory cell, separate from h
print(lstm.weight_hh_l0.shape)  # torch.Size([64, 16]) -> 4 blocks (i, f, g, o) of 16 rows

def grad_to_first_input(model, T=50):
    x = torch.randn(1, T, 8, requires_grad=True)
    _, (h, c) = model(x)
    c.sum().backward()               # how much does step 1 still affect c_T?
    return x.grad[0, 0].norm().item()

print(f"{grad_to_first_input(lstm):.1e}")   # 1.7e-11  tiny: forget gates start near 0.5
with torch.no_grad():
    lstm.bias_ih_l0[16:32] += 5.0    # rows 16..31 are the forget gate: f near sigmoid(5) = 0.99
print(f"{grad_to_first_input(lstm):.1e}")   # 1.0e+00  the cell path now carries the gradient

In words: PyTorch stores the four blocks stacked in one matrix, in the order input gate, forget gate, candidate (called g), output gate. The experiment changes only the forget-gate bias. With gates near 0.5, the gradient from step 1 to step 50 is about $10^{-11}$. With gates near 0.99, it is about 1. This is why many LSTM implementations start the forget-gate bias at 1 or higher.

Check yourself At the start of training, the forget-gate bias is near 0, so $\mathbf{f}_t \approx \sigma(0) = 0.5$. Estimate the memory-path gradient factor over 50 steps. Is that better than the plain RNN with factor 0.9? Reveal

$0.5^{50} \approx 9 \times 10^{-16}$. That is far worse than $0.9^{50} \approx 0.005$. The additive memory path is not magic: it only helps when the forget gates are close to 1. The LSTM's advantage is that the network can learn to set $\mathbf{f}_t$ near 1 for the units that must remember. Nothing else on the path shrinks the gradient. In a plain RNN, $\mathbf{U}$ and the tanh slopes are in the way at every step. This is why the forget-gate bias is often set to 1 or more at the start.

4Why we moved on: the case for attention

Intuition first

LSTMs eased the gradient problem. But they did not change one other limit. An RNN must process a sequence one step at a time. Step 50 needs the hidden state from step 49, which needs step 48, and so on back to the start. You cannot compute step 50 before step 49 is done.

☂ Everyday parallel

Compare two ways to read a book. In the first, one person reads it aloud, page by page. In the second, you give every page to a different reader in a room. They all read at the same time, then compare notes. The second way only works if each reader can look at any other page when needed. They cannot depend only on what the previous reader passed along.

This order of steps has a concrete cost. GPUs are built to do very many independent calculations at the same time. An RNN cannot use that parallel power along the time axis. Step 50 must wait for step 49, even when many processors are idle. So training on long sequences is slow. And even LSTMs still lose information over very long distances.

◆ The opening for attention

In an RNN, information from position 3 must pass through every step to reach position 300. What if position 300 could look at position 3 directly? There would be no relay, and nothing would stop us from computing many positions at once. That is the idea behind Section 18: attention and the transformer. They replace the step-by-step hidden state with a way for every position to look directly at every other position.

Check yourself An RNN reads a 1,000-token sequence on a GPU that can run 1,000 independent calculations at once. How many steps must run one after another? What would it be if every position could read every other position directly? Reveal

The RNN needs 1,000 steps in a row, one per token, because each needs the previous hidden state. The extra processors do not help along the time axis. If each position can read the others directly, the positions do not wait for each other. All 1,000 can be computed in one parallel step per layer. The gradient path between any two positions is also one step long, instead of up to 1,000.

5What to carry forward

  • An RNN reads a sequence step by step. It keeps a hidden state that is updated by the same weights at every step: $\mathbf{h}_t = \tanh(\mathbf{W}\mathbf{x}_t + \mathbf{U}\mathbf{h}_{t-1} + \mathbf{b})$.
  • Unrolling turns the recurrence into a deep chain of identical steps. Training it is backpropagation through time.
  • The gradient over $T$ steps is a product of $T$ Jacobians $\operatorname{diag}(1-\mathbf{h}_t^2)\,\mathbf{U}$. So it tends to vanish when $\mathbf{U}$'s largest eigenvalue is below 1, and it can explode when it is above 1.
  • LSTMs add gates and an additive memory cell, $\mathbf{c}_t = \mathbf{f}_t \odot \mathbf{c}_{t-1} + \mathbf{i}_t \odot \tilde{\mathbf{c}}_t$. On the memory path the gradient is scaled only by the forget gates. This eases the problem but does not remove it.
  • RNNs and LSTMs are sequential: they cannot run in parallel across time steps. That, and their limited long-range memory, is what motivates attention and transformers.
