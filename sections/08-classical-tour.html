A Tour of Classical Models

Before neural networks, machine learning already worked — meet the four ideas that still quietly win on everyday tabular data.

16 min read You'll learn: k-nearest neighbors · decision trees · ensembles · SVM intuition

This section is a fast tour, on purpose. No derivations — just one solid intuition and one everyday parallel per model, so you know what each one is doing and when to reach for it. We'll go deep on neural networks for the rest of the course; these classical models are still the right choice for a huge share of real, structured (tabular) data problems.

◆ The one idea to hold onto

Each model below makes a different bet about how to turn "examples I've seen" into "a prediction for something new." Knowing the bet each one makes is enough to know when to use it — you don't need to derive it to use it well.

1k-Nearest Neighbors: ask the closest examples

Intuition first

k-Nearest Neighbors (kNN) has almost no "training" step at all — it just remembers every labeled example. To predict on something new, it finds the k stored examples closest to it (measured by ordinary distance — the L2 norm from Section 1) and takes a majority vote of their labels.

☂ Everyday parallel

You've just moved to a new neighborhood and want a restaurant recommendation. You don't consult a general-purpose critic — you ask the few neighbors who live closest to you, on the theory that people nearby tend to have similar taste and know the same local spots. Whatever most of them recommend is your answer. That's kNN: no theory about restaurants in general, just "ask the nearest ones and go with the majority."

▲ Watch out: the curse of dimensionality

With very many features, almost every pair of points ends up roughly the same distance apart, so "closest" stops meaning much — kNN quietly degrades as dimensions pile up.

The same thing in code

from sklearn.neighbors import KNeighborsClassifier

model = KNeighborsClassifier(n_neighbors=5)
model.fit(X_train, y_train)          # "fit" just stores the data -- no real learning happens
pred = model.predict(X_new)          # for each new point: find its 5 closest neighbors, vote
Check yourself Why does kNN get slower at prediction time as your training set grows, unlike a trained decision tree or SVM? Reveal

Because kNN has no real training phase — all the "work" is deferred to prediction time. Every single prediction requires measuring the distance from the new point to every stored training example to find the closest k. A decision tree or SVM instead spends effort once, up front, to build a compact rule (a tree of splits, or a boundary defined by a few support vectors), so predicting afterward is fast regardless of how large the original training set was.

2Decision trees: a flowchart of yes/no questions

Intuition first

A decision tree predicts by asking a series of simple yes/no questions about the features ("is age > 30?", "is income > 50k?"), branching on the answer, and repeating until it reaches a leaf that holds the prediction. Training a tree just means choosing, at each branch, the question that best separates the classes.

☂ Everyday parallel

It's the game of 20 Questions. "Is it alive?" "Is it bigger than a breadbox?" Each answer cuts the space of possibilities roughly in half, and a handful of well-chosen questions narrows a huge range of options down to one guess. A decision tree is exactly this game played automatically, with the questions chosen from the training data.

Trees are wonderfully interpretable — you can print the whole flowchart and read off exactly why it made a prediction. But left alone, they overfit easily: given enough questions, a tree can carve out a tiny leaf for every single training example, memorizing the data instead of learning the pattern (exactly the failure mode from Section 7).

The same thing in code

from sklearn.tree import DecisionTreeClassifier

model = DecisionTreeClassifier(max_depth=4)   # cap the depth so it can't ask endless questions
model.fit(X_train, y_train)
Check yourself Why does limiting max_depth help a decision tree generalize better? Reveal

Depth controls the tree's capacity: an unlimited tree can keep splitting until every leaf holds a single training example, which means it has memorized the training set's noise along with its pattern (high variance). Capping the depth forces the tree to stop asking questions early, keeping only the splits that separate large, meaningful groups — trading a bit of training accuracy for a model that holds up on new data.

3Ensembles: combine many weak models

Intuition first

A single tree is unstable and prone to overfitting. Ensembles fix this by combining many models instead of trusting one, in two different ways.

☂ Everyday parallel

Bagging (used in random forests) is the wisdom-of-the-crowd fact that a county fair uses to guess an ox's weight: ask one person and they might be way off, but average hundreds of independent guesses and the errors cancel out, leaving a surprisingly accurate number. A random forest trains many trees, each on a random subset of the data and features, then averages their votes. Boosting is different: it's like a series of tutors, where each new tutor looks specifically at the mistakes the previous tutors' combined advice got wrong, and focuses entirely on fixing those. Each new model is trained to correct the ensemble's current errors, and the models are added together rather than simply averaged.

The same thing in code

from sklearn.ensemble import RandomForestClassifier, GradientBoostingClassifier

forest = RandomForestClassifier(n_estimators=200)   # bagging: many trees, average their votes
forest.fit(X_train, y_train)

boosted = GradientBoostingClassifier(n_estimators=200)  # boosting: each tree fixes the last one's errors
boosted.fit(X_train, y_train)
Check yourself A random forest and a gradient boosting model both use decision trees underneath. What's the key structural difference in how they combine those trees? Reveal

A random forest trains its trees independently and in parallel, each on a random subset of data and features, then averages their votes — the trees don't know about each other. Gradient boosting trains its trees sequentially: each new tree is trained specifically to correct the errors the ensemble-so-far is still making, then gets added on top. Bagging mainly reduces variance (averaging cancels noise); boosting mainly reduces bias (each step directly attacks remaining errors).

4SVM intuition: the widest street between classes

Intuition first

A support vector machine (SVM) for classification looks for the line (or, in higher dimensions, the flat boundary called a hyperplane) that separates the two classes with the widest possible margin — the biggest empty gap on either side before you hit a training point.

☂ Everyday parallel

Imagine drawing the widest possible straight road between two neighborhoods, without the road touching a single house on either side. Many roads would separate the neighborhoods, but the widest one gives you the most buffer if a new house is built close to the boundary later. An SVM finds exactly that widest street; the houses closest to its edges — the ones that would get clipped first if the road narrowed — are called the support vectors, and they're the only points that actually determine where the road goes.

Real data is rarely neatly separable by a straight line. The kernel trick handles this in one clean move: it lifts the data into a higher-dimensional space (for example, adding each point's squared distance from the center as a new feature) where a straight boundary in that higher space can separate classes that were tangled together in the original space — then that boundary maps back down to a curved one in the space you started with. Crucially, the kernel trick computes the effect of this lift without ever explicitly building the higher-dimensional points, which is what keeps it fast.

The same thing in code

from sklearn.svm import SVC

model = SVC(kernel="rbf")     # "rbf" kernel = the lift-into-higher-dimensions trick
model.fit(X_train, y_train)
Check yourself Why are only the "support vectors" — and not every training point — needed to describe the final SVM boundary? Reveal

The boundary is defined purely by finding the widest possible margin, and the width of that margin is limited only by whichever points sit closest to it on each side. Move a point that's already far from the boundary and the widest street doesn't change at all — it was never constraining the margin. Move one of the closest points and the street's position and width shift immediately. So only those closest points (the support vectors) matter for describing the boundary; the rest could be deleted after training with no effect on the model.

5When to use what

Model Strength Weakness When to reach for it
k-Nearest Neighbors Simple, no training step, adapts to any shape of boundary Slow at prediction time on large data; degrades in high dimensions Quick baseline on small, low-dimensional datasets
Decision tree Interpretable, handles mixed feature types, no feature scaling needed Overfits easily; unstable (small data changes → different tree) When you (or a regulator) need to read the exact rule
Random forest (bagging) Much more stable and accurate than a single tree; resists overfitting Less interpretable; slower and heavier than one tree Strong, low-effort default for tabular data
Gradient boosting Usually the most accurate classical model on tabular data More hyperparameters to tune; trains sequentially (slower to fit); can overfit if pushed too far Squeezing out the best possible accuracy on structured data
SVM Strong with a clear margin; kernel trick handles non-linear boundaries; works with few samples relative to features Doesn't scale well to huge datasets; needs feature scaling Small-to-medium datasets, especially with a clean or kernel-recoverable margin

6What to carry forward

  • kNN predicts by majority vote among the closest stored examples — no real training.
  • Decision trees are readable yes/no flowcharts that overfit easily on their own.
  • Ensembles fix that: bagging/random forests average many independent trees (wisdom of the crowd); boosting chains models that each fix the last one's mistakes.
  • SVMs find the widest-margin boundary, and the kernel trick lets that boundary be curved by lifting data into a higher dimension first.
  • None of this required deep math — the same intuitions (closeness, splitting, voting, margins) carry a long way in practice.
