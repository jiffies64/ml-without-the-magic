A Tour of Classical Models

Machine learning worked well before neural networks. Meet four ideas that are still the best choice for many everyday table-shaped datasets.

30 min read
You'll learn

This section is a fast tour, on purpose. For each model you get one clear intuition, one everyday parallel, and at most one or two small formulas. That is enough to know what each model does and when to use it. The rest of the course goes deep on neural networks. Still, these classical models remain the right choice for many problems with tabular data. Tabular data fits in a table: one row per example, one column per feature.

◆ The one idea to hold onto

Each model below makes a different assumption about how to turn “examples I have seen” into “a prediction for something new”. If you know the assumption, you know when the model will work well.

1k-Nearest Neighbors: ask the closest examples

Intuition first

k-Nearest Neighbors (kNN) has almost no training step. It stores every labeled example. To predict for a new point, it finds the $k$ stored examples closest to it and takes a majority vote of their labels. “Closest” usually means ordinary distance: the L2 norm from Section 1.

☂ Everyday parallel

You want to know whether you will like a new film. You find the 5 people whose past film ratings are most similar to yours. If most of them liked the new film, you predict that you will like it too. That is kNN. Each person is a stored example, “similar ratings” is the distance, and the majority of the 5 is the prediction.

Now the math

For a new point $\mathbf{x}$, compute its distance to each stored point $\mathbf{x}_i$:

$$ d_i = \lVert \mathbf{x} - \mathbf{x}_i \rVert_2 $$

Let $\mathcal{N}_k(\mathbf{x})$ be the set of the $k$ stored points with the smallest $d_i$. The prediction is the most common label among them:

$$ \hat y = \arg\max_{c}\; \big|\{\, i \in \mathcal{N}_k(\mathbf{x}) : y_i = c \,\}\big| $$

In words: for each class $c$, count how many of the $k$ nearest neighbors have label $c$. Predict the class with the largest count. The vertical bars $|\cdot|$ mean “the number of elements in”.

▲ Watch out: feature scale and the curse of dimensionality

Distance adds up all features, so a feature measured in large units (income in dollars) outweighs one in small units (age in years). Normalize the features first (Section 5). Also, with very many features, almost all pairs of points are about the same distance apart. Then “closest” means little, and kNN gets worse as the number of dimensions grows.

The same thing in NumPy

kNN prediction from scratch

import numpy as np

rng = np.random.default_rng(4)
X_train = np.vstack([rng.normal([2, 2], 1.0, size=(15, 2)),    # class 0
                     rng.normal([5, 4], 1.0, size=(15, 2))])   # class 1
y_train = np.array([0] * 15 + [1] * 15)

def knn_predict(X_train, y_train, x_new, k=5):
    dists = np.linalg.norm(X_train - x_new, axis=1)    # distance to every stored point
    nearest = np.argsort(dists)[:k]                     # indices of the k closest
    votes = np.bincount(y_train[nearest], minlength=2)  # count the labels among them
    return votes.argmax(), votes

label, votes = knn_predict(X_train, y_train, np.array([3.2, 3.2]))
print(label, votes)   # 1 [2 3]

With scikit-learn, the same model is KNeighborsClassifier(n_neighbors=5). Its fit method only stores the data (and may build a search structure, see the check below).

Check yourself The code above computes the distance to every stored point. What happens to prediction time when the training set grows 100 times larger? How can libraries reduce this? Reveal

With this brute-force search, each prediction becomes about 100 times slower, because kNN does its work at prediction time, not at training time. Libraries reduce this with search structures such as KD-trees and ball trees. They split space into regions, so the search can skip regions that are far away. This works well with few features. With many features (the curse of dimensionality again), the structures help less, and approximate nearest-neighbor methods are used instead.

2Decision trees: a flowchart of yes/no questions

Intuition first

A decision tree predicts by asking a series of simple yes/no questions about the features (“is age > 30?”, “is income > 50,000?”). It follows the answers down the branches until it reaches a leaf, which holds the prediction. Training a tree means choosing, at each branch, the question that best separates the classes.

☂ Everyday parallel

It is the game of 20 Questions. “Is it alive?” “Is it larger than a chair?” Each answer removes many possibilities. A few good questions narrow a huge range of options down to one guess. A decision tree plays this game automatically. It chooses its questions from the training data.

Now the math

How does a tree measure “best separates”? A common choice is Gini impurity. If a group of examples has a fraction $p_c$ of class $c$, its impurity is:

$$ G = 1 - \sum_c p_c^2 $$

In words: $G$ is 0 when the group is pure (one class only). For two classes it is largest, $0.5$, when they are mixed half and half. A candidate question splits a group into two smaller groups. The tree picks the question whose two groups have the lowest impurity on average, weighted by group size. (Another common measure is the entropy from Section 4.)

Trees are very interpretable: you can print the whole flowchart and read why it made a prediction. But on their own they overfit easily. With enough questions, a tree can make a tiny leaf for every training example. It then memorizes the data instead of learning the pattern: the failure from Section 7.

In practice you train these models with a library such as scikit-learn, not by hand. The remaining snippets use it and assume X_train and y_train hold your data.

a depth-limited tree in scikit-learn

from sklearn.tree import DecisionTreeClassifier

# X_train, y_train: your data, e.g. from the kNN example above
model = DecisionTreeClassifier(max_depth=4)   # cap the depth: at most 4 questions per path
model.fit(X_train, y_train)
Check yourself A group has 8 examples of class A and 2 of class B. What is its Gini impurity? Would splitting it into (4 A, 0 B) and (4 A, 2 B) help? Reveal

$G = 1 - 0.8^2 - 0.2^2 = 0.32$. After the split, the first group is pure ($G = 0$). The second has $G = 1 - (4/6)^2 - (2/6)^2 \approx 0.444$. The weighted average is $\tfrac{4}{10}\cdot 0 + \tfrac{6}{10}\cdot 0.444 \approx 0.267$. That is lower than 0.32, so the split helps a little. A split that put both B examples alone in one group would reach 0.

3Ensembles: combine many weak models

Intuition first

A single tree is unstable and overfits easily. Ensembles fix this by combining many models instead of trusting one. There are two main ways to do it.

Bagging (short for “bootstrap aggregating”) trains many trees. Each tree sees a bootstrap sample of the data: a random sample of the same size, drawn with replacement. Then it averages their votes. A random forest is bagging with one more trick: at each split, each tree may only look at a random subset of the features.

Boosting trains models one after another. Each new model is trained to correct the errors that the ensemble so far still makes. The models are added together, not averaged.

☂ Everyday parallel

Bagging is like asking many people to guess the number of beans in a jar and averaging the guesses. One guess can be far off, but averaging many guesses cancels part of the error. It cancels more when the people guess independently. If they all talked to each other first, they would make similar mistakes, and averaging would help less. Boosting is like a series of tutors. Each new tutor looks at the questions the student still gets wrong after all earlier tutoring, and works on those.

This is why random forests sample features. Trees trained on bootstrap samples of the same data are still similar, so their errors are correlated, and averaging cancels only part of them. Restricting each split to random features makes the trees more different from each other, so averaging cancels more.

bagging and boosting in scikit-learn

from sklearn.ensemble import RandomForestClassifier, GradientBoostingClassifier

# X_train, y_train: your data
forest = RandomForestClassifier(n_estimators=200)       # bagging: 200 trees on bootstrap samples, vote
forest.fit(X_train, y_train)

boosted = GradientBoostingClassifier(n_estimators=200)  # boosting: each tree corrects the ensemble's current errors
boosted.fit(X_train, y_train)
Check yourself You build a “forest” of 200 trees, but every tree is trained on the full dataset with all features and no randomness. How much better is it than one tree? Reveal

Not better at all. With the same data, the same features, and no randomness, the tree algorithm builds the same tree 200 times. All their errors are identical, so averaging cancels nothing. Averaging helps only when the models make different errors. That is why random forests add two sources of randomness: bootstrap samples and random feature subsets. (In the terms of Section 7: bagging reduces variance, and only when the trees vary.)

4SVM intuition: the widest street between classes

Intuition first

A support vector machine (SVM) for classification looks for the line that separates the two classes with the widest possible margin. In higher dimensions the line becomes a flat boundary called a hyperplane. The margin is the empty gap on either side of the line before you reach a training point.

☂ Everyday parallel

Imagine building the widest possible straight road between two neighborhoods, without the road touching any house. Many roads would separate the neighborhoods. The widest one leaves the most space if a new house is built near the edge later. An SVM finds that widest road. The houses touching its edges are the support vectors. They are the only houses that decide where the road goes.

Now the math

Write the boundary as $\mathbf{w}^\top\mathbf{x} + b = 0$. The distance from a point $\mathbf{x}$ to this boundary is $|\mathbf{w}^\top\mathbf{x} + b| / \lVert\mathbf{w}\rVert$. We can multiply $\mathbf{w}$ and $b$ by any positive number without moving the boundary. So choose the scale where the closest points on each side have $\mathbf{w}^\top\mathbf{x} + b = \pm 1$. Then each edge of the street is at distance $1/\lVert\mathbf{w}\rVert$ from the boundary, and:

$$ \text{margin} = \frac{2}{\lVert\mathbf{w}\rVert} $$

In words: a wide street means a small $\lVert\mathbf{w}\rVert$. So the SVM minimizes $\lVert\mathbf{w}\rVert^2$. At the same time, it requires every training point to be on the correct side, with $|\mathbf{w}^\top\mathbf{x} + b| \ge 1$.

Real data is rarely separable by a straight line. The kernel trick helps. First, imagine lifting the data into a space with more dimensions, for example by adding products of features as new features. In that space, a straight boundary may separate classes that were mixed in the original space. Seen back in the original space, that boundary is curved.

The trick is that the SVM only needs dot products between points, never the points themselves. For some lifts, you can compute the dot product in the big space directly from the original points. Here is a small example in 2-D. Define the lift $\phi(\mathbf{x}) = (x_1^2,\ \sqrt2\,x_1x_2,\ x_2^2)$. Then:

$$ \begin{aligned} \phi(\mathbf{x})\cdot\phi(\mathbf{z}) &= x_1^2z_1^2 + 2x_1x_2z_1z_2 + x_2^2z_2^2 \\ &= (x_1z_1 + x_2z_2)^2 = (\mathbf{x}\cdot\mathbf{z})^2 \end{aligned} $$

In words: the dot product in the 3-D space equals the square of the ordinary 2-D dot product. For $\mathbf{x} = (1, 2)$ and $\mathbf{z} = (3, 1)$: $\mathbf{x}\cdot\mathbf{z} = 5$, so both sides equal 25. We never had to build the 3-D points. The “rbf” kernel below does the same for a lift with infinitely many dimensions.

an SVM with the rbf kernel in scikit-learn

from sklearn.svm import SVC

# X_train, y_train: your data (normalize the features first)
model = SVC(kernel="rbf")     # "rbf" kernel: a curved boundary through the kernel trick
model.fit(X_train, y_train)
Check yourself After training an SVM, you delete one training point that is far from the street. Does the boundary change? What if you delete a support vector? Reveal

Deleting a far point changes nothing. It never limited the width of the street, so the widest street stays the same. Deleting a support vector usually does change the boundary. That point was holding an edge of the street in place. Without it, the street can become wider and may shift or turn. This is why a trained SVM only needs to keep its support vectors. It is also why its prediction cost grows with the number of support vectors, not with the size of the whole training set.

5When to use what

Model Strength Weakness When to use it
k-Nearest Neighbors Simple, no training step, can follow any boundary shape Slow predictions on large data; needs feature scaling; weak in high dimensions Quick baseline on small, low-dimensional datasets
Decision tree Interpretable; no feature scaling needed; handles numeric and categorical features (some libraries, such as scikit-learn, need categories encoded as numbers first) Overfits easily; unstable (small data changes → different tree) When you (or a regulator) need to read the exact rule
Random forest (bagging) Much more stable and accurate than a single tree; resists overfitting Less interpretable; slower and larger than one tree Strong, low-effort default for tabular data
Gradient boosting Often the most accurate classical model on tabular data More hyperparameters to tune; trains sequentially (slower to fit); can overfit if trained too long Getting the best possible accuracy on structured data
SVM Strong with a clear margin; kernel trick handles curved boundaries; works with few samples relative to features Training does not scale well to huge datasets; needs feature scaling Small-to-medium datasets, especially with a clear margin (possibly after a kernel)
Check yourself You have 50,000 rows of customer data with 30 mixed numeric features, and you want good accuracy with little tuning. Which model from the table do you try first, and why not kNN? Reveal

A random forest is a good first try. It is a strong default for tabular data, needs no feature scaling, and has few settings that matter. Gradient boosting may then add some accuracy with more tuning. kNN would need careful feature scaling. With 30 features and 50,000 rows, its predictions are also slow and its distances less meaningful.

6What to carry forward

  • kNN predicts by majority vote among the closest stored examples. It has no real training step and needs scaled features.
  • Decision trees are readable yes/no flowcharts, chosen with a measure such as Gini impurity. On their own they overfit easily.
  • Ensembles fix that. Bagging and random forests average many trees, and randomness keeps the trees different so their errors partly cancel. Boosting adds models that each correct the ensemble’s current errors.
  • SVMs find the boundary with the widest margin, $2/\lVert\mathbf{w}\rVert$. The kernel trick makes that boundary curved by working with dot products in a lifted space.
  • A few intuitions (closeness, splitting, voting, margins) take you a long way in practice.
