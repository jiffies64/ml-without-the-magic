Convolutional Networks

A convolution is a dot product that slides across an image. When you see it that way, you can derive the shape of every layer in a CNN by hand.

30 min read
You'll learn

  • output-shape math
  • pooling
  • ResNets & skip connections

Every image is a grid of numbers. So in principle you could feed it into the fully-connected layers from Section 1: flatten the grid into one long vector and multiply by a big matrix. In practice this is a bad idea. The reasons why are the same reasons convolutional networks exist. Once you see why fully-connected layers struggle with images, the convolution stops looking like a new trick. It becomes the obvious fix.

◆ The one idea to hold onto

A convolution takes one small, reusable pattern detector (a kernel). It slides the kernel over every position in the input and asks the same question everywhere: “how much of my pattern is here?” Because the same detector is used everywhere, CNNs need few parameters, and they find a cat wherever it appears in the photo.

1Why fully-connected layers struggle with images

Intuition first

A fully-connected layer gives every input pixel its own private weight, for every output neuron. This has two bad results for images. First, images have many pixels, so the weight matrix becomes enormous. Second, and less obvious: the layer does not know that “a cat's ear near the top of the photo” and “a cat's ear near the bottom” are the same feature. The two ears land on different input slots with different weights. So the layer learns them as two unrelated facts.

☂ Everyday parallel

Imagine you teach someone to spot a stop sign with one photo. You say: “the stop sign is the red octagon in the upper-left corner of this exact photo.” Now show them a second photo where the sign is in the bottom-right. They are lost. They never learned “stop sign.” They learned “red shape at one pixel location.” A fully-connected layer learns in the same way. It has a separate weight for each position. Nothing makes it reuse what it learned about a shape at one place when the shape appears at another.

Now the math

Take a small color image: 224×224 pixels with 3 color channels (red, green, blue). Flattened into a vector, that is:

$$ 224 \times 224 \times 3 = 150{,}528 \text{ numbers} $$

In words: one image is already a vector with over 150,000 entries. Connect it to a hidden layer of only 1,000 neurons. The weight matrix $\mathbf{W}$ then has shape (1,000 × 150,528), which is over 150 million numbers to learn. That is for one layer, before the network has seen a single example. And each of those weights is tied to one exact pixel position.

Convolution fixes both problems with one move. A fully-connected layer uses a giant matrix that touches every pixel once. A convolution uses a tiny matrix (the kernel) that touches every pixel many times, once per position it slides to. The next section makes that precise.

Check yourself A fully-connected layer from a 64×64 grayscale image to 500 neurons: how many weights does it have? What happens to that number if the image becomes 128×128? Reveal

$64 \times 64 \times 500 = 2{,}048{,}000$ weights (plus 500 biases). Doubling the width and height gives four times as many pixels, so the count grows four times, to 8,192,000. The size of a fully-connected layer grows with the image. Each of those weights also belongs to one fixed pixel. So a pattern learned at one place teaches the layer nothing about the same pattern at another place. A convolution, as you will see next, has the same number of weights for any image size.

2Convolution: a sliding dot product

Intuition first

A kernel (also called a filter) is a small grid of numbers, for example 3×3. To apply it, place it in the top-left corner of the input. Multiply it element by element with the patch of input under it, and add up the products into one number. That is a dot product (Section 1), computed on a 2D patch instead of a flat list. Then slide the kernel one step and repeat, until you have covered the whole input. The result is a new grid with one number per position. Each number tells you how strongly the pattern showed up there.

☂ Everyday parallel

Imagine you search a page by sliding a small stencil over it. At each position you check how well the stencil's shape lines up with the drawing under it. Move the stencil one step right and check again. At the end of the row, move down and do the next row. You never redraw the stencil. It is the same small shape at every spot, and at each spot you ask “does this pattern match here?”

Now the math

Three numbers control how a convolution slides:

Definitions

The kernel size $K$ is the width (and height) of the small grid of weights. The stride $S$ is how many pixels the kernel moves between positions (stride 1 checks every position; stride 2 skips every other one). Padding $P$ is a border of zeros added around the input. It lets the kernel center itself near the edges, and it controls how much the output shrinks.

First, the operation itself. Write the input as $x[c, r, s]$: channel $c$, row $r$, column $s$. (Channels are the separate grids of an image, such as red, green and blue; more on them below.) The kernel has weights $w[c, u, v]$ for every input channel $c$ and every offset $u, v$ from $0$ to $K-1$, plus one bias $b$. The output at row $i$, column $j$ is:

$$ \begin{aligned} y[i, j] &= \sum_{c} \sum_{u} \sum_{v} w[c, u, v] \\ &\qquad \times x[c,\, iS{+}u,\, jS{+}v] \;+\; b \end{aligned} $$

In words: the sums run over every input channel $c$ (from 1 to $C_{\text{in}}$) and every offset $u$ and $v$ (from 0 to $K-1$). Put the kernel's top-left corner at input row $iS$ and column $jS$. Multiply each kernel weight by the input value under it, in every channel. Add all $C_{\text{in}} K^2$ products and the bias. The same $w$ and $b$ are used for every output position $(i, j)$; only the patch of $x$ changes. (Here $x$ is the input after padding.)

▲ Watch out

In mathematics, a “convolution” flips the kernel before sliding it ($x[i-u]$ instead of $x[i+u]$). The formula above does not flip. Its proper name is cross-correlation. Deep learning libraries, including PyTorch's nn.Conv2d, compute cross-correlation and call it convolution. For learning this makes no difference: the network learns the weights, so a flipped kernel is still a kernel.

Now let's derive the size of the output grid for an input of width $W$. (Assume a square input and kernel; the same formula gives the height.) Padding adds $P$ zeros on each side, so the padded width is $W + 2P$. The kernel's left edge can start at position 0, then $S$, then $2S$, and so on. The last start is the largest one where the kernel still fits inside the padded input:

$$ \begin{aligned} \text{start} + K &\le W + 2P \\ \text{start} &\le W + 2P - K \end{aligned} $$

In words: the kernel's start position plus its width $K$ cannot run past the padded edge. That limits how far right the kernel can start.

The start positions are $0, S, 2S, \dots$ up to that limit. The number of start positions is the output size. It is the limit divided by the stride, rounded down, plus one for the start at 0:

$$ \text{out} = \left\lfloor \frac{W - K + 2P}{S} \right\rfloor + 1 $$

In words: take the input width, subtract the kernel width, add twice the padding, and divide by the stride. Round down ($\lfloor\cdot\rfloor$ means “round down”, because a position cannot be a fraction). Then add 1 to count the first position. This one formula gives the output shape of any convolution before you run it.

worked example

An input of width $W = 7$, kernel $K = 3$, stride $S = 2$, no padding ($P = 0$), as in Figure 16.1:

$$ \text{out} = \left\lfloor \frac{7 - 3 + 0}{2} \right\rfloor + 1 = \lfloor 2 \rfloor + 1 = 3 $$

In words: the kernel fits at start positions 0, 2 and 4. It covers pixels 0–2, 2–4 and 4–6. That is three positions and three output values, as the formula says.

A second, very common case keeps the output the same size as the input (“same” padding). Take $W = 5$, $K = 3$, $S = 1$, $P = 1$:

$$ \text{out} = \left\lfloor \frac{5 - 3 + 2}{1} \right\rfloor + 1 = 4 + 1 = 5 $$

In words: a 3-wide kernel would shrink the output by 2 pixels. Padding of 1 on each side adds those 2 pixels back, so the output stays 5×5. This is why “kernel 3, padding 1” appears together so often in real architectures.

Channels, feature maps, and parameter sharing

A color image does not have one grid of numbers. It has three (red, green, blue), called channels. So a kernel for this input is not 3×3 but 3×3×3. It spans the full depth of the input, and the sum over $c$ in the formula above adds up all three channels at once. One kernel produces one output grid, called a feature map: a map of how strongly the pattern fired at every position. A convolutional layer normally learns many kernels in parallel, say 64. They produce 64 stacked feature maps, and these become the 64 input channels of the next layer.

◆ Parameter sharing

The key trick: the same kernel weights are used at every position in the image. This one choice gives two things.

First, translation equivariance. Shift the input image, and the feature map shifts by the same amount; its values do not change. A pattern the kernel learned in one corner is found anywhere else, because the same weights do the checking. (Equivariance means “the output moves with the input.” Invariance means “the output does not change at all.” Convolution gives equivariance. Pooling, in the next section, adds a small amount of invariance.)

Second, far fewer parameters. A 3×3 kernel over 3 input channels, with 64 output feature maps, needs $3\times3\times3\times64 = 1{,}728$ weights. That is true whether the image is 32×32 or 3200×3200. The fully-connected layer at the start of this lesson needed over 150 million weights. That is about 87,000 times more, or roughly five orders of magnitude.

The same thing in PyTorch

nn.Conv2d, the shape formula, and the sum by hand

import torch
import torch.nn as nn
import torch.nn.functional as F

torch.manual_seed(0)
# batch of 8 RGB images, 32x32 pixels: shape (batch, channels, height, width)
x = torch.randn(8, 3, 32, 32)

conv = nn.Conv2d(in_channels=3, out_channels=16, kernel_size=3, stride=1, padding=1)
y = conv(x)
print(y.shape)  # torch.Size([8, 16, 32, 32])
# height/width: floor((32 - 3 + 2*1)/1) + 1 = 32  -> "same" padding, confirmed
# channels: 16, one feature map per learned kernel

print(conv.weight.shape)  # torch.Size([16, 3, 3, 3]) -> (out_ch, in_ch, K, K)
print(sum(p.numel() for p in conv.parameters()))  # 16*3*3*3 + 16 bias = 448

# the triple sum y[i,j] = sum_c sum_u sum_v w[c,u,v] * x[c, i+u, j+v] + b, by hand
with torch.no_grad():
    xp = F.pad(x[0], (1, 1, 1, 1))              # image 0, padded with P = 1
    i, j = 5, 7                                 # any output position (S = 1)
    by_hand = (conv.weight[0] * xp[:, i:i+3, j:j+3]).sum() + conv.bias[0]
    print(torch.allclose(by_hand, y[0, 0, i, j]))  # True

# a downsampling conv: stride 2, no padding
down = nn.Conv2d(3, 16, kernel_size=3, stride=2, padding=0)
print(down(x).shape)  # torch.Size([8, 16, 15, 15])
# floor((32 - 3 + 0)/2) + 1 = floor(29/2) + 1 = 14 + 1 = 15
Check yourself An input feature map is 28×28 with 8 channels. You apply a convolution with kernel size 5, stride 1, padding 2, and 32 output channels. Predict the output shape and the number of weights (without biases). Reveal

Output size: $\lfloor (28 - 5 + 4)/1 \rfloor + 1 = 28$. Padding 2 with a 5-wide kernel is again “same” padding, so the output is 32 maps of 28×28. Each kernel spans all 8 input channels, so it has $5 \times 5 \times 8 = 200$ weights. There are 32 kernels, so the layer has $200 \times 32 = 6{,}400$ weights (plus 32 biases). This number does not depend on the 28×28 size: that is parameter sharing.

3Pooling: shrinking on purpose

Intuition first

After a few convolutions, you often want to make the feature maps smaller on purpose. There are fewer numbers to carry forward. The network also gets a little tolerance when a pattern moves by a pixel or two. Pooling does this with no learned weights. It slides a small window over the input and keeps one summary number at each position.

☂ Everyday parallel

Think of a weather report for a country. The report does not list the temperature of every street. It gives one number per region. Max pooling reports the highest temperature in each region. It answers “did it get hot anywhere in this region?” Average pooling reports the regional mean. It is a smoother summary. In both cases, a heat spot that moves a little inside its region gives the same report.

Now the math

Pooling uses the same sliding window as convolution, so the same output-size formula applies. Usually the kernel size $K$ and the stride $S$ are equal, so the windows do not overlap. There are no weights. For max pooling, the output at $(i, j)$ in each channel $c$ is:

$$ y[c, i, j] = \max_{0 \le u, v < K} x[c,\, iS{+}u,\, jS{+}v] $$ $$ \text{out} = \left\lfloor \frac{W - K + 2P}{S} \right\rfloor + 1 $$

In words: the same sliding window as the convolution sum, but the window takes the largest value instead of a weighted sum. Each channel is pooled on its own, so the number of channels does not change. Average pooling replaces the max with the mean of the $K^2$ values.

The same thing in PyTorch

2×2 max pooling halves height and width

import torch
import torch.nn as nn

x = torch.randn(8, 16, 32, 32)

pool = nn.MaxPool2d(kernel_size=2, stride=2)
y = pool(x)
print(y.shape)  # torch.Size([8, 16, 16, 16])
# floor((32 - 2 + 0)/2) + 1 = 15 + 1 = 16, applied to height and width
Check yourself A 2×2 max pool with stride 2 sees a strong activation at column 0 of a window. The feature map shifts one pixel to the right. Does the pooled output stay the same? What if the activation was at column 1? Reveal

At column 0, the shift moves the activation to column 1, which is still inside the same window (columns 0–1). The window reports the same maximum, so the output often stays the same. At column 1, the shift moves it to column 2, which is in the next window. Now the output changes. So max pooling gives tolerance to some one-pixel shifts, not to all of them. The invariance is partial. A fully-connected layer has no such tolerance at all: any shift changes which weights multiply which values.

4ResNets and skip connections

Intuition first

With convolutions in hand, the next idea was to stack many more of them. A deeper network should never be worse: its extra layers could copy the input through unchanged if they did not help. But in practice, plain stacks of convolutions became harder to train past a certain depth. This was not overfitting. Even the training accuracy got worse. He et al. (2015), who introduced ResNets, called this the degradation problem.

What caused it? Their networks used batch normalization, which keeps gradients at a healthy size. So the authors argued that vanishing gradients (Section 12) were probably not the main cause. The problem was optimization. A stack of plain layers finds it hard to learn even the identity function (“output = input”). So the extra layers could not learn to “do nothing”, and they made things worse instead.

☂ Everyday parallel

Imagine you edit a good essay with a team. The plain way: each editor must rewrite the whole essay from memory. Even if an editor has nothing to add, they must reproduce every sentence perfectly, and small errors pile up. The residual way: each editor gets the essay and writes only corrections in the margin. An editor with nothing to add writes nothing, and the essay passes on unchanged. A residual block works like the second editor: it learns a correction $F(\mathbf{x})$ that is added to the input.

Now the math

A plain layer computes some function of its input, $F(\mathbf{x})$, and passes only that forward. A residual block computes:

$$ \mathbf{y} = \mathbf{x} + F(\mathbf{x}) $$

In words: $F(\mathbf{x})$ (usually two convolutions) is still computed and used. But it is added to the input $\mathbf{x}$ instead of replacing it. To “do nothing”, the block only needs $F(\mathbf{x}) \approx 0$. That is easy: set the weights near zero. A plain layer would have to learn the identity map exactly, which is much harder.

The skip path also helps the backward pass. By the chain rule (Section 10), the derivative of the output with respect to the input is:

$$ \frac{\partial \mathbf{y}}{\partial \mathbf{x}} = \frac{\partial \mathbf{x}}{\partial \mathbf{x}} + \frac{\partial F(\mathbf{x})}{\partial \mathbf{x}} = I + \frac{\partial F}{\partial \mathbf{x}} $$

In words: the gradient splits into two paths that add up. One is the identity path ($I$, the identity matrix: the derivative of $\mathbf{x}$ with respect to itself). The other is whatever the convolutions inside $F$ contribute. Stack many residual blocks, and the gradient through the stack is a product of factors like $(I + \partial F/\partial \mathbf{x})$. Even if every $\partial F/\partial \mathbf{x}$ is tiny, each factor stays close to $I$ instead of shrinking toward zero. So the gradient reaches the early layers largely intact. This is the same shrink-or-explode story as the repeated matrix products in Section 1 and the recurrent networks in Section 17. The skip connection fixes it through the structure of the network, not through careful tuning.

The same thing in PyTorch

a minimal residual block

import torch
import torch.nn as nn

class ResidualBlock(nn.Module):
    def __init__(self, channels):
        super().__init__()
        self.conv1 = nn.Conv2d(channels, channels, kernel_size=3, padding=1)
        self.conv2 = nn.Conv2d(channels, channels, kernel_size=3, padding=1)
        self.relu = nn.ReLU()

    def forward(self, x):
        out = self.relu(self.conv1(x))
        out = self.conv2(out)          # out is F(x)
        return self.relu(x + out)      # skip connection, then ReLU: ReLU(x + F(x))

block = ResidualBlock(channels=16)
x = torch.randn(8, 16, 32, 32)
y = block(x)
print(y.shape)  # torch.Size([8, 16, 32, 32]) -> padding=1, kernel=3 keeps size unchanged

In words: this is the original 2015 ResNet block. It applies a ReLU after the addition, so it computes $\text{ReLU}(\mathbf{x} + F(\mathbf{x}))$, not exactly $\mathbf{x} + F(\mathbf{x})$. A later version (He et al., 2016, “pre-activation” ResNets) moves the ReLUs inside $F$ and drops the last one. Then the skip path is a pure identity.

Check yourself In the block above, training has pushed F's weights and biases to nearly zero. What does the block output for an input value of 2.0? For −2.0? What is the gradient through the skip path? Reveal

With $F(\mathbf{x}) \approx 0$, the block outputs $\text{ReLU}(\mathbf{x})$. So 2.0 comes out as 2.0: the block passes it through unchanged. But −2.0 comes out as 0, because of the final ReLU. The block is an exact identity only for values that are not negative. (The pre-activation version, with no ReLU after the add, is an identity for every value.) Through the addition itself, the gradient is $I + \partial F/\partial \mathbf{x} \approx I$. Where the final ReLU is active, the gradient passes at full strength. This is why very deep ResNets train. A block that has not learned anything useful yet mostly passes its input on. It does not damage the signal.

5What to carry forward

  • Fully-connected layers give images too many parameters and no reuse of patterns across positions. Convolution fixes both.
  • A convolution slides a small kernel over the input and computes a dot product (summed over all input channels) at each position. The output size is $\lfloor (W-K+2P)/S \rfloor + 1$. Derive it; do not memorize it.
  • Parameter sharing (the same kernel used everywhere) gives translation equivariance and cuts the parameter count by orders of magnitude compared with a fully-connected layer.
  • Pooling shrinks feature maps with no learned weights, uses the same sliding-window formula, and adds a little shift invariance.
  • Skip connections ($\mathbf{y} = \mathbf{x} + F(\mathbf{x})$) make “do nothing” easy to learn and give gradients an identity path, so very deep networks train.

Convolutions assume a grid with local structure. That is great for images. Text and audio have a different structure: order along a single sequence. Next we will see how networks handle that.
