Neurons, Layers, Activations

A neuron is a weighted vote passed through a switch. Without that switch, extra layers add nothing.

42 min read
You'll learn
  • the artificial neuron
  • layers as matrices
  • activation functions
  • why nonlinearity is essential

Everything you have built so far (vectors, matrices, dot products) prepares you for one small object: the neuron. A neuron takes a few numbers, weighs them, adds them up, and passes the result through a small switch. Connect a few thousand of these and you have a neural network. In this section we build the neuron and stack neurons into layers. Then we prove a key fact about them: the switch is necessary. Remove it, and a hundred layers collapse into one.

◆ The one idea to hold onto

One neuron computes $\phi(\mathbf{w}^\top\mathbf{x} + b)$: a weighted sum passed through a nonlinear switch $\phi$. A layer runs many neurons at once, and that is one matrix multiply. The switch (the activation) is the only thing that makes extra layers add power. The rest of this section explains why.

1The artificial neuron: a weighted vote through a switch

Intuition first

A neuron makes one small decision. It looks at several input numbers and decides how much each one matters. It adds up this weighted evidence. Then it passes the total through a switch that decides how strongly to “fire.” A big total gives a strong output. A small or negative total gives a weak or zero output. No single neuron is clever. The power of a network comes from connecting many simple neurons.

☂ Everyday parallel

Think about how you decide to go for a walk. The weather matters a lot to you (a big weight). Your plans for the day matter somewhat (a medium weight). Your energy level matters a little (a small weight). You add up the weighted evidence. The more the total favors a walk, the more likely you are to go. A neuron does the same thing: it weighs the factors, sums them, and turns the total into an output. The activation decides how the total becomes a decision: gradually (sigmoid) or with a hard floor at zero (ReLU).

Now the math

Write the inputs as a vector $\mathbf{x} \in \mathbb{R}^{n}$ (a list of $n$ numbers). Give the neuron a matching list of weights $\mathbf{w} \in \mathbb{R}^{n}$ and one extra number $b$, the bias. Call the activation function $\phi$ (the Greek letter phi). The neuron computes:

$$ y = \phi\!\left( \mathbf{w}^\top\mathbf{x} + b \right) = \phi\!\left( \sum_{i=1}^{n} w_i x_i + b \right) $$

In words: the piece $\mathbf{w}^\top\mathbf{x}$ is the dot product from Section 1. Multiply each input by its weight and add the results. This gives one number (“how much do I care, in total?”). Add the bias $b$ to shift that number up or down. Finally, pass the result through the activation $\phi$ to get the neuron's output $y$.

Definition

A weight $w_i$ says how much input $x_i$ matters, and in which direction. A large positive weight means “this input pushes the output up.” A negative weight means “this input pushes it down.” The bias $b$ is one constant, added once to the weighted sum. It sets the neuron's default lean: how big the weighted sum must be before the neuron starts to fire. The activation $\phi$ is a fixed nonlinear function applied to that sum.

The number before the activation, $z = \mathbf{w}^\top\mathbf{x} + b$, appears so often that it has a name: the pre-activation. (Some texts call it the logit when it is the final score before a probability.) Keep the two apart: $z$ is the weighted vote, and $y = \phi(z)$ is the vote after the switch.

The same thing in PyTorch

one neuron by hand

import torch

x = torch.tensor([0.6, -1.2, 2.0])     # three inputs
w = torch.tensor([1.5,  0.3, -0.8])    # a weight per input
b = torch.tensor(0.1)                  # one bias

z = torch.dot(w, x) + b                # pre-activation: the weighted vote
y = torch.relu(z)                      # pass it through the switch (ReLU)

print(z)     # tensor(-0.9600)   0.6*1.5 + (-1.2)*0.3 + 2.0*(-0.8) + 0.1
print(y)     # tensor(0.)        negative vote -> neuron stays silent
Check yourself In the code above, which single number would you change, and to what, so that the neuron outputs exactly 0.5? Reveal

The easiest choice is the bias. The weighted sum without bias is $0.9 - 0.36 - 1.6 = -1.06$. For ReLU to output 0.5 you need $z = 0.5$, so $b = 0.5 + 1.06 = 1.56$. This shows the job of the bias: it moves the whole weighted sum up or down, without looking at the inputs. (Changing $w_3$ from $-0.8$ to $-0.07$ also works.)

2Layers: many neurons at once is one matrix multiply

Intuition first

One neuron gives you one number. Usually you want many. One neuron might ask “does this look like a wheel?”, another “does this look like a window?”, another “is there fur?”. A layer is a row of neurons. They all look at the same input at the same time. Each has its own weights and bias, and each produces its own number. Their outputs stack into a new vector, which becomes the input to the next layer.

☂ Everyday parallel

A panel of reviewers reads a loan application. One reviewer cares mostly about income, another about credit history, another about existing debt. They all read the same application, but they weigh it differently, and each writes down a score. The list of scores tells you more than any single opinion. A layer is that panel: the same input for everyone, different weights for each member, and a vector of scores out.

Now the math

Stacking neurons needs no new tools. It is the matrix–vector multiply from Section 1. Put each neuron's weight vector as a row of a matrix $\mathbf{W}$. Collect the biases into a vector $\mathbf{b}$. Then one line computes the whole layer:

$$ \mathbf{h} = \phi\!\left( \mathbf{W}\mathbf{x} + \mathbf{b} \right) $$

In words: row $i$ of $\mathbf{W}$ holds the weights of neuron $i$. So $\mathbf{W}\mathbf{x}$ computes every neuron's weighted vote in one multiply (one dot product per row). Add the bias vector and apply $\phi$ to every entry. The result is $\mathbf{h}$, the layer's output vector, with one number per neuron.

The shapes tell the whole story, so let's state them. Suppose the input has $n$ features and the layer has $m$ neurons:

$$ \underbrace{\mathbf{W}}_{m \times n}\; \underbrace{\mathbf{x}}_{n \times 1} \;+\; \underbrace{\mathbf{b}}_{m \times 1} \;=\; \underbrace{\mathbf{z}}_{m \times 1} $$

In words: $\mathbf{W}$ has one row per neuron ($m$ rows) and one column per input feature ($n$ columns). By the shape rule (inner numbers match, outer numbers stay), an $(m\times n)$ matrix times an $(n\times 1)$ vector gives an $(m\times 1)$ vector. So a layer maps $n$ numbers in to $m$ numbers out. You choose $m$ when you design the network.

In practice you rarely send one example at a time. You send a batch (a group of examples processed together for speed). Stack $N$ input vectors as the rows of a matrix $\mathbf{X}$ of shape $(N \times n)$. The layer becomes:

$$ \mathbf{H} = \phi(\mathbf{X}\mathbf{W}^\top + \mathbf{b}) $$

In words: each row of $\mathbf{X}$ is one example. Multiplying by $\mathbf{W}^\top$ gives an $(N \times m)$ matrix, one row of answers per example. The bias $\mathbf{b}$ has shape $(m,)$, so PyTorch adds it to every row. This automatic copying is called broadcasting; Section 13 explains it in detail.

This row-of-examples convention is why PyTorch's nn.Linear stores its weight with shape $(m \times n)$ and multiplies by $\mathbf{W}^\top$ inside its forward pass.

Check yourself A layer takes a 784-number image vector and has 128 neurons. What are the shapes of $\mathbf{W}$, $\mathbf{b}$ and $\mathbf{h}$? How many parameters does the layer have? Reveal

The layer maps $n = 784$ inputs to $m = 128$ neurons. So $\mathbf{W}$ is (128, 784): one row per neuron, one column per input feature. The bias $\mathbf{b}$ is (128,), one per neuron. The output $\mathbf{h}$ is (128,). The parameter count is $128 \times 784 + 128 = 100{,}480$. Almost all of them are weights. This is the size of the first hidden layer of a small image classifier.

3Activation functions: the shape of the switch

Intuition first

The activation is the switch that each neuron's weighted vote passes through. Different switches behave differently. Some are soft and gradual. Some block negative values completely. Some let large values through unchanged. The choice decides two things. First, the range of values the output can take. Second, and important for learning, how the gradient behaves. (The gradient is the slope that tells training which way to change the weights. Section 10 computes it.) Where a switch's slope is flat, learning cannot pass through it.

☂ Everyday parallel

Think of a light dimmer with a knob. Near the middle, a small turn changes the brightness a lot. Near the two ends the knob still turns, but the light hardly changes. That is sigmoid and tanh: at both ends, turning the input changes the output very little. In math words, the slope is nearly zero. ReLU is a different kind of dimmer. Below zero the light is off, and turning the knob does nothing (slope 0). Above zero, each turn adds the same amount of light (slope 1). How much the light responds to a turn of the knob is the gradient.

Now the math

The sigmoid $\sigma$ squashes any number into the range (0, 1). This is useful when you want an output you can read as a probability:

$$ \sigma(z) = \frac{1}{1 + e^{-z}} \qquad \text{range } (0, 1) $$

In words: a large positive $z$ gives an output near 1. A large negative $z$ gives an output near 0. And $z = 0$ gives exactly 0.5. The problem: at both ends the curve becomes flat, so its slope (the gradient) shrinks to nearly zero. This is called saturation, and it slows learning.

The tanh is a rescaled sigmoid, centered on zero, with range (−1, 1):

$$ \tanh(z) = \frac{e^{z} - e^{-z}}{e^{z} + e^{-z}} \qquad \text{range } (-1, 1) $$

In words: the same S-shape as sigmoid, but symmetric around zero. A negative input gives a negative output, so the outputs are centered. This makes tanh a bit easier to train than sigmoid. But it still saturates at both ends.

The ReLU (“rectified linear unit”) is very simple. It keeps the input if it is positive, and outputs zero otherwise.

$$ \text{ReLU}(z) = \max(0, z) \qquad \text{range } [0, \infty) $$

In words: for any positive $z$ the output is $z$ and the slope is 1. The gradient passes through at full strength, so learning does not stall on the positive side. For negative $z$ the output is 0 and the slope is 0 (the neuron is “off”). ReLU needs no costly $e^{z}$ and does not saturate for positive inputs. That is why it became the default activation for hidden layers.

ReLU has one weak point. A neuron whose $z$ is negative for every input has zero gradient everywhere, so it may never recover. This is a dead neuron. Leaky ReLU fixes this: on the negative side it lets a small fraction through instead of a hard zero.

$$ \text{LeakyReLU}(z) = \max(a z,\; z), \qquad a \approx 0.01 \qquad \text{range } (-\infty, \infty) $$

In words: positive inputs behave like ReLU (slope 1). Negative inputs get a small slope $a$ (for example 0.01) instead of 0. So the neuron always keeps a small gradient and can recover. The number $a$ is the “leak.”

Finally, a name you should know: GELU (“Gaussian Error Linear Unit”). It is a smooth version of ReLU that bends gently through zero instead of having a sharp corner. It is the default activation inside transformer models (the architecture behind today's large language models). You do not need its formula yet. Just recognize the name when you see it later.

The same thing in PyTorch

every switch on the same inputs

import torch

z = torch.tensor([-2.0, -0.5, 0.0, 0.5, 2.0])

print(torch.sigmoid(z))                    # tensor([0.1192, 0.3775, 0.5000, 0.6225, 0.8808])
print(torch.tanh(z))                       # tensor([-0.9640, -0.4621,  0.0000,  0.4621,  0.9640])
print(torch.relu(z))                       # tensor([0.0000, 0.0000, 0.0000, 0.5000, 2.0000])
print(torch.nn.functional.leaky_relu(z))   # tensor([-0.0200, -0.0050,  0.0000,  0.5000,  2.0000])
▲ Watch out

Do not use sigmoid or tanh in deep hidden layers by default. They are flat at the ends. When you stack many of them, the gradients shrink layer after layer, and the early layers barely learn. This is the vanishing gradient problem (Section 12). Sigmoid still has a proper place: the final layer of a binary classifier, where you want a probability between 0 and 1. For the hidden layers, start with ReLU.

Check yourself A ReLU neuron has pre-activation $z = -3$. What is its output, and what gradient flows back through it? What would change with Leaky ReLU ($a = 0.01$)? Reveal

With ReLU, the output is $\max(0, -3) = 0$ and the slope is 0. So no gradient flows back on this example, and the neuron's weights learn nothing from it. If $z$ is negative for every example, the neuron is dead. With Leaky ReLU, the output is $0.01 \times (-3) = -0.03$ and the slope is $0.01$. The gradient is small but not zero, so the weights can still change and the neuron can recover.

Check yourself Why can't we use a hard step function (output 1 if $z \gt 0$, else 0) as the activation and train it with gradients? Reveal

The step function is flat everywhere except at $z = 0$, where it jumps. So its slope is 0 at every point where it is defined. Gradient descent multiplies by this slope, so every weight gradient would be zero, and nothing would ever change. Sigmoid is a smooth version of the step: it has the same “off, then on” shape, but its slope is never exactly zero.

4Why nonlinearity is necessary

Intuition first

Here is the claim, and we will prove it. It is the reason activation functions exist. if you stack layers with no activation between them, the whole stack equals a single layer. A hundred plain matrix multiplies in a row have no more power than one. The switch is the only thing that makes depth useful.

☂ Everyday parallel

Place straight rulers end to end in one line, as many as you like. The chain is still one straight line. You never get a curve, no matter how many rulers you add. A linear layer is a straight ruler. To draw a curve you need a bend somewhere, and the activation is the only place where a bend can enter.

Now the math

Take two layers with no activation. The first maps $\mathbf{x}$ to $\mathbf{h}$, and the second maps $\mathbf{h}$ to $\mathbf{y}$:

$$ \mathbf{h} = \mathbf{W}_1\mathbf{x} + \mathbf{b}_1, \qquad \mathbf{y} = \mathbf{W}_2\mathbf{h} + \mathbf{b}_2 $$

Now substitute the first equation into the second and simplify, one step at a time:

$$ \begin{aligned} \mathbf{y} &= \mathbf{W}_2\mathbf{h} + \mathbf{b}_2 \\[2pt] &= \mathbf{W}_2\big(\mathbf{W}_1\mathbf{x} + \mathbf{b}_1\big) + \mathbf{b}_2 &&\text{(plug in } \mathbf{h}\text{)} \\[2pt] &= \mathbf{W}_2\mathbf{W}_1\mathbf{x} + \mathbf{W}_2\mathbf{b}_1 + \mathbf{b}_2 &&\text{(multiply out)} \\[2pt] &= \underbrace{\big(\mathbf{W}_2\mathbf{W}_1\big)}_{\mathbf{W}'}\mathbf{x} + \underbrace{\big(\mathbf{W}_2\mathbf{b}_1 + \mathbf{b}_2\big)}_{\mathbf{b}'} &&\text{(group the constants)} \\[2pt] &= \mathbf{W}'\mathbf{x} + \mathbf{b}' \end{aligned} $$

In words: the two weight matrices multiply into one new matrix $\mathbf{W}' = \mathbf{W}_2\mathbf{W}_1$. The two biases combine into one new bias $\mathbf{b}' = \mathbf{W}_2\mathbf{b}_1 + \mathbf{b}_2$. The result, $\mathbf{y} = \mathbf{W}'\mathbf{x} + \mathbf{b}'$, is a single linear layer. The two-layer network and this one-layer network compute the same function.

◆ The punchline

Nothing in that derivation depends on the number two. Chain 100 layers without activations, and the same collapse happens 99 times. The product $\mathbf{W}_{100}\cdots\mathbf{W}_1$ is some single matrix $\mathbf{W}'$, and all the biases combine into one $\mathbf{b}'$. So a 100-layer linear network is exactly as expressive as one layer. It can only draw straight lines (in more dimensions, flat planes). The extra parameters add nothing. The activation breaks the collapse. The expression $\phi(\mathbf{W}_2\,\phi(\mathbf{W}_1\mathbf{x}))$ cannot be rewritten as one matrix times $\mathbf{x}$, so each real layer adds new power.

So what can a network do once the nonlinearity is back? A lot. The universal approximation theorem says the following. Take a network with one hidden layer, a nonlinear activation (such as ReLU or sigmoid), and enough neurons. It can approximate any continuous function on a bounded range of inputs, as closely as you want. “Continuous” means the function has no sudden jumps; it does not need to be smooth. “Bounded range” means a limited region, for example every input between −10 and 10. We will not prove this here. The idea: each neuron contributes one bend, and enough bends, placed well, can follow any curve. The theorem says nothing about how many neurons you need, or whether training will find the right weights. And without the activation, the theorem does not apply at all.

The same thing in PyTorch

watch two linear layers collapse into one

import torch
torch.manual_seed(0)

W1 = torch.randn(4, 3); b1 = torch.randn(4)
W2 = torch.randn(2, 4); b2 = torch.randn(2)
x  = torch.randn(3)

# two "layers" with NO activation between them
y_two = W2 @ (W1 @ x + b1) + b2

# the single equivalent layer, built from the proof
W_eq = W2 @ W1                 # (2x4)(4x3) -> (2x3)
b_eq = W2 @ b1 + b2            # combined bias
y_one = W_eq @ x + b_eq

print(torch.allclose(y_two, y_one))   # True  -> same function, one layer
Check yourself A colleague builds a 10-layer network but forgets the activation functions. The loss drops a little, then stops improving, and the model does no better than linear regression. Why? And what happens if you add ReLU only after layer 5? Reveal

Without activations, the ten layers collapse into one linear map $\mathbf{W}'\mathbf{x} + \mathbf{b}'$ (see the proof above). The model is a linear model, so it cannot beat one. It stops where a straight-line fit stops. With ReLU after layer 5 only, layers 1–5 collapse into one linear layer, and layers 6–10 collapse into another. So you get a network with one hidden layer: nonlinear, but still much less than ten real layers. The fix is an activation after every hidden layer.

5A real layer in PyTorch

Intuition first

You now have every piece: weights, bias, matrix multiply, activation. PyTorch combines the weighted sum and the bias in nn.Linear. It keeps the activation separate, so you combine the two yourself. Let's send a batch through one hidden layer with ReLU and follow the shapes. If the shapes are right, the wiring is right.

☂ Everyday parallel

Think of a two-station assembly line. Station one (Linear) takes each part and combines its measurements into a rough result. Station two (ReLU) is a quality check: it sets every value below zero to zero and passes the rest unchanged. The same two stations process every item on the belt (every example in the batch).

The same thing in PyTorch

a hidden layer's forward pass, with shapes

import torch
import torch.nn as nn

batch_size, in_features, out_features = 32, 784, 128

layer = nn.Linear(in_features, out_features)   # holds W (128x784) and b (128,)
relu  = nn.ReLU()

x = torch.randn(batch_size, in_features)       # a batch: 32 examples of 784 numbers
print("input :", x.shape)                      # torch.Size([32, 784])

z = layer(x)                                   # weighted sum + bias:  x @ W.T + b
print("linear:", z.shape)                      # torch.Size([32, 128])

h = relu(z)                                    # apply the switch to every entry
print("relu  :", h.shape)                      # torch.Size([32, 128])

# check that the activation removed the negatives:
print("min after relu:", h.min().item())       # 0.0  -> nothing negative remains

In words: the batch goes in with shape $(32, 784)$. Linear turns each 784-number example into 128 numbers, which gives $(32, 128)$. ReLU keeps that shape and sets every negative entry to zero. Each row is one example. The batch dimension (32) passes through unchanged.

▲ Watch out

The in_features of nn.Linear must equal the last dimension of its input. The next layer's in_features must equal this layer's out_features. If they do not match, PyTorch raises a shape error when you call the layer. When a network does not run, print the shape after every layer. The error is where two numbers that should be equal are different.

Check yourself You add a second layer nn.Linear(784, 10) after the ReLU above and call it on h. What happens, and what is the fix? Reveal

PyTorch raises a shape error. The tensor h has shape (32, 128), so its last dimension is 128, but the new layer expects 784 input features. The fix is nn.Linear(128, 10): its in_features must equal the previous layer's out_features. The output then has shape (32, 10).

6What to carry forward

  • A neuron computes $\phi(\mathbf{w}^\top\mathbf{x} + b)$: a weighted vote (weights say how much each input matters) plus a bias (the default lean), passed through a nonlinear switch $\phi$.
  • A layer runs many neurons at once with one matrix multiply: $\mathbf{h} = \phi(\mathbf{W}\mathbf{x} + \mathbf{b})$. It maps $n$ inputs to $m$ outputs, and $\mathbf{W}$ has shape $(m, n)$.
  • Activations differ in output range and gradient behavior. ReLU ($\max(0,z)$) is the default for hidden layers: cheap, and it does not saturate for positive inputs. Sigmoid and tanh saturate. Leaky ReLU avoids dead neurons. GELU is the transformer default.
  • The proof: stacked linear layers with no activation collapse to one layer, $\mathbf{W}'\mathbf{x} + \mathbf{b}'$. Nonlinearity makes depth useful. With it, a network with one hidden layer can approximate any continuous function on a bounded input range.

We now have a network that can compute a forward pass. But its weights are random, so its answers are nonsense. Next we learn how to correct those weights: how the gradient flows back through every neuron and every activation to train the whole stack at once. That is backpropagation, and it is where the network starts to learn.
