Overfitting & Regularization

A model that scores 100% on its training data has not yet shown you anything. This section is about the number that counts, measured on data the model has never seen, and how to protect it.

38 min read
You'll learn
  • generalization
  • bias–variance
  • L1/L2 regularization
  • train/val/test
  • cross-validation

You can make almost any model fit its training data very closely. That part is easy, and it tells you little. What we care about is whether the model works on new data: tomorrow’s customer, the next photo, a sentence it has not read. This section is about the gap between those two, why it opens, and the tools that close it.

◆ The one idea to hold onto

The score that matters is performance on data the model never saw during training. Every idea below (splitting your data, cross-validation, regularization) exists to keep that one number trustworthy.

1Generalization: doing well on data you haven't seen

Intuition first

Generalization is a model’s ability to perform well on new examples, not only on the ones it trained on. A model that generalizes has learned the real pattern in the data. A model that does not has memorized the specific examples, including their noise and accidents.

☂ Everyday parallel

Two students prepare for a history exam. One memorizes last year’s exam paper word for word. The other understands the period: causes, results, and how events connect. Give both students last year’s paper, and the memorizer wins easily. Give them this year’s paper, which asks about the same material in new ways, and the memorizer fails. The memorizer overfit to one paper. The other student generalized to the subject.

Definition

Overfitting is when a model fits the training data too closely, including its noise. Training error keeps going down while error on new data gets worse. Underfitting is the opposite. The model is too simple to capture even the real pattern, so it does poorly on both training data and new data. Model capacity is a rough measure of how flexible a model is: how complicated a pattern it can represent. A straight line has low capacity. A deep decision tree with a thousand splits has very high capacity.

Capacity controls both failure modes. If it is too low, the model cannot represent the real pattern, so it underfits. If it is too high, the model has so much freedom that it fits the random noise in your particular training set. Then it overfits. The best capacity is somewhere in between. Most of this section is about finding it.

The same thing in NumPy

fitting the same noisy data with three capacities

import numpy as np

rng = np.random.default_rng(0)
x = np.linspace(-3, 3, 20)
y = 0.5 * x**2 + rng.normal(0, 1, size=x.shape)       # true pattern: a parabola, plus noise

x_test = rng.uniform(-3, 3, size=1000)                 # new points from the same source
y_test = 0.5 * x_test**2 + rng.normal(0, 1, size=x_test.shape)

for degree in (1, 2, 15):
    coeffs = np.polyfit(x, y, degree)
    train_mse = np.mean((np.polyval(coeffs, x) - y) ** 2)
    test_mse = np.mean((np.polyval(coeffs, x_test) - y_test) ** 2)
    print(f"degree {degree:2d}: train MSE {train_mse:.3f}   test MSE {test_mse:.3f}")

output

degree  1: train MSE 3.846   test MSE 2.935
degree  2: train MSE 0.592   test MSE 1.182
degree 15: train MSE 0.139   test MSE 5.758

Read the three rows one at a time.

  • Degree 1 (a line) cannot bend to follow a parabola. Both errors are high: it underfits. (Its test error is a little lower than its training error only by chance: 20 training points are a small sample.)
  • Degree 2 (a parabola) matches the true pattern. Its test error, 1.18, is close to 1.0, the variance of the noise. No model can predict the noise, so no model can do much better on average.
  • Degree 15 has the lowest training error but by far the highest test error. It learned the noise, not the pattern: it overfits.
Check yourself A model reaches 99% accuracy on its training set but only 61% on its validation set. Is this overfitting or underfitting? What is a good first fix? Reveal

This is overfitting. Near-perfect training performance next to much worse performance on unseen data is its typical sign. The model has enough capacity to memorize the training set instead of learning the general pattern. Good first fixes: reduce capacity (a smaller model, fewer tree splits), or add regularization (later in this section). You can also collect more training data, because a bigger set is harder to memorize. Or stop training earlier, before the model starts fitting noise.

2Train / validation / test — and cross-validation

Intuition first

If you measure your model only on the data it trained on, you cannot detect overfitting. The memorizer always looks excellent on the paper it memorized. So we split the data into three separate parts. Each part has a different job, and we never let them mix.

☂ Everyday parallel

Preparing for a real exam has three phases. You do practice questions to learn the material (the training set). You take a practice exam to see how you are doing and to decide what to study again (the validation set). Finally, you take the real exam once (the test set). Its value comes from the fact that you never changed your studying because of it. Suppose you saw the real exam early and kept “improving” based on it. Then your final grade would no longer tell you how well you know the material.

Definition

The training set is what the model learns its numbers from. The validation set is held out during training and used to make decisions: which model, which settings. These settings are called hyperparameters: choices you make before training, such as capacity or the regularization strength below. The test set is used once, at the end, to report a final, unbiased number. If you tune anything based on the test set, it becomes a second validation set, and your reported score is no longer trustworthy.

Now the math

With only one validation split, your estimate of “how good is this model” depends on which examples happened to land in that split. A small, unlucky validation set can make a good model look bad, or the other way around. k-fold cross-validation fixes this. It rotates which part is held out, so every example is used for validation exactly once. Let $s_i$ be the validation score of a model trained on all folds except fold $i$ and evaluated on fold $i$. Then:

$$ \text{CV score} = \frac{1}{k}\sum_{i=1}^{k} s_i $$

In words: split the training data into $k$ folds of equal size (5 and 10 are common choices). Train $k$ separate times, each time leaving out a different fold to validate on. Then average the $k$ validation scores. Every example is validated on exactly once, so the average depends much less on one unlucky split. The spread of the $k$ scores also tells you how stable the estimate is.

The same thing in NumPy

split 10 rows into 5 folds

import numpy as np

X = np.arange(20).reshape(10, 2)          # 10 training examples, 2 features each
k = 5
rng = np.random.default_rng(0)
folds = np.array_split(rng.permutation(len(X)), k)   # shuffle, then cut into k folds

for i in range(k):
    val_idx = folds[i]
    train_idx = np.concatenate([folds[j] for j in range(k) if j != i])
    print(f"fold {i}: train on {len(train_idx)} rows, validate on rows {sorted(val_idx.tolist())}")

output

fold 0: train on 8 rows, validate on rows [4, 6]
fold 1: train on 8 rows, validate on rows [2, 7]
fold 2: train on 8 rows, validate on rows [3, 5]
fold 3: train on 8 rows, validate on rows [0, 9]
fold 4: train on 8 rows, validate on rows [1, 8]

Each of the 10 rows appears in exactly one validation fold. In practice you would use a library for this, for example scikit-learn’s KFold(n_splits=5, shuffle=True), which does the same job.

Check yourself While tuning a model, you check test-set accuracy after every change and keep the version with the best test score. You never train on the test set. What is wrong? Reveal

You did not train on the test set, but you selected based on it, and selecting is a form of fitting. After enough attempts, some version will score well on the test set by luck, because it happens to match that set’s particular noise. Picking “the best on the test set” then has the same effect as tuning on it. The reported number no longer estimates real-world performance. The fix is to do all tuning with the validation set (or cross-validation) and use the test set once, at the end.

3The bias–variance tradeoff

Intuition first

Overfitting and underfitting are two sides of a deeper split. A model’s test error comes from two separate sources, bias and variance. As capacity changes, one goes down while the other goes up.

☂ Everyday parallel

Picture a dartboard. Each dart is one model, trained on a new random sample of data. The bullseye is the true answer. High bias means the darts land in a tight group, but the group is far from the bullseye: consistent, but consistently wrong. High variance means the darts scatter over the board: each new sample gives a very different model. A good model is both consistent and centered on the bullseye. A bad one can fail in either way, or both.

Definition

Bias is systematic error. The model’s assumptions are too simple for the real pattern, so its predictions are wrong in the same direction whatever training data it sees. A straight line forced to fit a curve has high bias. Variance is sensitivity to the particular training set. Retrain on a slightly different sample, and the predictions change a lot. A deep, unconstrained tree that bends around every training point has high variance.

Now the math

Suppose the true relationship is $y = f(x) + \epsilon$. The noise $\epsilon$ has mean 0 and variance $\sigma^2$, and it is independent of everything else. No model can predict it, so we call it irreducible. We train a model on a random training set $D$ and get the prediction $\hat f_D(x)$ at a test point $x$. Let $\bar f(x) = \mathbb{E}_D[\hat f_D(x)]$ be the average prediction over many random training sets.

We want the expected squared error at $x$, averaged over both the training set $D$ and the noise $\epsilon$ in the test label. Add and subtract $\bar f(x)$, and write the error as a sum of three parts:

$$ y - \hat f_D(x) = a + b_D + \epsilon $$

In words: $a = f(x)-\bar f(x)$ is a fixed number (it does not depend on $D$). $b_D = \bar f(x)-\hat f_D(x)$ changes with the training set. $\epsilon$ is the test-label noise. The three parts add up to $y - \hat f_D(x)$ because $y = f(x) + \epsilon$.

Square the sum and take the expectation of each term:

$$ \begin{aligned} &\mathbb{E}\big[(a + b_D + \epsilon)^2\big] \\ &\quad= a^2 + \mathbb{E}[b_D^2] + \mathbb{E}[\epsilon^2] \\ &\qquad + 2a\,\mathbb{E}[b_D] + 2a\,\mathbb{E}[\epsilon] \\ &\qquad + 2\,\mathbb{E}[b_D\,\epsilon] \end{aligned} $$

In words: the last three terms (the cross terms) are all zero. Also, $\mathbb{E}[\epsilon^2] = \sigma^2$. $\mathbb{E}[b_D] = \bar f(x) - \mathbb{E}_D[\hat f_D(x)] = 0$ by the definition of $\bar f$. $\mathbb{E}[\epsilon] = 0$ because the noise has mean zero. $\mathbb{E}[b_D\,\epsilon] = \mathbb{E}[b_D]\,\mathbb{E}[\epsilon] = 0$ because the test noise is independent of the training set.

What remains is the bias–variance decomposition:

$$ \begin{aligned} &\mathbb{E}\big[(y - \hat f_D(x))^2\big] \\ &\quad= \underbrace{(f(x)-\bar f(x))^2}_{\text{bias}^2} \\ &\qquad + \underbrace{\mathbb{E}_D\big[(\bar f(x)-\hat f_D(x))^2\big]}_{\text{variance}} + \underbrace{\sigma^2}_{\text{noise}} \end{aligned} $$

In words: three parts add up to the test error. Bias² is how far the average prediction is from the truth. Variance is how much predictions change between training sets. Noise $\sigma^2$ is the part no model can predict. All three are non-negative, so the test error can never go below $\sigma^2$.

◆ The tradeoff

More capacity (a deeper tree, more parameters, a higher polynomial degree) usually lowers bias, because the model can follow the true pattern more closely. It usually also raises variance, because the model has more freedom to follow the noise in its training set. So total test error, plotted against capacity, is often U-shaped (Figure 7.2). Regularization, next, is a way to reduce variance without giving up all the capacity.

Check yourself You keep the model (degree 15) but collect ten times more training data from the same source. Which of bias², variance and noise changes, and in which direction? Reveal

Variance goes down. With more points, each random training set pins the curve down more firmly, so different training sets give more similar models. Bias² stays about the same, because it depends on what the model can represent, and that did not change. (Here it is already near zero.) Noise does not change at all: it belongs to the data, not the model. This is why more data is the classic cure for overfitting.

4Regularization: penalizing the size of the weights

Intuition first

Regularization fights overfitting directly. It adds an extra term to the loss that penalizes large weights, on top of the usual term that penalizes wrong predictions. The model can still use every weight, but it pays a price for large ones. This pushes it toward simpler, smoother solutions that are less likely to follow noise. The penalty uses the norms from Section 1: L2 or L1, applied to the weights.

☂ Everyday parallel

Imagine two ways to charge you for shopping. L1 is a flat fee on every dollar you spend. Per dollar, a small purchase pays the same fee as a big one. A purchase that is only a little useful is not worth that fee, so you drop it completely. L2 is a tax on the square of each purchase. Big purchases are taxed heavily, but small ones are taxed almost nothing, so you keep them, only a little smaller. L1 drops weights to zero. L2 shrinks all weights but rarely drops one.

Now the math

L2 regularization (also called ridge, or weight decay with gradient descent) adds the squared L2 norm of the weights $\boldsymbol\theta$ to the loss:

$$ \begin{aligned} L_{\text{ridge}}(\boldsymbol\theta) &= L_{\text{data}}(\boldsymbol\theta) + \lambda \lVert\boldsymbol\theta\rVert_2^2 \\ &= L_{\text{data}}(\boldsymbol\theta) + \lambda\sum_i \theta_i^2 \end{aligned} $$

In words: $L_{\text{data}}$ is the ordinary loss for wrong predictions. $\lambda$ (lambda) is a hyperparameter you choose. It sets how strongly we punish large weights.

The penalty $\lambda\theta_i^2$ has derivative $2\lambda\theta_i$. Put the full gradient into a gradient descent step with learning rate $\alpha$:

$$ \begin{aligned} \theta_i &\leftarrow \theta_i - \alpha\Big(\frac{\partial L_{\text{data}}}{\partial \theta_i} + 2\lambda\theta_i\Big) \\ &= \underbrace{(1 - 2\alpha\lambda)}_{\text{shrink factor}}\,\theta_i \;-\; \alpha\frac{\partial L_{\text{data}}}{\partial \theta_i} \end{aligned} $$

In words: each update multiplies the weight by a factor a little below 1, then applies the usual data-driven step. That is why L2 is called “weight decay”: the weight decays toward zero every step, on top of whatever the data pushes it toward. The shrink is proportional to the weight’s own size, so it gets weaker as the weight gets small. It does not by itself drive a weight to exactly zero.

L1 regularization (also called lasso) adds the L1 norm instead:

$$ \begin{aligned} L_{\text{lasso}}(\boldsymbol\theta) &= L_{\text{data}}(\boldsymbol\theta) + \lambda \lVert\boldsymbol\theta\rVert_1 \\ &= L_{\text{data}}(\boldsymbol\theta) + \lambda\sum_i |\theta_i| \end{aligned} $$

In words: for $\theta_i \ne 0$, the penalty’s gradient is $\lambda\,\text{sign}(\theta_i)$. This is a constant push toward zero, the same size for a huge weight and a tiny one. L2 shrinks by a fraction. L1 shrinks by a fixed amount. Suppose a weight sits at zero and its data gradient there is smaller than $\lambda$ in size. Then the data cannot overcome the push, so the best value for that weight is exactly zero. That is L1 doing feature selection: it decides that some inputs are not worth using.

There is a catch. The best value is exactly zero, but plain gradient descent does not reach it. Near zero, the constant push overshoots: the weight jumps from +0.001 to −0.001 and back, and it rarely lands on 0.0 exactly. Solvers that produce exact zeros use a different step. After the ordinary data step, they apply soft-thresholding: move each weight toward zero by $\alpha\lambda$, and stop at zero instead of crossing it.

$$ \theta_i \leftarrow \text{sign}(\theta_i)\,\max\big(|\theta_i| - \alpha\lambda,\; 0\big) $$

In words: a weight smaller than $\alpha\lambda$ becomes exactly 0. A larger weight shrinks by $\alpha\lambda$. This is called a proximal gradient step. scikit-learn’s Lasso uses coordinate descent, which applies the same soft-thresholding to one weight at a time.

The same thing in PyTorch

L1 with plain gradient steps vs. with soft-thresholding

import torch

torch.manual_seed(0)
X = torch.randn(200, 6)
true_w = torch.tensor([3.0, -2.0, 0.0, 0.0, 0.0, 0.0])   # only 2 features matter
y = X @ true_w + 0.5 * torch.randn(200)

lam, lr = 0.1, 0.05

def data_grad(w):                       # gradient of the MSE part only
    return 2 * X.T @ (X @ w - y) / len(y)

# (a) plain gradient descent on MSE + lam * |w|  (sign(w) as the gradient of |w|)
w = torch.zeros(6)
for step in range(2000):
    w = w - lr * (data_grad(w) + lam * torch.sign(w))
print("plain GD:", [round(v, 4) for v in w.tolist()])

# (b) proximal step: a normal step on the data loss, then soft-thresholding
w = torch.zeros(6)
for step in range(2000):
    w = w - lr * data_grad(w)
    w = torch.sign(w) * torch.clamp(w.abs() - lr * lam, min=0)   # shrink; stop at 0
print("proximal:", [round(v, 4) for v in w.tolist()])

# plain GD: [2.9864, -1.9335, 0.0072, 0.0029, 0.0008, 0.0035]
# proximal: [2.9871, -1.934, 0.0, 0.0, 0.0, 0.0]

Both runs find the two useful weights. Only the proximal version sets the four useless weights to exactly zero. Plain gradient descent leaves them moving around near zero.

◆ Why L1 zeroes weights and L2 doesn’t: the geometric reason

You can view each penalty as a budget: minimize the data loss while keeping the penalty below some limit $t$. The L2 budget $\sum\theta_i^2 \le t$ is a round disk (a ball in higher dimensions). The L1 budget $\sum|\theta_i| \le t$ is a diamond. Its sharp corners lie on the axes, where one weight is zero.

Now let the loss contours grow outward from the unconstrained best point. The solution is where they first touch the budget region. A round disk has no special points, so the contact is almost never on an axis. A diamond’s corners stick out, so the contours often touch a corner first. Touching at a corner means a weight is exactly zero (Figure 7.3).

The same thing in PyTorch

L2 via weight_decay, L1 added to the loss by hand

import torch
import torch.nn as nn

torch.manual_seed(0)
model = nn.Linear(10, 1)
criterion = nn.MSELoss()
x = torch.randn(32, 10)
y = torch.randn(32, 1)

# L2 / ridge / "weight decay": built into the optimizer.
optimizer = torch.optim.SGD(model.parameters(), lr=0.01, weight_decay=1e-4)
loss = criterion(model(x), y)
loss.backward()
optimizer.step()

# L1 / lasso: no optimizer flag, so add the penalty to the loss by hand.
lam = 1e-4
optimizer.zero_grad()
loss = criterion(model(x), y) + lam * model.weight.abs().sum()
loss.backward()
optimizer.step()

Two details connect this code to the math. First, PyTorch’s weight_decay adds weight_decay * w to each gradient, so each step multiplies the weight by (1 - lr * weight_decay). Our formula has $(1 - 2\alpha\lambda)$, so weight_decay $= 2\lambda$. Second, weight_decay here applies to all parameters, including the bias. The bias only shifts the output, so there is usually no reason to penalize it. To exclude it, pass the weights and biases as separate parameter groups with different weight_decay values. The L1 line above already penalizes only model.weight.

Check yourself You fit a linear model with L1 using scikit-learn’s Lasso, and again with a hand-written PyTorch loop (penalty added to the loss, plain SGD). Lasso shows 12 weights at exactly 0.0. PyTorch shows none, only values like 0.0003. Is your PyTorch code wrong? Reveal

Probably not. Both minimize the same loss, and its minimum has those 12 weights at zero. The difference is the solver. Plain gradient descent with the $\lambda\,\text{sign}(\theta)$ push overshoots zero on every step, so those weights move back and forth near zero. Lasso’s coordinate descent uses soft-thresholding, which stops exactly at zero. To get exact zeros from PyTorch, add a soft-thresholding step after each update. Or set weights below a small threshold to zero at the end.

5What to carry forward

  • Generalization means doing well on unseen data. Overfitting fits the training data’s noise. Underfitting is too simple for the real pattern. Capacity moves a model between them.
  • Train / validation / test have separate jobs. Training learns the weights, validation guides decisions, and the test set is used once for a final number. Cross-validation with $k$ folds rotates the held-out part so every example is validated once.
  • Test error = bias² + variance + irreducible noise. More capacity usually lowers bias and raises variance. The goal is the capacity with the smallest sum.
  • L2 (ridge) shrinks every weight by a fraction each step (“weight decay”). L1 (lasso) pushes by a constant amount. Its best solution often has weights at exactly zero, because its budget is a diamond with corners on the axes. You need soft-thresholding (or coordinate descent) to get those exact zeros.
