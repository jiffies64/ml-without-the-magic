What Learning Means

The models in this course share three ingredients: a hypothesis, a loss, and an optimizer. Linear regression is the clearest place to see all three, and we can solve it by hand.

40 min read
You'll learn

  • linear regression (closed form & gradient descent)

“Training a model” sounds mysterious. It becomes clear when you split it into three questions. What kinds of guesses do we allow? How do we score a guess? How do we search for the best guess? When these three questions feel familiar, you can read the training loop of almost any model in this course, including the large ones later on.

◆ The one idea to hold onto

Learning is search. You fix a family of candidate functions. You fix a number that measures how wrong each candidate is. Then you search the family for the candidate with the lowest number. Every algorithm in this course is a different way to do that search.

1The learning triad: hypothesis, loss, optimization

Intuition first

Every learning algorithm in this course has three separate parts.

  • A hypothesis class: the family of functions you allow as “the answer”. It can be only straight lines, or anything a neural network can express.
  • A loss: one number that says how wrong one function’s guesses are. You compute it by comparing its predictions with the real answers.
  • Optimization: the search procedure. It tries functions from the hypothesis class and moves toward the one with the lowest loss.

Learning, from start to end, is these three parts working together.

☂ Everyday parallel

You adjust a shower with one knob. The hypothesis class is every position the knob can take. The loss is how far the water is from the temperature you like. Optimization is what you do next: feel the water, turn the knob a little in the direction that helped, and feel again. Nobody tells you the correct knob position. You find it by repeated small corrections.

Definition

A hypothesis class is the set of candidate functions a model may choose from. You choose it before training starts. For example, “only straight lines” is a much smaller class than “any curve a deep network can draw”.

Definition

A loss function takes one hypothesis’s predictions and the true answers and returns a single number. Lower means better. Every training run minimizes some loss function. (Many losses, such as the squared error below, are never negative and reach 0 for a perfect fit. This is not true of every loss. Section 4 showed that cross-entropy cannot go below the entropy of the data.)

Definition

An optimization procedure is the algorithm that searches the hypothesis class for the member with the lowest loss. It does not know the answer in advance. It only knows how to turn the current guess into a slightly better one.

Now the math

Call the adjustable numbers of a model its parameters $\theta$ (theta). The model with parameters $\theta$ is a function $f_\theta$. We have $N$ training examples $(x_i, y_i)$. The three parts become three lines:

$$ \begin{aligned} & f_\theta \in \mathcal{H} \\ & L(\theta) = \frac{1}{N}\sum_{i=1}^{N} \ell\big(f_\theta(x_i),\, y_i\big) \\ & \theta^\star = \arg\min_\theta L(\theta) \end{aligned} $$

In words: the three lines are the hypothesis, the loss, and the optimization. $\mathcal{H}$ is the hypothesis class. $\ell$ scores one prediction against one true answer, and $L$ averages that score over all $N$ examples. $\arg\min_\theta$ means “the value of $\theta$ that makes $L$ smallest”. The optimizer is the method that finds (or approaches) $\theta^\star$.

The same thing in PyTorch

the three parts as three small functions

import torch

def hypothesis(theta, x):          # which functions we allow: straight lines
    return theta[0] * x + theta[1]

def loss(theta, x, y):             # how we score a guess: mean squared error
    return ((hypothesis(theta, x) - y) ** 2).mean()

def optimize_step(theta, x, y, lr):   # how we search: one small downhill step
    theta = theta.detach().requires_grad_(True)
    loss(theta, x, y).backward()
    return (theta - lr * theta.grad).detach()

The rest of this lesson fills in each of these functions for linear regression.

Check yourself Your shower knob only turns between “cold” and “warm”, but you like hot water. Can a better optimization strategy fix this? Reveal

No. The best position the knob allows is “warm”, so the loss can never reach the value you want. The problem is the hypothesis class: it does not contain a good answer. A better search only finds the best member of the class faster. Models behave the same way. If a straight line cannot describe the data, no optimizer will make a straight line fit it well.

2The hypothesis class: linear regression

Intuition first

The simplest useful hypothesis class says: the prediction is a straight-line function of the input. Linear regression allows only this family. No curves, no bends.

Our running example is predicting a house’s price from its floor area. Bigger houses tend to cost more, roughly in proportion. Each extra square meter adds a roughly fixed amount of money. That is the shape of a straight line: a starting price plus a rate per square meter.

☂ Everyday parallel

A taxi fare works like a straight line. There is a fixed starting fee, and then a fixed price for each kilometer. The starting fee is the bias $b$, and the price per kilometer is the weight $w$. If you know both numbers, you can predict any fare from the distance alone.

Now the math

With a single input $x$ (the size in m²), the hypothesis is:

$$ \hat{y} = wx + b $$

In words: $\hat y$ (“y-hat”) is the model’s predicted price. $x$ is the house’s size. $w$ (the weight) is the money added per extra square meter: the slope. $b$ (the bias) is the price the line gives at size zero: the intercept. Learning this hypothesis means finding good numbers for $w$ and $b$.

Real houses have more than one useful feature: size, number of bedrooms, age, distance to the city center. Put these $d$ numbers in a vector $\mathbf{x}$. Give each one its own weight in a vector $\mathbf{w}$. The model is the same idea with more inputs:

$$ \begin{aligned} \hat{y} &= \mathbf{w}^\top\mathbf{x} + b \\ &= w_1x_1 + w_2x_2 + \dots + w_dx_d + b \end{aligned} $$

In words: $\mathbf{w}^\top\mathbf{x}$ is a dot product (Section 1): multiply each feature by its own weight and add the results. Then add the single bias number $b$. There is one weight per feature and one shared bias.

The same thing in PyTorch

one prediction from one house

import torch

w = torch.tensor([1800.0])     # dollars per extra m²
b = torch.tensor([48000.0])    # baseline price
x = torch.tensor([100.0])      # house size, m²

y_hat = x * w + b
print(y_hat)                   # tensor([228000.])
Check yourself You fit $\hat y = wx + b$ to some houses. Then every price in the data doubles (sizes stay the same). What are the new best $w$ and $b$? Reveal

Both double. Take any line $(w', b')$ and compare it with the doubled prices. Its errors are exactly twice the errors of the line $(w'/2,\, b'/2)$ on the old prices. So its loss is four times that line’s old loss. The new loss is smallest when $(w'/2,\, b'/2)$ is the old best line, that is, when $w' = 2w$ and $b' = 2b$. (Running the normal-equation code below with doubled y gives [3602.58] 95751.21, twice the original.)

3The loss: Mean Squared Error

Intuition first

We need one number that answers: “across every house in our data, how wrong were this line’s guesses?” Mean Squared Error (MSE) does this. For each house, subtract the true price from the predicted price. Square that difference. Then average the squares over all houses.

☂ Everyday parallel

Imagine each data point is tied to the line by a vertical spring. A stretched spring stores energy proportional to the square of its stretch. Let the line move freely, and it settles where the total spring energy is lowest. That resting place is the line with the smallest sum of squared errors.

Now the math

$$ L(w,b) = \frac{1}{N}\sum_{i=1}^{N}\left(\hat{y}_i - y_i\right)^2 $$

In words: here $\hat y_i = wx_i + b$ is the prediction for house $i$. For each of the $N$ houses, take (predicted price − true price) and square it. Then average all $N$ squared errors into one number. Squaring does two jobs. It makes every error positive, so an over-guess and an under-guess of the same size do not cancel. It also punishes large mistakes much more than small ones.

Why square, and not absolute value?

The absolute value $|\hat y - y|$ also makes errors positive. But it is not smooth: at zero its slope jumps from −1 to +1. That is awkward for gradient-based optimization (Section 2). The square is smooth everywhere. Also, as the next box shows, it follows from a simple assumption about noisy data. It is not an arbitrary choice.

◆ Where MSE comes from

Suppose the true price is a straight line plus random noise: $y_i = wx_i + b + \varepsilon_i$. Each noise value $\varepsilon_i$ comes from a Gaussian (bell-curve) distribution with mean 0. Its standard deviation $\sigma$ is the same for every house (see Section 3). Then the probability density of price $y_i$, given $x_i$, is a Gaussian centered at $\hat y_i = wx_i+b$:

$$ \begin{aligned} &p(y_i\mid x_i;w,b) \\ &\quad= \frac{1}{\sqrt{2\pi\sigma^2}}\exp\!\left(-\frac{(y_i-\hat y_i)^2}{2\sigma^2}\right) \end{aligned} $$

(As Section 3 explained, a density is not a probability. It is a height, and higher means “more likely near this value”. That is all we need here.) If the houses are independent, the likelihood of the whole dataset is the product of these densities. The log turns the product into a sum, and it turns the exponential into a plain term. For one house:

$$ \begin{aligned} \log p(y_i\mid x_i) &= -\tfrac12\log(2\pi\sigma^2) \\ &\quad - \frac{(y_i-\hat y_i)^2}{2\sigma^2} \end{aligned} $$

Adding this over all $N$ houses gives the log-likelihood, which we write as $\ell$:

$$ \begin{aligned} \ell(w,b) &= -\tfrac{N}{2}\log(2\pi\sigma^2) \\ &\quad - \frac{1}{2\sigma^2}\sum_{i=1}^N (y_i-\hat y_i)^2 \end{aligned} $$

In words: the first term does not contain $w$ or $b$. The factor $\tfrac{1}{2\sigma^2}$ is a positive constant. So maximizing this log-likelihood over $w, b$ is the same job as minimizing $\sum_i(y_i-\hat y_i)^2$. That is MSE, up to the constant $1/N$. Squared error is what you get when you assume Gaussian noise.

Check yourself One house in your data has a typo: its price is ten times too high. Which loss pulls the fitted line more toward that house, squared error or absolute error? Why? Reveal

Squared error. If that house’s error is 1,000,000, its squared error is $10^{12}$, far larger than all the other houses together. The line bends toward it to shrink that one term. Absolute error only counts 1,000,000, so the other houses still matter. This matches the Gaussian story: a Gaussian says huge errors almost never happen, so one huge error must be “explained away” at great cost.

4Optimization, take one: solving directly

Intuition first

For a straight line, the MSE loss is a smooth bowl. When no feature is a copy of another (see the check below), the bowl has a single lowest point and no other dips. So we do not need to search by trial and error. We can use calculus to go straight to the bottom: set the slope to zero and solve, as you would for a simple parabola.

☂ Everyday parallel

A ball thrown upward follows a parabola. You do not need to film the whole flight to find its highest point. Because you know the shape, a formula gives the top directly. The normal equation below does the same for the MSE bowl: we know its shape, so a formula gives the bottom.

Now the math

Put all the houses in one table. The data matrix $\mathbf{X}$ has one row per house and one column per feature, so its shape is $N\times d$. The true prices form a vector $\mathbf{y}$ of length $N$.

A trick handles the bias $b$ without carrying it separately. Add a column of 1s to the front of $\mathbf{X}$, and add $b$ to the front of the weight vector. Call the new versions $\tilde{\mathbf{X}}$ (shape $N\times(d+1)$) and $\tilde{\mathbf{w}}$ (length $d+1$, with $\tilde w_0=b$). Now $\tilde{\mathbf{X}}\tilde{\mathbf{w}}$ gives every prediction $\hat y_i = \mathbf{w}^\top\mathbf{x}_i+b$ at once, and the loss is:

$$ L(\tilde{\mathbf{w}}) = \frac{1}{N}\sum_{i=1}^N \left(\tilde{\mathbf{x}}_i\cdot\tilde{\mathbf{w}} - y_i\right)^2 $$

In words: $\tilde{\mathbf{x}}_i$ is row $i$ of $\tilde{\mathbf{X}}$, one house’s features with a 1 in front. This is the same MSE as before, with the bias folded in.

Differentiate with respect to one weight $\tilde w_k$. Use the chain rule: the derivative of a square, times the derivative of the inside. The inside $\tilde{\mathbf{x}}_i\cdot\tilde{\mathbf{w}}$ changes by $\tilde x_{i,k}$ when $\tilde w_k$ grows by 1:

$$ \frac{\partial L}{\partial \tilde w_k} = \frac{1}{N}\sum_{i=1}^N 2\left(\tilde{\mathbf{x}}_i\cdot\tilde{\mathbf{w}} - y_i\right)\tilde x_{i,k} $$

In words: for every house, take its residual (predicted − actual) and multiply it by that house’s $k$-th feature value. Then average and double. Stack this over every $k$ to get a vector. That is the full gradient in matrix form:

$$ \nabla_{\tilde{\mathbf{w}}} L = \frac{2}{N}\,\tilde{\mathbf{X}}^\top\!\left(\tilde{\mathbf{X}}\tilde{\mathbf{w}} - \mathbf{y}\right) $$

In words: $\tilde{\mathbf{X}}\tilde{\mathbf{w}}-\mathbf{y}$ is every residual at once, a vector of length $N$. Multiplying by $\tilde{\mathbf{X}}^\top$ does the step above (“multiply by each feature column and sum over houses”) for every weight at the same time.

Now find the minimum: set the gradient to the zero vector and solve.

$$ \begin{aligned} \frac{2}{N}\,\tilde{\mathbf{X}}^\top\!\left(\tilde{\mathbf{X}}\tilde{\mathbf{w}} - \mathbf{y}\right) &= \mathbf{0} \\ \tilde{\mathbf{X}}^\top\tilde{\mathbf{X}}\tilde{\mathbf{w}} - \tilde{\mathbf{X}}^\top\mathbf{y} &= \mathbf{0} \\ \tilde{\mathbf{X}}^\top\tilde{\mathbf{X}}\tilde{\mathbf{w}} &= \tilde{\mathbf{X}}^\top\mathbf{y} \\ \tilde{\mathbf{w}} &= \left(\tilde{\mathbf{X}}^\top\tilde{\mathbf{X}}\right)^{-1}\tilde{\mathbf{X}}^\top\mathbf{y} \end{aligned} $$

In words: multiply both sides by $N/2$, so the constant goes away. Move the $\mathbf{y}$ term to the other side. Then multiply both sides by the inverse of $\tilde{\mathbf{X}}^\top\tilde{\mathbf{X}}$ to get $\tilde{\mathbf{w}}$ alone. This is the normal equation: one formula that gives the exact best-fit weights, with no search.

▲ Watch out

The inverse $(\tilde{\mathbf{X}}^\top\tilde{\mathbf{X}})^{-1}$ exists only when $\tilde{\mathbf{X}}^\top\tilde{\mathbf{X}}$ is non-singular. Roughly, this means no feature is an exact linear combination of the others (for example, one column exactly twice another). Real code does not call a matrix-inverse function. It calls a linear-solve routine, which gives the same answer faster and with smaller rounding errors.

The same thing in NumPy

fit the line with the normal equation

import numpy as np

def fit_normal_equation(X, y):
    N = X.shape[0]
    X_aug = np.hstack([np.ones((N, 1)), X])                  # bias trick: a column of 1s
    w_aug = np.linalg.solve(X_aug.T @ X_aug, X_aug.T @ y)    # solve; do not invert
    b, w = w_aug[0], w_aug[1:]
    return w, b

X = np.array([[60.0], [75.0], [110.0], [140.0]])   # house size, m²
y = np.array([150_000.0, 200_000.0, 225_000.0, 310_000.0])

w, b = fit_normal_equation(X, y)
print(w, b)   # [1801.29240711] 47875.60581583208

So the best line is about $\hat y = 1801.29\,x + 47876$: roughly 1,800 dollars per square meter on top of a base of about 48,000 dollars. Figure 5.1 shows this line.

Check yourself Two of your features are “size in m²” and “size in cm²”. One is the other times 10,000. What goes wrong in the normal equation, and why? Reveal

$\tilde{\mathbf{X}}^\top\tilde{\mathbf{X}}$ becomes singular (it has no inverse). The two columns carry the same information. You can raise one weight and lower the other by the matching amount, and the predictions do not change. So infinitely many weight pairs give the same lowest loss, and there is no single best answer. In the picture of the loss, the bowl has a flat valley floor along that direction instead of a single bottom. This is why the intuition above says “a single bottom when no feature is a copy of another”. The usual fix is ridge regularization (Section 7). It adds a small penalty that makes the matrix invertible again.

5Optimization, take two: gradient descent

Intuition first

The normal equation is exact, but it must solve a system with a $(d+1)\times(d+1)$ matrix. That becomes expensive when the number of features $d$ is very large. Gradient descent works differently. It starts from any guess and takes many small steps downhill on the loss surface. The gradient (Section 2) points toward the steepest increase, so each step goes in the opposite direction.

☂ Everyday parallel

Think of tuning a guitar string by ear. You hear that the note is too high, so you turn the peg down a little. You listen again and correct again. When the note is far off, you turn more. When it is close, you turn less. The size of the error sets the size of the correction, and that is also true of the gradient. Turn the peg too far in one go, and you overshoot to the other side. A learning rate that is too large does the same thing.

Now the math

We already derived the gradient above. Gradient descent does not set it to zero. Instead it takes a small step against it:

$$ \tilde{\mathbf{w}} \leftarrow \tilde{\mathbf{w}} - \alpha\,\nabla_{\tilde{\mathbf{w}}} L $$

In words: the arrow means “replace the old value with this new one”. $\alpha$ (alpha) is the learning rate, a small positive number that sets the step size. We move a little in the direction opposite the gradient, because the gradient points toward higher loss. Repeat the update many times, and $\tilde{\mathbf{w}}$ slides down the bowl toward its bottom.

◆ Normalize the features first

Gradient descent is sensitive to the scale of the features. The fix is to normalize each feature: subtract its mean $\mu$ and divide by its standard deviation $s$. The new feature $x' = (x-\mu)/s$ has mean 0 and standard deviation 1. Figure 5.2 shows why this helps. With a raw feature, the loss bowl is a long, narrow valley. The gradient points mostly across the valley, not along it, so progress is slow. After normalizing, the bowl is nearly round, and the gradient points almost straight at the bottom.

After training on $x'$, you can convert the weights back to the original units. Put $x' = (x-\mu)/s$ into the model and expand:

$$ \begin{aligned} \hat y &= w'\,\frac{x-\mu}{s} + b' \\ &= \frac{w'}{s}\,x + \Big(b' - \frac{w'\mu}{s}\Big) \end{aligned} $$

In words: the weight in original units is $w'/s$. The bias in original units is $b'$ minus the weight times the mean. The model is the same line; only the units of its numbers change.

◆ When gradient descent beats the closed form

Solving the normal equation takes about $d^3$ arithmetic steps for $d$ features (written $O(d^3)$, “order $d$ cubed”). Some datasets have a million features. An example is a bag-of-words text representation, with one feature per word in the vocabulary that counts how often the word appears. Then $d^3 = 10^{18}$, which is far too much. Such data is also sparse: almost all entries are zero. Storing only the nonzero entries saves memory, but $\tilde{\mathbf{X}}^\top\tilde{\mathbf{X}}$ is often dense and huge.

Gradient descent needs only matrix–vector products at each step, and these are cheap for sparse data. It can also process the data in small batches, so the whole dataset need not fit in memory. The cost: it gives an approximate answer that improves over many steps, not an exact answer from one formula.

The same thing in PyTorch

gradient descent on normalized size, then back to dollars per m²

import torch

X = torch.tensor([[60.], [75.], [110.], [140.]])   # house size, m²
y = torch.tensor([150_000., 200_000., 225_000., 310_000.])

# normalize the feature first (see the box above)
X_mean, X_std = X.mean(), X.std()
Xn = (X - X_mean) / X_std

w = torch.zeros(1, requires_grad=True)
b = torch.zeros(1, requires_grad=True)
lr = 0.1

for step in range(500):
    y_hat = Xn.squeeze() * w + b        # forward pass (the hypothesis)
    loss = ((y_hat - y) ** 2).mean()    # MSE

    loss.backward()                     # autograd fills w.grad and b.grad

    with torch.no_grad():               # the update is not part of the graph
        w -= lr * w.grad
        b -= lr * b.grad
        w.grad.zero_()
        b.grad.zero_()

print(w.item(), b.item(), loss.item())
# 64685.78125 221249.96875 216498320.0

# undo the normalization: w = w'/s, b = b' - w'*mean/s
w_orig = w.item() / X_std.item()
b_orig = b.item() - w.item() * X_mean.item() / X_std.item()
print(round(w_orig, 2), round(b_orig))
# 1801.29 47876

The first line prints the weights in normalized units, so they look very different from the normal-equation answer. After we convert them back, they match it: about 1,801 dollars per m² and a base of about 47,876 dollars. Two different optimizers found the same bottom of the same bowl.

Check yourself In the code above, delete the normalization (use Xn = X) and keep lr = 0.1. Predict what happens. Reveal

The weights blow up, and the printed values become nan. The size of one gradient step on $w$ grows with $x^2$, which is about 10,000 here. With $\alpha = 0.1$, each step overshoots the bottom by a huge amount, lands farther away, and the next step is even larger. You would need a learning rate thousands of times smaller, and then $b$ would move extremely slowly. Normalizing removes this conflict.

6What to carry forward

  • Learning = hypothesis class (which functions we allow) + loss (how we score wrongness) + optimization (how we search). The algorithms in this course use these three parts in different forms.
  • Linear regression’s hypothesis is $\hat y = \mathbf{w}^\top\mathbf{x}+b$: a straight line (or plane, or hyperplane) fit to the data.
  • MSE squares and averages the errors. It is the maximum-likelihood loss when the noise is Gaussian.
  • The normal equation $\tilde{\mathbf{w}} = (\tilde{\mathbf{X}}^\top\tilde{\mathbf{X}})^{-1}\tilde{\mathbf{X}}^\top\mathbf{y}$ finds the exact minimum by setting the gradient to zero.
  • Gradient descent walks downhill step by step. It works best on normalized features. Iterative methods like it are the usual choice when the data is too large or too sparse for the normal equation.
