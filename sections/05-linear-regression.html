What Learning Means

Every model you will ever train is secretly just three ingredients — a hypothesis, a loss, and an optimizer — and linear regression is the cleanest place to watch all three get solved by hand.

30 min read You'll learn: hypothesis classes · loss functions · optimization · linear regression (closed form & gradient descent)

"Training a model" sounds mysterious until you break it into three questions, none of which is mysterious at all: what kinds of guesses are we willing to make, how do we score a guess as good or bad, and how do we search for the best one? Get comfortable with those three questions and you can read the training loop of almost any model in this course — including the giant ones later on.

◆ The one idea to hold onto

Learning is search. You fix a family of candidate functions, you fix a number that measures how wrong each candidate is, and then you search that family for the candidate with the lowest wrongness. Every algorithm in this course is a different way of doing that search.

1The learning triad: hypothesis, loss, optimization

Intuition first

Three separate ingredients make up every learning algorithm you'll meet. First, a hypothesis class: the family of functions you're willing to consider as "the answer" — maybe only straight lines, maybe anything a neural network can express. Second, a loss: a single number that says how wrong one particular function's guesses are, computed by comparing its predictions to the real answers. Third, optimization: the search procedure that tries different functions from the hypothesis class and steers toward the one with the lowest loss. Learning, end to end, is just those three things wired together.

☂ Everyday parallel

You're tuning a recipe for tomato soup. The hypothesis class is every recipe you'd consider making — maybe you've decided it must be tomato, garlic, and cream in some proportions, so "recipe" really means "the three numbers: how much tomato, how much garlic, how much cream." The loss is a taste test: how far this batch is from the flavor you're aiming for (too salty, not creamy enough — turned into one "distance from perfect" score). Optimization is what you do next: taste, adjust the ratios a little in the direction that helped last time, taste again. You never see "the answer" printed anywhere — you find it by repeatedly tasting and nudging.

Definition

A hypothesis class is the set of candidate functions a model is allowed to choose from. Restricting it is a choice you make before training even starts — e.g. "only straight lines" is a much smaller, simpler hypothesis class than "any curve a deep network can draw."

Definition

A loss function takes one hypothesis's predictions and the true answers and returns a single non-negative number: 0 means "perfect," and bigger means "worse." Every training run is, underneath, minimizing some loss function.

Definition

An optimization procedure is the algorithm that searches the hypothesis class for the member with the lowest loss. It never magically knows the answer; it only knows how to take the current guess and produce a slightly better one.

Check yourself In the soup analogy, what plays the role of the loss function — and would "zero loss" ever really happen? Reveal

The taste test's "distance from the target flavor" score is the loss. In practice you almost never hit exactly zero — there's always some noise (today's tomatoes are slightly different from yesterday's), so the goal is realistically "as low as we can get," not a mathematically perfect zero. The same is true of nearly every model you'll train on real data.

2The hypothesis class: linear regression

Intuition first

The simplest useful hypothesis class is: predictions are a straight-line function of the input. Linear regression restricts itself to exactly that family and nothing fancier — no curves, no bends.

☂ Everyday parallel

Predicting a house's price from its size. Bigger houses tend to cost more, roughly in proportion — add a square foot, add a roughly fixed number of dollars. That's exactly the shape of a straight line: a starting price plus a rate per square foot.

Now the math

With a single input x (say, size in square feet), the hypothesis is:

$$ \hat{y} = wx + b $$

In words: ŷ ("y-hat") is the model's predicted price. x is the house's size. w (the weight) is dollars added per extra square foot — the slope. b (the bias) is the baseline price when size is zero — the intercept. Learning this hypothesis means finding good numbers for w and b.

Real houses have more than one useful feature — size, number of bedrooms, age, distance to downtown. Stack those numbers into a vector x and give each one its own weight in a vector w; the model is the same idea generalized:

$$ \hat{y} = \mathbf{w}^\top\mathbf{x} + b = w_1x_1 + w_2x_2 + \dots + w_dx_d + b $$

In words: wᵀx is a dot product (Section 1) — multiply each feature by its own weight and add up the results — then shift by the single bias number b. One weight per feature, one shared bias for the whole prediction.

The same thing in PyTorch

import torch

w = torch.tensor([120.0])      # $ per extra sqft
b = torch.tensor([10000.0])    # baseline price
x = torch.tensor([1800.0])     # house size, sqft

y_hat = x * w + b
print(y_hat)                   # tensor([226000.])
Check yourself With ŷ = 120x + 10000, what price does the model predict for a 1,800 sqft house, and what do w and b represent in plain words? Reveal

ŷ = 120 × 1800 + 10000 = 226,000. Here w = 120 means "each extra square foot adds 120 dollars to the predicted price," and b = 10000 means "a hypothetical zero-square-foot house would be priced at 10,000 dollars" — a baseline that mostly exists to shift the line up or down, not a literal claim about tiny houses.

3The loss: Mean Squared Error

Intuition first

We need one number that says "across every house in our data, how wrong were this line's guesses?" Mean Squared Error (MSE) does this: for each house, subtract the true price from the predicted price, square that difference, and average the squares over all houses.

Now the math

$$ L(w,b) = \frac{1}{n}\sum_{i=1}^{n}\left(\hat{y}_i - y_i\right)^2, \qquad \hat{y}_i = wx_i+b $$

In words: for each of the n houses, take (predicted price − true price), square it, then average all n squared errors into one number. Squaring does two jobs at once: it makes every error positive (so a 10-dollar over-guess and a 10-dollar under-guess don't cancel out when summed), and it punishes large mistakes far more than small ones.

Why square, and not absolute value?

Absolute value |ŷ−y| would also make errors positive, but it isn't smooth: at exactly zero its slope jumps abruptly, which is awkward for gradient-based optimization (Section 2). Squaring is smooth everywhere and — as the next box shows — falls directly out of a simple assumption about noisy data, rather than being picked arbitrarily.

◆ Where MSE actually comes from

Suppose the true price is a straight line plus random noise: $y_i = wx_i + b + \varepsilon_i$, where each $\varepsilon_i$ is drawn from a Gaussian (bell-curve) distribution with mean 0 (see Section 3). Then the probability of seeing price $y_i$ given $x_i$ is the Gaussian density centered at $\hat y_i = wx_i+b$:

$$ p(y_i\mid x_i;w,b) = \frac{1}{\sqrt{2\pi\sigma^2}}\exp\!\left(-\frac{(y_i-\hat y_i)^2}{2\sigma^2}\right) $$

Assuming the houses are independent, the likelihood of the whole dataset is the product of these densities. Taking the log turns the product into a sum (logs turn multiplication into addition) and the exponential into a plain term:

$$ \log \mathcal{L}(w,b) = \sum_{i=1}^n \left[-\log\sqrt{2\pi\sigma^2} - \frac{(y_i-\hat y_i)^2}{2\sigma^2}\right] = -n\log\sqrt{2\pi\sigma^2} - \frac{1}{2\sigma^2}\sum_{i=1}^n (y_i-\hat y_i)^2 $$

In words: the first term doesn't involve w or b at all, and $\tfrac{1}{2\sigma^2}$ is just a positive constant. So maximizing this log-likelihood over w,b is exactly the same job as minimizing $\sum_i(y_i-\hat y_i)^2$ — which is Mean Squared Error, up to the constant $1/n$. Squared error isn't an arbitrary convention; it's what falls out the moment you assume Gaussian noise.

Check yourself Why does minimizing sum-of-squared-errors correspond to maximizing likelihood under Gaussian noise, rather than, say, minimizing it? Reveal

The log-likelihood is −n·log(√2πσ²) − (1/2σ²)·Σ(y−ŷ)². The second term is subtracted, and its size grows with the squared errors. So making the squared errors bigger makes the log-likelihood smaller, and making them smaller makes the log-likelihood larger. To maximize likelihood you therefore have to minimize the sum of squared errors — the minus sign is what flips "minimize error" into "maximize likelihood."

4Optimization, take one: solving directly

Intuition first

Because the MSE loss for a straight line is a smooth bowl shape (one single lowest point, no bumps), we don't have to search for the bottom by trial and error — we can use calculus to jump straight to it, the same way you'd find the minimum of a simple parabola by setting its slope to zero and solving.

Now the math

First, a trick to handle the bias b without carrying it separately: glue a column of 1s onto the front of the data matrix, and glue b onto the front of the weight vector. Call the augmented versions $\tilde{\mathbf{X}}$ (shape $n\times(d+1)$) and $\tilde{\mathbf{w}}$ (length $d+1$, with $\tilde w_0=b$). Now $\tilde{\mathbf{X}}\tilde{\mathbf{w}}$ produces every prediction $\hat y_i = wx_i+b$ at once, and the loss is:

$$ L(\tilde{\mathbf{w}}) = \frac{1}{n}\sum_{i=1}^n \left(\tilde{\mathbf{x}}_i\cdot\tilde{\mathbf{w}} - y_i\right)^2 $$

In words: $\tilde{\mathbf{x}}_i$ is row $i$ of $\tilde{\mathbf{X}}$ — one house's (augmented) features. This is exactly the same MSE as before, just written with the bias folded in.

Differentiate with respect to one weight $\tilde w_k$ using the chain rule (derivative of a square, times derivative of the inside):

$$ \frac{\partial L}{\partial \tilde w_k} = \frac{1}{n}\sum_{i=1}^n 2\left(\tilde{\mathbf{x}}_i\cdot\tilde{\mathbf{w}} - y_i\right)\tilde x_{i,k} $$

In words: for every house, take its residual (predicted − actual) and multiply by that house's k-th feature value, then average and double. Stacking this expression over every k reassembles a vector, giving the full gradient in matrix form:

$$ \nabla_{\tilde{\mathbf{w}}} L = \frac{2}{n}\,\tilde{\mathbf{X}}^\top\!\left(\tilde{\mathbf{X}}\tilde{\mathbf{w}} - \mathbf{y}\right) $$

In words: compute every residual at once ($\tilde{\mathbf{X}}\tilde{\mathbf{w}}-\mathbf{y}$, a length-n vector), then multiply by $\tilde{\mathbf{X}}^\top$, which — being a matrix — does exactly the "multiply by each feature column and sum over houses" step from the line above, for every weight simultaneously.

Now solve for the minimum by setting the gradient to the zero vector:

$$ \begin{aligned} \frac{2}{n}\,\tilde{\mathbf{X}}^\top\!\left(\tilde{\mathbf{X}}\tilde{\mathbf{w}} - \mathbf{y}\right) &= \mathbf{0} \\ \tilde{\mathbf{X}}^\top\tilde{\mathbf{X}}\tilde{\mathbf{w}} - \tilde{\mathbf{X}}^\top\mathbf{y} &= \mathbf{0} \\ \tilde{\mathbf{X}}^\top\tilde{\mathbf{X}}\tilde{\mathbf{w}} &= \tilde{\mathbf{X}}^\top\mathbf{y} \\ \tilde{\mathbf{w}} &= \left(\tilde{\mathbf{X}}^\top\tilde{\mathbf{X}}\right)^{-1}\tilde{\mathbf{X}}^\top\mathbf{y} \end{aligned} $$

In words: multiply both sides by $n/2$ (drops out), move the constant term to the other side, then multiply both sides by the inverse of $\tilde{\mathbf{X}}^\top\tilde{\mathbf{X}}$ to isolate $\tilde{\mathbf{w}}$. This is the normal equation: one formula that hands you the exact best-fit weights, no searching required.

▲ Watch out

The inverse $(\tilde{\mathbf{X}}^\top\tilde{\mathbf{X}})^{-1}$ only exists when $\tilde{\mathbf{X}}^\top\tilde{\mathbf{X}}$ is non-singular — roughly, when no feature is an exact linear combination of the others (e.g. one column being exactly twice another). In practice, real code never calls an explicit matrix-inverse function; it calls a linear-solve routine instead, which is faster and numerically safer for the same answer.

The same thing in NumPy

import numpy as np

def fit_normal_equation(X, y):
    n = X.shape[0]
    X_aug = np.hstack([np.ones((n, 1)), X])       # bias trick: prepend a column of 1s
    w_aug = np.linalg.solve(X_aug.T @ X_aug, X_aug.T @ y)   # solve, don't explicitly invert
    b, w = w_aug[0], w_aug[1:]
    return w, b

X = np.array([[650.0], [800.0], [1200.0], [1500.0]])   # house size, sqft
y = np.array([150_000.0, 180_000.0, 240_000.0, 300_000.0])

w, b = fit_normal_equation(X, y)
print(w, b)   # array([176.6...]), 22...   -- exact best-fit line, in one call
Check yourself Suppose two of your features are "size in sqft" and "size in square meters" — one is just the other times a constant. What breaks in the normal equation, and why? Reveal

$\tilde{\mathbf{X}}^\top\tilde{\mathbf{X}}$ becomes singular (non-invertible), because the two columns carry identical information — infinitely many combinations of their two weights produce the exact same predictions, so there's no single "best" solution to land on. Geometrically, the two features point in the same direction, so the loss bowl isn't a bowl anymore along that direction — it's flat, like a valley floor rather than a single pit. The usual fix, ridge regularization, adds a small penalty that makes the matrix invertible again (a technique from Section 7).

5Optimization, take two: gradient descent

Intuition first

The normal equation is exact, but it needs to invert a $(d+1)\times(d+1)$ matrix, which gets expensive — and sometimes impossible — as the number of features $d$ grows huge. Gradient descent instead starts from any guess and repeatedly takes a small step downhill on the loss surface, using the gradient (Section 2 of this course) as a compass that always points toward steepest increase — so we step in the opposite direction.

☂ Everyday parallel

You're hiking down a mountain in thick fog. You can't see the valley floor, but you can feel which way the ground slopes under your feet right now. So you take a step in the steepest downhill direction, feel the new slope, take another step, and repeat. You never need a map of the whole mountain — just the local slope, over and over. It's the same foggy hillside from Section 2; here we finally walk all the way down it.

Now the math

We already derived the gradient above: $\nabla_{\tilde{\mathbf{w}}} L = \tfrac{2}{n}\tilde{\mathbf{X}}^\top(\tilde{\mathbf{X}}\tilde{\mathbf{w}}-\mathbf{y})$. Gradient descent uses it not to solve for zero directly, but to take a small step against it:

$$ \tilde{\mathbf{w}} \leftarrow \tilde{\mathbf{w}} - \alpha\,\nabla_{\tilde{\mathbf{w}}} L $$

In words: the arrow means "replace the old value with this new one." $\alpha$ (alpha) is the learning rate, a small positive number controlling step size. We move a little bit in the direction opposite the gradient, because the gradient points toward increasing loss and we want to decrease it. Repeat this update many times and $\tilde{\mathbf{w}}$ slides down the loss bowl toward its bottom.

◆ When gradient descent beats the closed form

The normal equation costs roughly $O(d^3)$ to invert a $d\times d$ matrix — for a dataset with a million features (e.g. a bag-of-words text representation), that's completely infeasible, and such matrices are often sparse in a way that inversion destroys. Gradient descent instead only needs cheap matrix–vector products at each step, can process data in small batches instead of loading everything into memory at once, and works even when $\tilde{\mathbf{X}}^\top\tilde{\mathbf{X}}$ isn't invertible at all. The trade: it gives an approximate answer that improves gradually, instead of the closed form's exact answer in one shot.

The same thing in PyTorch

import torch

X = torch.tensor([[650.], [800.], [1200.], [1500.]])
y = torch.tensor([150_000., 180_000., 240_000., 300_000.])

# gradient descent is sensitive to feature scale -- normalize first
X_mean, X_std = X.mean(), X.std()
Xn = (X - X_mean) / X_std

w = torch.zeros(1, requires_grad=True)
b = torch.zeros(1, requires_grad=True)
lr = 0.1

for step in range(500):
    y_hat = Xn.squeeze() * w + b        # forward pass (the hypothesis)
    loss = ((y_hat - y) ** 2).mean()    # MSE

    loss.backward()                     # autograd fills w.grad, b.grad

    with torch.no_grad():               # the update step itself isn't part of the graph
        w -= lr * w.grad
        b -= lr * b.grad
        w.grad.zero_()
        b.grad.zero_()

print(w.item(), b.item(), loss.item())
Check yourself You're training on a bag-of-words dataset with 1,000,000 features. Why is gradient descent the practical choice over the normal equation here? Reveal

The normal equation needs $(\tilde{\mathbf{X}}^\top\tilde{\mathbf{X}})^{-1}$, a 1,000,000 × 1,000,000 matrix inverse — roughly $10^{18}$ operations and enormous memory, completely impractical. Gradient descent instead touches the data only through matrix–vector products, which stay cheap and can even exploit the sparsity that bag-of-words features usually have (most entries are zero). It trades an exact one-shot answer for a sequence of cheap, scalable steps.

6What to carry forward

  • Learning = hypothesis class (what functions we allow) + loss (how we score wrongness) + optimization (how we search) — every algorithm in this course is this triad in a different costume.
  • Linear regression's hypothesis is $\hat y = \mathbf{w}^\top\mathbf{x}+b$, a straight line (or plane, or hyperplane) fit to the data.
  • MSE squares and averages the errors — and isn't an arbitrary choice: it's the maximum-likelihood loss when noise is Gaussian.
  • The normal equation $\tilde{\mathbf{w}} = (\tilde{\mathbf{X}}^\top\tilde{\mathbf{X}})^{-1}\tilde{\mathbf{X}}^\top\mathbf{y}$ solves for the exact minimum directly, by setting the gradient to zero.
  • Gradient descent instead walks downhill step by step — slower per problem, but the only option once the data is too large or too sparse to invert.
